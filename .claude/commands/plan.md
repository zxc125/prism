# /plan — 拆分阶段

## 前置

承接当前会话的 `/spec` 产出（决策文档 + 架构方案）。如果当前会话没有 spec 产出，先确认用户要基于哪份方案文档开工。

## 你的角色

你是实施计划设计者。读 spec 产出的方案文档，把它拆成可执行、可验证的实施步骤。

## 流程

### 1. 读 spec 产出

读 `/spec` 落盘的：
- `docs/决策/<topic>.md`
- `docs/架构/<topic>（方案）.md`

确认归属判定（新 P / P.x / 已有 P 内）。

### 2. 起草 P 文档

用 `docs/模板/P文档.md` 起草 `docs/阶段路径/Pxx-<主题>.md`，填齐：
- **目标**：为什么做，解决什么问题
- **范围**：覆盖 / 不在本阶段（指向 P.x）
- **设计决策（已拍）**：从决策文档搬入，表格形式
- **实施顺序**：**每行必须有可验证产出**（不模糊的文件指针 / 命令 / 可观察结果），不能是「优化体验」这种模糊描述

### 3. TodoWrite 分解

把实施顺序表转成 TodoWrite 任务清单，每个任务对应一个可执行单元。

### 4. 关键风险单列

如果方案文档「风险评估」段有中/高风险项，在 P 文档里单列提醒（或用「关键陷阱」可选段）。

### 5. 用户确认

呈现 P 文档骨架 + Todo 清单，**等用户确认后建议执行 `/impl`**。

## Gate（过关条件）

- [ ] P 文档落盘，五段结构齐全（关键陷阱/修复记录除外）
- [ ] 实施顺序表每行有**可验证产出**（文件指针 / 命令 / 可观察结果）
- [ ] 设计决策表与决策文档一致
- [ ] TodoWrite 已生成
- [ ] 用户确认开 `/impl`

## 注意

- **不要在 plan 阶段写代码**——这一步只出文档 + 拆步
- 实施顺序表的指针必须落在**真实存在的文件**或**将要创建的明确路径**
- 如果发现方案文档有遗漏（如缺影响范围段），回退建议先补 `/spec`
