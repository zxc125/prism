# /spec — 需求评审

## 输入

需求：$ARGUMENTS

## 你的角色

你是这个项目（本地优先前端观测平台 Prism）的需求评审者。先读 CLAUDE.md「四条锁定决策」+「进度」表，再开始。

## 流程

### 1. 复述需求（确认理解）

用一句话复述需求，明确边界（做什么、不做什么）。如果需求模糊，先向用户提问澄清，不要自行假设。

### 2. Explore 对照（spawn subagent）

用 Agent tool spawn 一个 **Explore** agent（breadth: very thorough），让它并行扫：
- `docs/阶段路径/` 全部 P 文档 — 是否已有阶段覆盖了这需求的一半？
- `docs/决策/` — 是否有冲突的既有锁定决策？
- `docs/架构/` — 是否有可复用的已有方案？
- CLAUDE.md「四条锁定决策」+ 进度表 — 是否触碰锁定决策？

Explore agent 返回结论后，你判断：
- 这需求是**全新 P 阶段**、**已有 P 的 .x 增量**、还是**已有 P 内的补全**？
- 是否与既有决策冲突（冲突 = 必须先改决策文档再继续）？

### 3. 必答 4 问（gate — 全部要有明确答案）

1. **是否动 CLAUDE.md「四条锁定决策」？** （本地优先 / 观测外部 / 闭环到回放+诊断 / 交错事件模型）—— 动 = 必须先更新决策文档 + 用户显式确认
2. **属于新 P、P.x、还是已有 P 内？** —— 给出归属 + 理由
3. **影响哪些 crate/包/目录？** —— 列出具体路径（`src/`、`src-tauri/`、`crates/`、`packages/`、`site/`、`plugins/`）
4. **是否涉及视觉变更？** —— 是 → `/impl` 阶段必须走 `frontend-design` skill

### 4. 产出文档

用 `docs/模板/` 起草（决策.md + 架构方案.md）：
- `docs/决策/<topic>.md`
- `docs/架构/<topic>（方案）.md`

方案文档必须包含「影响范围」段（新增/修改/不动 + 风险）——这是评审重点。

### 5. 用户确认

把 4 问答案 + 归属判定 + 文档路径呈现给用户，**等用户确认归属判定后再建议下一步**：
- 新 P 或 P.x → 建议执行 `/plan`
- 已有 P 内补全且改动小 → 建议执行 `/fix`

## 完成标志

- [ ] 决策文档 + 方案文档落盘（用模板）
- [ ] 4 问有明确答案
- [ ] 用户确认归属判定
