# /sync-docs — 更新文档

## 前置

承接 `/regress` 通过的完整改动。当前会话应该刚跑完回归且 gate 通过。

## 你的角色

你是文档同步审计者。代码已经改完、测过，但文档可能还停在旧状态。你的任务是让文档与代码现实对齐。

## 流程

### 1. 读当前改动

运行 `git diff`（或 `git diff --staged` + `git diff main`）拿到本次改动的全貌。列出：
- 新增了哪些文件 / 路由 / commands / crate 模块
- 修改了哪些已有文件
- 删除了什么

### 2. CLAUDE.md 进度表检查

逐列核对 CLAUDE.md 的进度表当前 P 行：

| 列 | 检查 |
|---|---|
| 关键产出指针 | 新增的核心文件是否已登记？指针是否指向真实存在的文件？ |
| 验证 | `cargo test` 数字是否更新？`vue-tsc` 是否 0 error？site build 是否通过？ |
| 阶段行状态 | 本 P 的状态标记是否 📋→🚧→✅ 推进？ |

如果是新 P：在进度表新增一行（参照现有行的密度：是什么 + 1-2 个核心指针 + 验证状态）。
如果是 `/fix`：**不加新行**，只更新「验证」列数字 + 回写原 P 文档的修复记录段。

### 3. P 文档状态同步

更新 `docs/阶段路径/Pxx-*.md`：
- 头部 `**进度**` 行：📋/🚧/✅ + 一句话状态
- 实施顺序表：每行的状态列 📋→🚧→✅
- 如果实施时发现了方案没料到的陷阱，追加「关键陷阱」段（可选）

### 4. 架构 / 决策回写检查

如果实施过程中**偏离了原方案**（改了签名、换了路径、加了非目标项），回写：
- `docs/架构/<topic>（方案）.md` — 更新对应段
- `docs/决策/<topic>.md` — 如果决策变了（罕见），先与用户确认

如果实施与方案完全一致，跳过本步。

### 5. CLAUDE.md 其他段检查

改动是否触发其他段更新：
- 新增 Tauri command →「新增的 Tauri command」段
- 新增路由/窗口 label →「多窗口系统」段 + capabilities
- 新增 skill →「前端约定」
- 新增锁定决策 →「四条锁定决策」（需用户显式确认）

### 6. 呈现 diff

把所有文档改动汇总呈现给用户确认。

## Gate（过关条件）

- [ ] CLAUDE.md 进度表指针/验证数字与当前代码一致
- [ ] P 文档状态标记已推进
- [ ] 新增 command/路由/文件已在 CLAUDE.md 登记
- [ ] 实施偏离方案的，架构文档已回写
- [ ] 用户确认

## 注意

- **不要在这一步改代码**——纯文档同步。如果发现代码问题，记录下来建议开 `/fix`
- CLAUDE.md 进度表保持「是什么 + 1-2 个指针 + 验证」的密度，不要膨胀成实现细节（细节归 P 文档）
- 指针逐一核对落在真实文件（防止指向已删除/改名的文件）
