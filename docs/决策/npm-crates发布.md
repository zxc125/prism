## scope 改名决策

- **`@prism` npm org 被他人注册**（org 名与包名独立抢注——`@prism/observer-sdk` 包名虽 404 但 org 名被占）→ 改用 `@prism-obs`。
- crates.io 无 scope/org 机制，名字全局唯一；`observer-storage` / `tauri-plugin-observer` / `observer-server` 三者均未被占，沿用 `observer-*` 系列（不改名）。
- 全库（代码 import / workspace 依赖 / vite alias / 官网文案 / 文档 / skill）统一改名 `@prism/observer-sdk` → `@prism-obs/observer-sdk`、`@prism/observer-tauri` → `@prism-obs/observer-tauri`。

## npm 发布配置决策

- **入口指向 dist**：`main`/`types`/`exports` 从 `src/index.ts` 改为 `dist/index.js` + `dist/index.d.ts`；`files` 收窄为 `["dist"]`。
- **d.ts 生成**：`vite-plugin-dts`（`rollupTypes: true` 合并单文件 d.ts）+ `sourcemap: true`。
- **内部 dev 与发布入口分离**：根 [vite.config.ts](../../vite.config.ts) + [examples/tauri-demo/vite.config.ts](../../examples/tauri-demo/vite.config.ts) 加 `resolve.alias`，内部 dev/build 直连 src 源码（热更新），npm 发布的消费方走 `exports` → dist。
- **observer-tauri external 用正则**：`/^@tauri-apps\/api/` 匹配子路径（`/core`、`/event` 等），否则整个 `@tauri-apps/api` 被打进 bundle（80KB → 2.4KB）。
- **observer-tauri 发布用 `pnpm publish`**（非 `npm publish`）：pnpm 自动把 `workspace:*` 解析成精确版本（`0.1.0`），否则消费方装不了。下次发版改 `workspace:^` 可得 `^0.1.0` 更灵活。
- **国内镜像分离**：全局 registry 是 `npmmirror`（只读镜像），登录/发布都加 `--registry https://registry.npmjs.org/` 指定官方源。

## crates.io 发布配置决策

- **path 依赖加 version 双指定**：`observer-storage = { version = "0.1.0", path = "..." }`——crates.io 不接受纯 path 依赖；path 供 monorepo 本地开发，version 供 crates.io 解析。
- **发布顺序**：`observer-storage`（无内部依赖）→ `tauri-plugin-observer`（依赖前者，需等 crates.io 索引传播 ~25s）。
- **tauri-plugin-observer 发布用 `--no-verify`**：Tauri plugin 的 build.rs 在验证编译时生成 `permissions/autogenerated/`，被 cargo 检测为「源目录被修改」而拒绝发布。`--no-verify` 跳过验证（发布前已 `cargo check` 全量通过）。
- **`cargo login` / `publish` 需 `--registry crates-io`**：全局 `~/.cargo/config.toml` 把 crates.io 替换成 rsproxy-sparse 镜像，镜像不支持登录/发布。
- **crates.io 要求已验证邮箱**：发布前需在 settings/profile 设置并验证邮箱。
