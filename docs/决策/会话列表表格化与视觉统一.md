# 会话列表表格化与视觉统一 决策

> P21（2026-09-17 评审定稿）：console 会话观测视图三项改造——会话列表换 el-table-v2 虚拟表格、时长语义修复（未结束态显式化）、统一 console 字体（EP 字体变量回接 token）。上位输入：用户需求 + bug 实证（本机 14 会话 13 个无 `endedAt`）。实现流水账见 [docs/阶段路径/P21-会话列表表格化与视觉统一.md](../阶段路径/P21-会话列表表格化与视觉统一.md)。

## 范围决策

- **表格形态 = `el-table-v2`（EP 自带虚拟表格）**：零新依赖（element-plus ^2.14.3 已在）；会话量随外部接入增长，卡片列表无虚拟化承载。**显式反转 P10「卡取代行」方向**：P1 原始形态即「富行」，P10 改卡的信息增益（色点/时间/时长/名称/标记）在表格列化后全部保留且更可扫读；此反转在方案文档论证并在 CLAUDE.md 回写，非静默改形态。
- **时长语义 = 未结束态显式化**：无 `endedAt` 的会话显示「未结束」状态徽标，时长列显示 `—`，**废除 `endedAt ?? Date.now()` 的增长数值展示**。bug 定性：数据层（会话未正常停止，P19 已把「外部会话无 endedAt 是常态」写成关键陷阱）+ 展示层（now 兜底渲染与真实完成时长无差别，误导）。注：卡片渲染非响应式，数值只在刷新时变化、非逐秒跳动——但每次刷新值都不同，感知即「一直在变」。
- **appId 列纳入**：`SessionMeta.appId` 已在 `list_sessions` 返回路径（零数据成本）；site 手册 quickstart.md L58 已向用户承诺「appId 为 web-demo 的会话」可见，属兑现承诺。仅在有值时显示。
- **批量删除 = 前端选择集 + 复用 `delete_session` × N（spec 补录，2026-09-17）**：表格首列 checkbox 选择（全选作用于**当前筛选结果全集**——虚拟表格只渲染可视区，全选须作用于全集才有用），「删除所选 (N)」逐个调既有 `delete_session` 后刷新清空选择。零后端/API 变化。
- **「最后活动时间」估算：本期不做（留 P.x）**：数据（段索引 `lastTs`）在 `read_session_meta` 路径已存在，但**不在列表路径**——补齐需 Rust 列表命令聚合，且 gz 段的 lastTs 需整文件解压（P19 尾窗 seek 优化不覆盖 gz），列表全量刷新成本不可控。采纳门（后续）：仅对无 endedAt 会话计算 + 结果缓存 + 先实测 gz 尾行成本。本期「未结束」徽标已消除误导，不依赖该数据。

## 技术路线决策

- **虚拟化选型 = EP 自带 table-v2，非自实现、非三方库**：与 D7（大文件回放性能）「自实现定高虚拟滚动、不引三方库」不冲突——那是十万行信号流场景；会话列表量级小，且 EP 为既有依赖，无新增。
- **SessionCard 处置 = 保留为自定义行渲染器**：卡片内容吸收进表格行渲染，组件不删——P10 测试流程场景 H 的组件清单少动，且「来源色点」在行内存续（concepts.md L58 对外承诺来源色区分）。
- **空/加载态 = EmptyState/SkeletonList 保留**，经 el-table-v2 的 empty/loading 桥接，P10 测试场景 G/H 形态不变。
- **字体统一 = `:root:root` 补 `--el-font-family: var(--font-sans)`**：与既有 EP 深色化机制（CLAUDE.md「Element Plus 深色化」）同构，把 EP 拉回既定 token，属 P10 字体纪律（mono 限定技术值 / 正文 sans）的补全，非新设计。table-v2 的 DOM/class 与 el-table v1 完全不同，theme.css 现存 `.el-table` nudge 为无主 CSS，随本 P 清理替换为 v2 适配。

## 边界决策

- **对外手册零改动**：site/docs 10 篇全部「会话列表/会话浏览器」形态无关措辞（已逐篇核实），表格化不产生失实；来源色点承诺继续满足。
- **内部文档同步**：CLAUDE.md 签名元素重述为「Sessions = 会话浏览器（表列行 + 来源色点）」——形态中性载体词，根因修复（本次冲突源于把「卡」这一实现形态写进了签名元素）；docs/测试/P10-测试流程.md 场景 D3/G/H 4 处「会话卡」措辞与组件清单随实施更新；P10 方案 §5 为历史文档注记不回写。
- **不动 Rust/npm/后端**：纯前端 P；`list_sessions` 接口与 `SessionMeta` 类型零变化。

## 默认值 / 取值

- 表格行高 / 密度：对齐 P10 密集读出（dense readout）风格，mono 仍严格限定时间码/ID/技术值列；具体数值 impl 时由 frontend-design 流程定。
- 「未结束」徽标：琥珀系信号色（承袭 REC/进行中 DNA），与「导入」tag 同款式。
- 字体走查范围：全部 EP 组件 + 自建组件抽检，以 `--el-font-family` 生效为准。

## 未做（留后续）

- 「最后活动时间」列：见范围决策采纳门。
- **「无 endedAt」数据层不修（2026-09-17 拍板：维持现状）**：成因是异常终止（录中杀进程/崩溃/关主窗口）时进程已死，真实结束时间物理丢失——不是可修复的 bug；web SDK 正常关闭走 `session/end` 不缺，仅崩溃/强杀场景缺失。现有两层缓解已够用：列表「未结束」徽标（P21 D4）+ 回放时长 `lastTs` 估算（P19）。**重开触发**：bond-sat 等外部接入后「未结束」徽标大量出现。届时缓解路径二选一：① 启动回填——用段索引 `lastTs` 写回 `endedAt ≈ 最后活动`（改写用户数据，需决策背书 + gz 段回填成本先实测）；② 列表加「最后活动」列（只展示不写，采纳门同上）。
- 后端批量删除命令（`delete_sessions` 一次事务）：现量级 N×`delete_session` 足够；万级批量或需原子性时再议（对外 API 变更，届时升格）。
- 服务端分页/筛选：`list_sessions` 全量 + 内存过滤在本机量级足够，量大后再议。
- 「进行中录制」实时状态（区分「正在录」与「异常终止」）：需会话级活跃信号，现 `is_recording_active` 是进程级——本期徽标统一「未结束」，细分留 P.x。
