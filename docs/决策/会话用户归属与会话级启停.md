# 会话用户归属与会话级启停

> P22 锁定决策（2026-09-18 评审）。外部输入：bond-sat 提案「用户维度会话拆分与用户信息注入」（2026-09-17，其仓库 docs/observer-recording/）。方案细节见 [会话用户归属与会话级启停（方案）](../架构/会话用户归属与会话级启停（方案）.md)，本文只记决策。

## 背景

bond-sat「日志信息」页需按当前登录用户过滤/导出会话。现状：会话边界 = 进程启动（autoStart），session.json 无用户字段，登录前即开会话——多用户混录于同一会话，导出必然携带他人数据。需求方提案 A/B 两案，选 A（上游发版支持），本决策记录上游侧拍板。

## 决策

| # | 决策点 | 选择 | 理由 |
|---|---|---|---|
| D1 | meta 注入点 | 插件 `start_session` 可选参数（运行时），非 `ObserverConfig`（装配期） | 用户身份登录期才存在，装配期静态配置放不下；与 P20 D1「部署拓扑装配期声明」不冲突——那是拓扑，这是身份 |
| D2 | stop 写路径 | 只写 `endedAt`（read-modify-write），废除整文件重建（impl 直用等价的 `finalize_session`，非 `merge_session_meta`） | 提案的 `session_meta_payload` 第 6 参方案需 Session 态加字段且不解决状态/文件漂移；read-modify-write 根除「stop 冲掉 start 期 merge 字段」陷阱（commands.rs `stop_overwrite_keeps_app_id` 同型），并解除 stop 对 source/app_id 状态依赖 |
| D3 | 保留键保护 | 宿主 meta 不覆盖 `id`/`startedAt`/`source`/`appId` | 基础键是平台身份字段；实现 = 先 merge extra 后插基础键 |
| D4 | user 形态 | `SessionMeta.user?: { id: string; name?: string }` 具名字段 | 跨包契约清晰，不引入索引签名（提案论证成立）；建议宿主仅注入 id + 姓名，不带账号/手机号（合规口径见下） |
| D5 | controller 会话级 API | `startSession(meta?)`（幂等，已活跃先 `stop_session` 收口）/ `stopSession()`（= invoke `stop_session`，双模统一，不 unlisten/destroy） | 会话边界归宿主策略（登录区间是宿主用例，非平台概念）；双模统一因 Remote 的 `stop_session` 本就清态 + 广播，事件驱动链路自动停段 + 主窗 endSession；段门控语义不变（`gating: "manual"` 宿主无感） |
| D6 | Remote 服务端 | 零改动 | 已核实：`/ingest/session` 整 body 即 meta（routes.rs:86）+ `HttpSink.startSession` merge 实参（sinks.ts:48）+ IndexedDBSink 已收 meta；仅 TS 类型放宽转正 |
| D7 | 版本 | crates `tauri-plugin-observer` 0.5.0 / npm `observer-tauri` 0.6.0 / npm `observer-sdk` 0.4.0 | 0.x minor = 兼容新增（P17 D6 / P18 / P20 先例）；发版顺序 sdk → tauri（依赖）→ crates（独立） |
| D8 | console UI | 用户列后并入（2026-09-18 用户拍板，P22 实施表 1.9）；用户过滤仍不做 | 需求方是 bond-sat（Local 自行过滤）；console 读路径已透传 user，加列纯前端展示工作，不阻塞本 P |

## 与锁定决策的关系

四条锁定决策全不触碰。本决策是「观测外部」能力的延伸：会话归属信息让外部应用的会话可按主体过滤，闭环仍回「回放 + 诊断 + 导出」。

## 合规口径

`user` 以明文写入 session.json（Local 落盘 + Remote 上报），与 P16 D9「会话即明文 JSON」一致；数据因此可归属、可过滤，合规上是增强而非削弱。P9 redact 只作用于事件 payload，不动 session meta，user 不被剥离。入镜字段范围建议仅 `id` + `name`（提请宿主评审确认，平台不做白名单强制）。

## 否决项：方案 B（宿主 sidecar 映射）

bond-sat 自维护 `user-map.json`（sessionId → 用户区间）——否决：① 同一 sessionId 内 A/B 用户段混录的本质未解决，bundle 导出必携带他人数据，「只看本人」退化为视觉过滤；② 映射与会话数据分离，插件导出的 bundle 不带用户，跨机导入后过滤失效。仅当上游变更被否时的过渡选项。

## bundle 契约

session 对象加可选字段 `user`，按 [bundle-规范.md](../架构/bundle-规范.md) 版本演进策略「不破坏性变更（加可选字段）：不 bump version」，version 保持 1，旧 import 兼容。读路径（list/read/export/import）全为裸 `Value` 透传，零改动已核实。
