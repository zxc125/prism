# 导出流式化与压缩交付 决策

> 2026-11-18，承接下游 bond-sat-frontend 提案（`docs/observer-recording/2026-11-18-诊断数据导出流式化与压缩交付提案.md`）：诊断数据导出在大 会话（GB 级）下全量内存组装峰值 10GB 级（换页抖动/OOM，交易客户端不可接受），且裸 JSON 大文件不可 IM 转发。上游立项 P25 治理。可落地方案见 [导出流式化与压缩交付（方案）](../架构/导出流式化与压缩交付（方案）.md)，实现流水账见 [docs/阶段路径/P25-导出流式化与压缩交付.md](../阶段路径/P25-导出流式化与压缩交付.md)。

## 范围决策

- **只进 to-file 命令**：流式化与 compress 参数只落 `export_session_to_file`，`export_session`（IPC 直返）本体不动。延续「只加变体不改本体」（[导出to-file变体.md](导出to-file变体.md)）；同画像内存链路（console 自有导出 / server `GET /sessions/:id/export` / npm `uploadSessions`）另 P 盘点。
- **交付压缩定位第三层**：`.zst` 属「交付文件层」（解压后字节 = prism-session v1 原文，契约零 bump），与 P24 传输层请求 gzip、P9 排除项「bundle 内嵌 gzip（载荷层）」显式区隔，照 P24 手法记档不视为重开。
- **单版 0.7.0 发版**（**论证改判**，原两里程碑切分前提被证伪）：M1 代码快照不存在于版本控制（发 0.6.1 必是完整 M2 代码）；新参数进 patch 违反版本惯例；宿主 zstd 0.13.3 已在依赖树（「零新增供应链面」对唯一已知消费方成立），M1-only 消费者集合为空；宿主原提案 §六 本就单版 0.7.0。**M1/M2 里程碑由 compress 参数提供**：缺省 false 与假想 M1 同一运行时路径，渐进验证由「不传/传 compress」两个验收场景承载。对 bond-sat 推荐直接钉 `=0.7.0` **两阶段接线**（阶段一不传 compress 实测内存 → 阶段二小补丁传 true）；0.6.1 单独升级保留为可选非推荐。

## 技术路线决策

- **流式写 + parse 校验直写原文行**：segments 逐行 `read_line`，`from_str::<Value>` 校验通过后直写原文行文本（不重序列化）；坏行剔除沿用现状语义；**行级失败（残行/坏 JSON/单行非 UTF-8）剔行继续；流级失败（gz 截断等 read 持续 Err）停止续读该段、保留已解出行**——段键必存在，导出永不因坏段炸掉（比全量实现「整段剔空」保留更多有效数据，属预期改进并经单测与 build 路径对照钉死）。行校验用 parse 而非 `json_balanced`——导出低频且已在 spawn_blocking，CPU 换正确性（非法行入 bundle 会让导入侧 `parse_bundle` 整体拒绝，闭环单点故障）。
- **segments 输出 segmentId 字典序**：现状 `build_export_bundle` 经 serde_json `Map`（BTreeMap，全仓未开 `preserve_order`）已是字典序稳定输出；流式按目录枚举序直写是回归，排序必做（同 crate 先例 `bundle.rs` `files.sort()`）。
- **压缩用 zstd level 3，依赖只进 plugin crate**：宿主 client_log 同款（已实证编译）；storage 流式 API 压缩无关（吃 `&mut impl Write`）。flate2(gzip) 为备选记档——若后续「console 原生解压」立项，gzip 可让 console 免引 C 依赖，届时再权衡。
- **返回值 = 实际落盘文件字节数**：经 `.metadata().len()` 取（宿主 client_log `compress_to` 先例，`finish()` 后取文件元数据，不硬编码压缩比换算）；compress=false 时与现状口径一致（未压缩字节），compress=true 时为压缩后字节。

## 边界决策

- **compress 默认 false 保闭环**：默认出明文 `.json`，console「导出→导入」闭环（锁定决策 #3 的落地形态，P16/宿主验收 #2 承诺）默认路径零变化；压缩是宿主显式 opt-in。
- **.zst 解压即回导**：`.json.zst` 手册注明「`zstd -d` 解压后即可回导 console 导入」——闭环对人工转发保持一步可达，不声明放弃；console 原生嗅探解压留后续 P。
- **宿主接线不在本仓库**：bond-sat 传 `compress: true`、`.json.zst` 命名（含无 ts 兜底分支）、文案，由宿主随 M2 发版自行接线；上游只提供能力 + 测试流程文档给宿主验证清单。

## 默认值 / 取值

- `compress` = `None`（即 false）：默认明文 `.json`，老调用方零改动。
- zstd level = 3：与宿主 client_log 一致；大会话导出速度与压缩比平衡点。
- 压缩比预期口径 = 5-12x（视 base64 图片/长文本占比，DOM 快照型可达 8-15x）：实测校准，不承诺 10:1。
