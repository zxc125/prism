# 录制事件量控（录制档位）决策

> P14 spec 阶段决策。背景：交易系统等高频页面（行情推送 → 密集 DOM mutation）下，rrweb 全量默认录制导致 (a) 录制本身开销引发页面卡顿掉帧 (b) 大量无回放价值的录制数据。需要「仅记录用户操作」级别的量控制能力。实现流水账见 [docs/阶段路径/P14-录制事件量控.md](../阶段路径/P14-录制事件量控.md)。

## 范围决策

- **过滤落点**：录制端 SDK 层（`SegmentRecorder` 组装 rrweb record options + 预设映射）。存储 / 传输 / 回放链路零改动——量控制在数据产生处解决，`append_events`、sink、bundle 契约均不感知。
- **bundle 契约**：不动。契约不约束 segment 内事件构成，`parseBundle` 不校验 rrweb 事件内部结构；过滤属于录制策略，无需 version bump。
- **诊断信号豁免**：type:6 诊断信号（error/console/network）**永不**随 DOM 采样降级。信号 hook（`installSignalHooks`）独立于 `record()`，天然不受 sampling 影响；写入决策防止后续实现误伤（锁定决策 #4「交错事件模型」的边界声明：过滤 = 同一条事件流内的量控制，不拆流）。
- **console self-obs 设置落点**：录制档位为纯前端录制策略，存 localStorage（不进 Rust ingest config——那管的是 HTTP 接收 server，正交）。

## 技术路线决策

- **预设制（RecordProfile）而非裸暴露 record options**：`full` / `balanced` / `minimal` 三档 + `domBlocks` 区域屏蔽列表。理由：交易系统用户要的是「选个档位」，不是学习 rrweb sampling 语义；裸透传留作后续 P.x 的进阶口。
- **三层工具箱，本 P 只做前两层**：
  1. **sampling 高频通道控制**（rrweb 原生）——降 mousemove/scroll/input/mouseInteraction 事件量。*对行情 mutation 无效*（rrweb 2.1.1 无 mutation 级采样）。
  2. **domBlocks 区域屏蔽**（映射 rrweb `blockSelector`）——行情表格等免录区 selector，mutation 完全不进事件流且跳过序列化，**降数据量与录制开销最直接**的手段；回放中该区域显示占位。
  3. ~~emit 层 mutation 预算/丢帧~~（自建 + `checkoutEveryNms` 保底，接受画面陈旧）——**本 P 不做**，留后续。
- **「仅记录用户操作」不可硬做**：不能实现为「丢光 mutation 只留 interaction」——画面将冻结在初始快照，交互事件作用于不存在的 DOM。可行语义是「高频通道静默 + 免录区屏蔽」，需在 UI hint 与文档站明确此预期。
- **full 档零行为变化**：默认档与现状逐字节一致，已有用户/已发布包升级无感。

## 边界决策

- **不动 Rust 侧**：`plugins/tauri-plugin-observer`、`crates/observer-storage`、`crates/observer-server` 的 append 链路零过滤照旧（服务端过滤与配额已有 P9 体系）。
- **不动回放链路**（2026-09-10 修订，见 [大文件回放性能 决策](大文件回放性能.md)）：本条的唯一语义是「**录制档位的引入不得要求回放侧感知**」——新增档位产出的数据，回放侧零改动即可消费；type:2 全量快照 / type:4 Meta / type:6 信号永不丢，回放天然兼容（Replayer 原生支持流内多次 full snapshot）。**不构成对回放侧性能改造的冻结**：P19 为治理大文件回放卡顿会改 `usePlayer`/Player 组件（按需创建 Replayer、seek 与同步策略、信号流虚拟化），不改任何数据消费语义与产物格式。原「`usePlayer`/Player 组件零改动」措辞就此收窄为 P14 范围内的自我约束。
- **推翻两条旧 scope 决策**：P9「不动采集层」与《离线导出与云端部署（方案）》L1 采集层「不动」标注——本决策有意覆盖，后续文档引用采集层改动时以本文件为准。

## 默认值 / 取值

- `profile = "full"`：默认零行为变化。
- `balanced`：`sampling.mousemove=100` · `scroll=200` · `input:'last'` · `slimDOM preset` 开。
- `minimal`：`sampling.mousemove=false` · `scroll=500`（类型只收 number，无法全关）· `mouseInteraction` 禁用表（保留 Click/TouchStart/TouchEnd，其余含 Focus/Blur/TouchCancel 设 false——rrweb 对象形式为「禁用表」语义：false=关、未列出=记录，与类型直觉相反）· `input:'last'` · `slimDOM preset:'all'`。
- `domBlocks = []`：默认无免录区；交易场景建议行情表格 selector 传入。
- 发版：`@prism-obs/observer-sdk` 与 `@prism-obs/observer-tauri` minor bump 0.2.0（0.x 阶段 minor = 兼容新增），遵循 [npm-crates发布](npm-crates发布.md) 流程。

## 未做（留后续）

- **裸 record options 透传（`RecordTuning`）**：进阶用户细调每个 sampling 通道——等有真实需求再做（P.x）。
- **emit 层 mutation 预算/丢帧**：非交互静默期丢弃增量 + 定期 checkout 保底——是唯一能降 mutation 量的手段，但引入画面陈旧语义与实现复杂度，等 domBlocks + minimal 档实测不满足再上。
- **session.json `recordProfile` 可选字段**（回放侧「画面可能滞后」提示的数据依据）——动 observer-storage → `cargo test`，倾向 P.x；短期可用现有 `note`/`tags` 字段人工标注。
- **录制端 CPU 开销档**（降 MutationObserver 回调本身的开销）——与数据量档位正交，实测卡顿仍在再议。
