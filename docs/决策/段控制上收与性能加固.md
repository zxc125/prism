# 段控制上收与性能加固 决策

> P17 场景：外部应用（bond/frontend）实测录制期间切页/滚动卡顿，归因三成本中心（空闲期常录的 mutation 序列化、`append_events` 主线程阻塞、活跃期虚拟表 mutation 洪峰）；bond 侧 0909 提案（方案 A 手动档）+ 本仓性能归因合并为同一阶段。实现流水账见 [docs/阶段路径/P17-段控制上收与性能加固.md](../阶段路径/P17-段控制上收与性能加固.md)。

## 范围决策

- **上收「机制」、策略留宿主**：controller 暴露 `startSegment`/`stopSegment`/`signal` 手动档（bond 提案方案 A）；交互监听/判闲/异常兜底策略留在宿主应用。通用门控模块（`installActivityGating`，提案方案 B）等第二个门控消费者再做。
- **性能加固纳入同一 P**：`append_events` async 化 + SDK flush 串行化与上收同批发版——三件事触碰同批文件、共享同一次实测验收（bond A/B）。
- **下游迁移不在本仓**：bond 升级三包、usePrismRecorder 收敛到 controller、`.prism-block` 扩到虚拟表行容器均为消费方动作，P17 文档列清单不实施。

## 技术路线决策

- **signal() 复用 SegmentRecorder 既有 emit buffer**：type:6 交错进同一条事件流（锁定决策 #4），受 P14 D8「信号永不随 DOM 采样降级」豁免约束；不加新通道。
- **flush 串行化在 SegmentRecorder 层**（JS await 队列），不动 Sink 接口；实际作用点是 TauriSink 的 invoke 路径（HttpSink.appendEvents 本为同步入队）。
- **`append_events` 用 `#[tauri::command(async)]`**（非 async fn + spawn_blocking、非 writer 线程）：签名不变，serde + 写盘脱离主线程；保序由 SDK 串行化兜住（同窗口至多一个在途 invoke，下一批发送在前一批响应之后 → 到达序 = 发送序；跨窗口异文件互不干扰）。权限声明不变（命令名不变）。
- **零 diff 手法（用词对准）**：未调用新 API 时逐行为等价——手法出处为 P14 D3「零 diff」（full 档返回 `{}`）与 P16 D1「默认值保兼容」（mode 默认 remote），非单一出处。
- **版本**：`@prism-obs/observer-sdk` 0.2.0 → 0.3.0、`@prism-obs/observer-tauri` 0.3.0 → 0.4.0（additive minor，0.x 阶段 minor = 兼容新增）；`tauri-plugin-observer` 0.2.0 → 0.2.1（执行模型变更、公开 API 不变 → patch）。`npm-crates发布.md` 包清单随之回写。
- **覆盖既有 scope 约束的声明**：P14「不动 Rust 侧」语义为 append 链路**零过滤**，本 P 不改过滤行为、仅改执行模型，但触碰了 P14 列为不动的 `plugins/tauri-plugin-observer/**`——以本决策为准（沿用 P14 决策「推翻旧 scope 决策」行文范式）；P16「observer-sdk 不动不发版」为 P16 时点约束，本 P 发版解除。
- **不做 checkoutEveryNms / inlineStylesheet / 裸 RecordTuning 透传**：门控下段短有界（bond 方案 §8 #14 论据），快照成本大头是 DOM 遍历非样式表读取；等实测不满足再上（P14 未做段已有锚点）。
- **手册章落既有页内**：5 页结构锁定不破（决策/手册小白化），「高频渲染场景量控」为 web.md / tauri.md 既有量控相关节内的 `##` 扩展；按三档预设语义写、引导 domBlocks，不引导裸调 RecordTuning；发版后同步更新版本锚点（顺手修正现状 0.2.x 锚与 observer-tauri 0.3.0 的漂移）。

## 边界决策

- **controller.startSegment 返回 `Promise<void>`**：不回传 segmentId（内部闭包现状即不回传，消费方 bond 经 `signal()` 注入后无需 id；要了再以 additive minor 加）。
- **手动 stopSegment 不补 hidden lifecycle**：hidden 语义归 Rust `on_window_event`（Local 落 windows.jsonl）与 `segment{stop}` 事件（Remote 补报），手动停段是宿主策略边界、非窗口隐藏。
- **startSegment/stopSegment 幂等**：复用现有 `rec.active` 早退守卫。
- **signal() 段未活跃时丢弃**：消费方先 `startSegment()` 再 `signal()`（与 bond 空闲异常兜底「开段→补发」语义一致）。
- **段边界与交互解耦成为可能**：上收后宿主可把开段时机挪到 `requestIdleCallback`/路由稳定后——这是治理「段首全量快照尖峰恰好压在点击上」的前提，为提案文档未覆盖的补充价值。
- **observer-sdk 最小引入 vitest**（2026-09-09 拍板）：仅覆盖 flush 串行化 + signal 注入 2-3 用例，不铺开全 workspace——保序是静默回归高危区，A/B 实测无法隔离。
- **`gating?: "manual"` + controller `active` getter**（2026-09-09 impl 补记，D9）：bond 提案方案 A 的隐含缺口——只上收 controller 方法时，`recording-session{active}` 广播（:142）与挂载兜底（:197）的自动开段会压过宿主门控，demo 验收与 bond 迁移均不成立。抑制开关语义对齐提案 §3 Plan B 合并表（广播/兜底不开段；`segment{start/stop}` 事件与 autoStart 不变），纯 additive 缺省零 diff；`active` 属机制判据非策略。
