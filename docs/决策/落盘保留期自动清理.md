# 落盘保留期自动清理 决策

> P23（2026-10-20）依下游 bond-sat 已定稿提案 + 本仓五路代码核对分析拍板。背景：bond-sat Local 模式落盘无保存时效，macOS AppData 完全无界；能力层（`observer-storage::retention`）P9 已沉淀、server 已接线，插件侧接线空白。实现流水账见 [docs/阶段路径/P23-落盘保留期自动清理.md](../阶段路径/P23-落盘保留期自动清理.md)，落地方案见 [docs/架构/落盘保留期自动清理（方案）.md](../架构/落盘保留期自动清理（方案）.md)。

## 范围决策

- **自动清理 vs 外放删除命令**：本期只做插件**内部自动清扫**（宿主在 `ObserverConfig` 声明策略 = 显式 opt-in 授权），不新增宿主可调的删除命令。循 [外部应用本地落盘](外部应用本地落盘.md)「删数据是危险操作」边界，此处属**扩展而非推翻**：声明策略即授权，未声明即零行为变化。
- **清扫范围 = 当前落盘根**：只扫 `recordings_root_with` 当前配置根。切根不迁移、旧根不清（循 [外部落盘根自定义](外部落盘根自定义.md) D6「数据不删、仅不可见」），跨根清理即违规。
- **Remote 模式不启动清扫**：无本地落盘；服务端 retention 兜底（注：服务端对「无 endedAt 会话」有同构豁免盲点，本期记档不修，见「未做」）。
- **无主会话纳入清理**：升级前落盘的无 `user` 会话随策略清理——保留期属设备级策略，`user` 过滤仅是展示口径（合规安全侧），不构成豁免理由。
- **清扫与内嵌 server 同根**：console 内嵌 server 的 data_dir 即落盘根（`appDataDir/recordings`），server 清扫与插件清扫作用同一目录。原装 console 插件 retention 缺省空 → 插件线程不启动，实际只跑 server 一条（10min）；外部宿主声明策略后只跑插件一条（1h）；未来 console 若声明插件 retention，两条独立策略清同一根——均幂等只删、无锁冲突，策略叠加需宿主自审（2026-10-21 回归复核修正，原「数据面不重叠」失实）。

## 技术路线决策

- **protect 变体放 storage**：新增 `enforce_retention_protect(root, policy, protect)`，`enforce_retention` 改委托（空名单）：**签名不变，既有调用方正常路径行为不变**（新字段缺省 None；仅「Some(0) 防呆 / id 校验 / 实际计数」三个删除纪律点随变体生效，现网配置无触发面）；server/console 调用点零改动。不采插件私有实现（逻辑分叉）。
- **`enforce_retention` 本体语义不得变更**（P9 锁定「无 endedAt 跳过」+ server 清扫共用）：孤儿清理等新维度全部走**显式 opt-in 的新策略字段**，缺省 `None` = 旧语义。老调用方（server per-tenant / console 单租户）的策略缺省新字段，委托路径行为不变。
- **孤儿清理维度进本期**：新增策略字段 `orphan_max_age_days`——「无 `endedAt` 且 `startedAt` 超龄且不在 protect 名单」的会话可清。依据：P19 已实证「外部会话无 `endedAt` 是常态」（崩溃/强杀/正常点 X 退出均无收口，全链路无退出兜底——lifecycle 主窗口不拦截、无 `RunEvent::Exit`）；孤儿维度是「消除无界增长」动机的必要条件，且 protect 名单（豁免当前活跃会话，循 P22 D5）正是让它变安全的前提。**不采**「max_sessions 必配」替代方案（兜数量不兜时效，且把成本转嫁宿主）。
- **孤儿维度独立显式配置**（不与 `max_age_days` 隐式联动）：语义单一、可测试、server 侧后续 opt-in 零歧义；代价是宿主需显式声明（手册给 bond-sat 双 30 配方）。
- **protect 名单取「当前活跃会话」须 `filter(active)` 再取 id**：`stop_session` 不清 `s.id`（只置 `active=false`），不看 active 会无限期豁免已收口会话。收口即失去保护 = 收口后按策略参与淘汰（文档注明）。
- **清扫调度**：`init_with` 的 setup 内起线程，仅 `Mode::Local` 且策略非空；首跑延迟 30s、周期 1h。循环体包 `catch_unwind`（panic 记日志后 continue）——现成 panic 源：`recordings_root_with` 内 `expect`；无护栏则数据无界增长静默回归。
- **删除纪律**（protect 变体内落地）：`Some(0)` 视同 `None`（防呆：首启 30s 删光存量不可能是合法意图）；删除前过 `validate_session_id`，不合法跳过不计数（消除 `id≠目录名` 误删/虚计数）；返回**实际删除数**（`remove_dir_all` 失败不计数，Windows 锁场景下轮重试）。
- **锁纪律**：清扫线程取活跃 id 时锁只包 id 提取、绝不跨 `enforce` 调用（全 crate 对毒化锁按静默 no-op 处理，持锁跨 IO 会阻塞录制、panic 毒化锁放大成录制哑火）。
- **版本**：storage 0.1.0→0.2.0（新增 pub API + 策略字段，additive minor）；插件 0.5.0→0.6.0（config 字段 + 清扫，additive minor）；npm 两包零改动零发版（`ObserverConfig` 纯 Rust 侧，TS 无镜像）。循 [段控制上收与性能加固](段控制上收与性能加固.md) D6 minor 惯例。

## 边界决策

- **annotations.jsonl 随整目录连带删除**：P6 用户标注是会话的从属数据，与诊断数据同生命周期；storage 通用 API 不对单文件特判。宿主需长期保留应先 export bundle（呼应 P16 D5/P18 快照语义）。手册注明。
- **server 现网不回接**：protect/孤儿工具本期不迁给 observer-server 清扫线程（其对 in-ingest 会话的超量危险记档）；server 侧 opt-in 只需在租户策略里填新字段，属后续决策。
- **活跃会话体积无界**：常驻录制下单会话体积不受两维+孤儿三维约束，记档为已知 residual；后续按成本递进：`max_sessions` 兜底 < 孤儿维已覆盖的僵尸回收 < 会话级滚动（SDK/controller 语义变更，另立阶段）。
- **验收造数**：§九.4 已否决手动清理命令，联调造数以「预置目录 + 手改 session.json 时间戳」为约定方式，写进测试流程文档；不为此新增命令或夹具。

## 默认值 / 取值

- `ObserverConfig.retention` 缺省 = `RetentionPolicy::default()`（三维全 `None`）= 不清扫、线程不启动：存量宿主（console `init_with(..Default::default())` / 外部应用）零行为变化、零线程开销。
- 清扫周期 1h，首跑延迟 30s；对齐 server「便宜扫描」哲学，不采 10min（本地无此时效敏感）不采 24h（长挂机漏扫）。
- bond-sat 建议配方：`max_age_days: Some(30)` + `orphan_max_age_days: Some(30)` + `max_sessions: None`（Windows 有 updater 重装兜底，macOS AppData 依赖此值封顶；孤儿维覆盖异常退出）。

## 未做（留后续）

- 手动清理命令（`enforce_retention_now`）：API 面最小，需求方暂无入口诉求（提案 §九.4）。
- server 现网回接 protect/孤儿维度：工具已备，opt-in 即用；待 server 侧排期。
- 体积维度（QuotaTracker 的 Local 对齐）：动机与手段的缺口已记档，先观察三维实跑效果。
- 旧根清理 / 跨根治理：违反 P20 D6，明确不做。
- 会话级滚动（单会话分段重开）：SDK/controller 语义变更，若活跃体积实测成问题另立阶段。
- bond-sat「列表有、点开无」消失语义的 UI 错误态：归 bond-sat 前端，手册注明数据可能被清扫。
