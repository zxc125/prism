# 官网与品牌（方案）

本文档定义产品对外的品牌命名、定位、功能叙事、竞品差异与官网设计风格，是官网文案与视觉的执行依据。视觉像素级执行仍走 `/frontend-design` 流程，本文只定方向、文案与结构。命名决策已锁定（§1），其余章节据此展开。

## 1. 品牌命名

### 1.1 双轨命名：鉴（Jiàn）/ Prism

- **中文名「鉴」**：咬住「观测 + 回放诊断」。古义为铜镜、明察、引以为鉴--既指照见（观测），又指对照明辨（回放诊断），承载品牌的核心动作。
- **英文名 Prism**：补上「分光 = 交错事件模型」这层「鉴」本身没承载的项目特质。棱镜将白光分拆为光谱，正对应 error/console/network 信号交错进同一条事件流的交错事件模型；亦呼应多窗口对齐录制（多束光同源）。

中英合起来覆盖四条锁定决策：

| 锁定决策 | 由哪个名字承载 |
|---|---|
| 本地优先 | 鉴（观测台，本地分析） |
| 观测外部 | 鉴 + Prism（观测 + 多通道） |
| 闭环回放+诊断 | 鉴（明察、引以为鉴） |
| 交错事件模型 | Prism（分光） |

### 1.2 选名理由

1. **两条路线都站得住**--无论英文作为「鉴」的对译（A 路线）还是独立品牌（B 路线），Prism 都有力；备选 Retrospect / Mirro 只在 A 路线成立。
2. **技术镜像独特**--分光 = 交错事件模型，是「鉴」未承载的另一层项目特质。
3. **典故符合偏好**--牛顿分光是科学史经典，有含义背景，与选「鉴」的初衷一致。
4. **视觉天然咬合**--棱镜分光的光谱色正是琥珀金 + 冷青蓝绿，与 `--amber` `#F0A83D` + `--teal` `#4DD0C8` 同款。Logo 可直接做「白光入棱镜，分出琥珀/冷青双光谱」的图形，中英文共享一个视觉符号。
5. **短、独特、可注册**--5 字母，国际化无障碍，前端观测领域未被强势占用。

### 1.3 Logo 概念

白光 → 棱镜 → 双光谱（琥珀 + 冷青）。这一个图形同时是：

- 品牌符号（中英文共享）
- 产品机制隐喻（多源信号 -> 交错进同一时间轴）
- 调色板来源（不是任意配色，而是棱镜光谱）

## 2. 定位

### 2.1 一句话定位

> 本地优先的前端观测平台。会话回放、诊断信号、多窗口对齐--数据留在你手里，不上云，不锁仓。

### 2.2 定位三要素

1. **品类**：前端会话回放 + 诊断工具（不是 RUM，不是 APM，不是告警系统）
2. **差异化锚点**：本地优先 / 数据主权--与所有云竞品的根本分界
3. **能力边界**：闭环到「回放 + 诊断 + 导出/标注/分享」，明确不做生产 RUM、不做告警、不做用户行为分析

### 2.3 目标用户

| 优先级 | 人群 | 核心诉求 |
|---|---|---|
| P0 | Tauri / Electron 桌面应用开发者 | 多窗口对齐调试，别家做不到 |
| P0 | 注重隐私 / 合规的团队（金融、医疗、政企） | 用户数据不能出本地 / 出内网 |
| P1 | 不想按 session 付费的中小团队 | 一次性自托管，无 per-seat / per-replay 计费 |
| P1 | 开源 / 自托管倾向开发者 | 数据主权，无厂商锁定 |
| P2 | 需离线采集再回传的现场场景 | 断网录制 -> 导出 bundle -> 回工位诊断 |

### 2.4 不做什么（反向定位）

- ❌ 不做云端 SaaS RUM（不存用户数据）
- ❌ 不做告警 / 阈值监控 / 生产指标看板
- ❌ 不做用户行为分析 / 漏斗 / 热图
- ❌ 不做 per-session / per-seat 计费

这条「不做什么」清单是最强的差异化武器，官网单独立一节明示。

## 3. 功能

按「采集 -> 回放 -> 诊断 -> 协作 -> 部署」闭环组织，每条配一句价值描述。

### 3.1 采集

- **DOM 级会话录制**--基于 rrweb 2，像素级还原用户操作，非视频、体积小
- **多窗口对齐录制**--Tauri 桌面应用多窗口共享同一墙上时钟，回放时多轨同步驱动（**独家**）
- **Web SDK 嵌入**--`@prism-obs/observer-sdk` 一行接入任意 web 应用，单 tab 录制
- **Tauri Plugin 接入**--`tauri-plugin-observer` 装即用，外部 Tauri App 获得多窗口能力
- **离线采集**--IndexedDB 暂存，断网照录，恢复后导出 bundle 回传

### 3.2 回放

- **多轨时间轴 + 真实播放头**--平铺显示所有活跃窗口，琥珀色播放头带 glow
- **in-app 播放器**--`/s/:id` 路由内嵌，不开新窗口，面包屑导航
- **跨窗口同步**--按 `shown/hidden` 区间在主时间轴对齐各 segment

### 3.3 诊断（核心差异）

- **交错事件模型**--error / console / network 作为 rrweb plugin 事件（`type:6`）交错进同一条事件流，与 DOM 共享时间轴，不跨流对齐
- **诊断信号流**--统一信号流 + 过滤（非 DevTools 三 tab 模板），时间轴上 error 红标
- **信号类型色**--log 灰 / warn 琥珀 / error 牛血红 / network 冷青

### 3.4 协作

- **标注**--在时间轴任意时刻打标注（label / text / author），存 session 级 `annotations.jsonl`，与事件流分离
- **单文件 bundle 导出**--`prism-session` 格式，零依赖 JSON，跨进程 / 跨机迁移
- **导入重建**--导入分配新 id 重建目录，含版本校验 + 路径穿越防护

### 3.5 部署

- **桌面 App**--Tauri 2，macOS / Windows / Linux，零云依赖
- **单二进制自托管**--`observer-server` 一个二进制同时托管 API + console 前端，`--web-dir` 启用 SPA 静态托管
- **浏览器化**--console 可纯浏览器访问，LoginGate 输入 endpoint+key 即用
- **多租户**--自托管时支持 per-tenant 配额 / 保留 / 限流 / 服务端 PII redact（不可逆）

## 4. 亮点

6 个可一句话讲清的记忆点，官网每个配一个视觉签名：

1. **本地优先，数据不出本地**--默认零云依赖。用户数据不经任何第三方服务器，隐私天然合规，无厂商锁定。
2. **多窗口对齐录制，别家做不到**--Tauri 多窗口共享墙上时钟，回放多轨同步。核心论点，非 side feature。
3. **交错事件模型，DOM 与诊断信号同一时间轴**--error/console/network 不在侧边栏独立面板，而是交错进 DOM 事件流。回放到第 3 秒，同时看到 DOM 状态、那条 console、那个失败请求。
4. **诊断导向，不是监控导向**--不做告警、不做 RUM 指标，专注「复现 -> 看懂 -> 标注 -> 分享」的诊断闭环。
5. **单二进制自托管**--`observer-server` 一个文件，API + 前端一起托管。内网、离线、合规审计都能用。
6. **开放 bundle 契约**--`prism-session` 明文 JSON 规范，本地文件 / 本地 server / 云端上传三路共用。你的数据，随时带走。

## 5. 竞品差异

### 5.1 对标矩阵

| 维度 | 鉴 / Prism | FullStory / LogRocket | Sentry Replay | Highlight.io | PostHog Replay | rrweb（库） |
|---|---|---|---|---|---|---|
| 默认形态 | 本地 / 自托管 | 云 SaaS | 云 | 云优先 | 云 | 库 |
| 数据主权 | 完全自有 | 厂商托管 | 厂商托管 | 厂商托管 | 厂商托管 | 自有 |
| 计费 | 无 / 自托管成本 | per-session | 包在套餐内 | per-session | per-session | 免费 |
| 多窗口对齐 | **支持（独家）** | ❌ | ❌ | ❌ | ❌ | ❌ |
| 诊断信号交错 | **同一时间轴** | 独立面板 | 偏 error | 独立面板 | 独立面板 | 需自建 |
| 定位 | 诊断工具 | RUM / 分析 | 错误追踪 | RUM | 产品分析 | 录回放库 |
| 告警 / RUM | **不做** | 做 | 做 | 做 | 做 | ❌ |
| 桌面 App 形态 | **有（Tauri）** | ❌ | ❌ | ❌ | ❌ | ❌ |
| 开放数据契约 | **有** | ❌ | ❌ | 部分 | ❌ | N/A |

### 5.2 三条核心差异叙事（官网文案可直接用）

**① 与 FullStory / LogRocket（云 RUM）**

> 它们把你的用户会话上传到第三方云，按 session 收费，数据不在你手里。鉴 / Prism 反过来：默认本地，可选自托管。没有 per-session 计费，没有「数据导出要找销售」。你的会话文件就是一份 JSON，随时能打开、能带走、能删干净。

**② 与 Sentry Replay / Highlight（错误回放）**

> 它们把回放绑在错误追踪 / RUM 套件里，诊断信号散在不同面板。鉴 / Prism 只做诊断这一件事：error/console/network 交错在 DOM 同一条时间轴上。回放到第 3 秒，同时看到页面、那条 console.error、那个 500 请求--不用在三个 tab 间来回跳。

**③ 与 rrweb（库）**

> rrweb 是优秀的录回放库，但它只是库--没有 console、没有诊断信号、没有多窗口、没有标注协作。鉴 / Prism 建在 rrweb 之上，补齐「从录到诊断到分享」的整条闭环。

## 6. 官网设计风格

### 6.1 设计原则：继承 P10「现代科技感」，为营销放大呼吸感

产品 console 是控制室 / 观测台的密集信息界面；官网是同一品牌的门面，应是「控制室的大堂」--同一套视觉语言，但留白更大、叙事更强、签名元素更突出。

参照系（P10 已锁定）：Vercel 的克制 + Linear 的细节 + Raycast 的数字感。不退回通用暗色模板、不用 acid-green/vermilion、不用厚边框重面板。视觉变更仍须走 `/frontend-design` 流程（CLAUDE.md 规则），本文只定方向。

### 6.2 品牌主隐喻：棱镜分光

贯穿全站的中心视觉叙事：

> 白光（多源会话） → 棱镜（鉴 / Prism） → 双光谱（琥珀 DOM 流 + 冷青诊断信号流）

这不是装饰，而是产品机制的可视化：多源信号经棱镜分光，交错进同一条时间轴。官网 hero 动态可视化、section 分隔、logo 动效都可复用这个隐喻。

### 6.3 调色板（复用产品 token，保证品牌一致）

| 用途 | Token | 值 | 官网用法 |
|---|---|---|---|
| 页面底 | `--ink` | `#0A0C10` | 全站深空底 |
| 面板 / 卡片 | `--slate` / `--slate-2` | `#11141A` / `#181C24` | 内容容器、lifted surface |
| 主文字 | `--bone` | `#E6EAF0` | 标题、正文 |
| 次文字 | `--ash` | `#8B94A3` | 说明、caption |
| **信号主色** | `--amber` | `#F0A83D` | CTA、播放头、激活态、实时数据流（带 `--amber-glow`） |
| **数据辅色** | `--teal` | `#4DD0C8` | network、信息流、可视化（与琥珀暖冷对比） |
| 危险 / REC | `--oxblood` | `#E5484D` | REC 脉冲点、error 标记 |
| 细线 | `--hair` | `#1F242E` | 分隔线、卡片边（hairline，非厚框） |

色彩叙事：琥珀 = 信号 / 激活 / 实时；冷青 = 数据 / 网络 / 信息流。两者暖冷对比即棱镜双光谱，是品牌签名。token 定义见 [theme.css](../../src/styles/theme.css)。

### 6.4 字体

- **正文 / 标题**：系统 sans（`-apple-system` / `PingFang SC` / `Segoe UI`），不引外部字体（国内网络 Google Fonts 可能不通）
- **等宽**（`SF Mono` / `JetBrains Mono`）：严格限定用于时间码 / ID / 代码块 / CLI 命令 / 技术值--科技嗓音，不装饰性滥用
- Hero 标题字号需放大到 48-72px 级别（产品内 token 最大 `--fs-2xl: 28px`，官网需独立放大）

### 6.5 签名视觉元素（每屏一个，不复刻通用模板）

1. **Hero**：营销化可视化作主视觉--抽象的棱镜分光动画（白光入棱镜 -> 琥珀 + 冷青双光谱流动），不直接放产品截图。背景用 vue-bits beam / animated gradient 组件做分光流动线（琥珀 + 冷青双流，subtle 不喧宾夺主）
2. **多窗口段**：多轨时间轴可视化，窗口 lane + 真实播放头 + 信号交错点
3. **诊断段**：单条时间轴上 error（红）/ console（灰）/ network（青）信号交错排列特写
4. **部署段**：三形态（桌面 App / 单二进制 server / 浏览器）并置卡片，来源色点（本机琥珀 / web 冷青 / tauri 绿）
5. **REC DNA**：hero 角落或 Live 段保留牛血红 REC 脉冲点--品牌从「剪辑室」时代继承的锚点

### 6.6 交互与动效

- **克制**：参照 Linear / Vercel，动效服务于叙事，不为动而动
- **棱镜分光线**：缓慢、低对比、循环（hero 背景）
- **播放头 glow**：呼吸式微动（尊重 `prefers-reduced-motion`）
- **滚动揭示**：section 进入视口时淡入 + 微上移
- **代码块 / CLI**：等宽字体 + 冷青命令提示符

### 6.7 文案语调

- 中文，sentence case，具体优于聪明（与产品 UI 一致）
- 技术可信：敢放架构图、CLI 命令、bundle JSON 样例
- 不堆形容词：不写「强大的」「领先的」「革命性的」；写「多窗口共享墙上时钟」「error 交错进 type:6 事件流」

### 6.8 页面结构（一页式 + 少量子页）

```
1.  Hero           定位一句话 + CTA（自托管 / 看 Demo）+ console 主视觉 + 棱镜分光背景
2.  痛点           云 RUM 的三重代价：隐私 / 成本 / 锁仓
3.  本地优先宣言    数据主权--一节「我们相信什么」
4.  核心能力       6 个亮点的卡片网格 + 签名视觉
5.  独家：多窗口    Tauri 多窗口对齐的故事 + 时间轴可视化
6.  独家：诊断信号   交错事件模型特写
7.  闭环           录 -> 回放 -> 诊断 -> 标注 -> 导出 / 分享
8.  部署形态       桌面 App / 单二进制 / 浏览器 三选
9.  竞品对比       对标矩阵
10. 架构透明       rrweb-based / Rust 核心 / 开放 bundle 契约
11. 快速开始      CLI 命令（等宽块）+ 开源链接
12. Footer
```

**单页滚动**：12 节不拆子页，一屏到底。

### 6.9 官网技术栈与工程位置

官网是独立营销站，与 console（Element Plus + CSS 变量）分开，**放仓库顶层 `site/`**（pnpm workspace 新成员），不进 `src/`。理由：技术栈冲突（Tailwind vs Element Plus + auto-import）、构建独立、不污染 Tauri 安装包、部署管线不同（官网上公网静态主机，console 进 Tauri bundle / observer-server）。注意区分 `site/`（营销官网源码）与 `crates/observer-server/web/`（console 浏览器版 UI 产物，P10），二者不是一回事。

**目录结构**：

```
prism/
├─ src/                      # console 应用（不动）
├─ site/                     # ← 官网（新建 workspace 成员）
│   ├─ package.json          # vite + vue + tailwind v4 + motion-v + @vueuse/motion + lucide（vue-bits 非 npm 依赖，见下）
│   ├─ vite.config.ts
│   ├─ index.html
│   ├─ THIRD_PARTY_NOTICES.md  # vue-bits 组件来源 + MIT+Commons Clause 版权声明
│   └─ src/
│       ├─ components/       # hero / 棱镜分光动画 / section（含 jsrepo 拉来的 vue-bits 组件源码）
│       ├─ styles/           # 品牌 token 映射进 Tailwind v4 @theme 块
│       ├─ assets/           # logo.svg（静态 SVG）
│       └─ App.vue
├─ pnpm-workspace.yaml       # 加 "site"
└─ package.json              # 加 dev:site / build:site 脚本
```

**技术栈**（vue-bits 已核实：仓库 `DavidHDev/vue-bits`，4.3k stars，活跃维护，2026-07-27 核对）：

- **框架**：Vue 3.5 + Vite 7（与主项目 Vue 版本一致，便于复用类型 / 片段）
- **样式**：Tailwind CSS **v4**（`@tailwindcss/vite`，CSS-first 配置，无 `tailwind.config.ts`，用 CSS 内 `@theme` 块定义 token；品牌 token 从 [theme.css](../../src/styles/theme.css) 的 `--amber`/`--teal` 等映射进来）
- **图标**：lucide（`lucide-vue-next`），统一线性图标风格
- **动效**：motion-v（Motion 的 Vue 版）+ `@vueuse/motion`（vue-bits 依赖，需带上）
- **vue-bits**：**非 npm 依赖**。npm 上的 `vue-bits` 是 2020 年的 Vue 2 老包（peerDep `vue ^2.6.11`），与本项目无关，勿装错。`DavidHDev/vue-bits` 是 jsrepo 管理的 copy-paste 组件集（`private: true`、不发布 npm），用 `jsrepo` CLI 按需把 beam / animated gradient / 网格 / 文字动效等组件源码拉进 `site/src/components/`（shadcn 式）。挑组件时确认不带 `primevue` 依赖（vue-bits 文档站自身用 primevue，但单个动效组件通常不带）
- **Logo 动效**：静态 SVG 先行（走 `/frontend-design` 出稿），hero 内用 motion-v 给 SVG 套入场 / 循环动效；vue-bits 用于背景分光流，不用于 Logo 本体
- **部署**：`pnpm --filter site build` 出静态产物 -> Cloudflare Pages / Vercel / GitHub Pages，绑域名
- **许可证合规**：vue-bits 是 **MIT + Commons Clause**（非纯 MIT）--允许作为 website 一部分使用（含商业目的），但禁止再分发组件本身。鉴/Prism 开源 `site/` 时，对 copy 来的 vue-bits 组件保留版权声明（`Copyright (c) 2025 David Haz`）并汇总到 `THIRD_PARTY_NOTICES.md`，避免被误认为自有代码

## 7. 决策记录

1. **开源策略**：✅ 全开源。官网「快速开始」放 repo 链接 + CLI 安装命令，CTA 指向 GitHub。
