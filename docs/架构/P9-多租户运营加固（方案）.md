# P9 多租户与运营加固（最佳实践方案）

本文档是 [P9-多租户与运营加固](../阶段路径/P9-多租户与运营加固.md) 的可落地实施方案：给出数据结构、函数签名、配置格式与测试计划，使开发者能据此直接开工。决策依据见 P9 doc 的「设计决策」表，本文不重复论证。

## 1. 总览

P9 在 P8 抽出的 observer-server / observer-storage 之上加一层「租户上下文 + 运营策略」，**不动采集层、不动 bundle 契约**。五块改动：

```
observer-storage  : validate_session_id + gzip 落盘/读 + redact(Rust) + enforce_retention
observer-server   : tenant registry + key 解析 + appId 越权拒 + 配额 + 后台清扫 + 限流 + gzip 传输 + import 前 redact
console SettingsUI: 保留策略配置接后端
```

非目标：admin API/UI、OAuth/SSO、浏览器版 console、DOM 文本 redact、bundle 内嵌 gzip、tiny_http 线程化。均留后续。

## 2. 租户模型

### 2.1 配置文件 `tenants.json`

放在 data_dir 同级（或 `--tenants-file` 指定），启动读取，支持 `SIGHUP`/文件 mtime 轮询热加载：

```json
[
  {
    "key": "sk_acme_prod",
    "tenantId": "acme",
    "appIds": ["shop-web", "shop-admin"],
    "quotaBytes": 5368709120,
    "retention": { "maxAgeDays": 30, "maxSessions": 5000 },
    "redact": {
      "stripNetworkBody": true,
      "stripNetworkHeaders": true,
      "scrubbers": ["Bearer\\s+[\\w.-]+", "[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+"]
    },
    "rateLimit": { "maxRpm": 600 }
  }
]
```

- 字段全部可选除 `key`/`tenantId`；缺省 = 不限。
- `appIds` 空数组 = 不校验 appId（向后兼容老 key）。
- console 内嵌模式（[ingest.rs](../../src-tauri/src/ingest.rs)）：**不传 tenants.json**，`ObserverServer` 走隐式单租户（见 2.4）。

### 2.2 数据结构（observer-server 新增 `src/tenant.rs`）

### 2.3 目录布局与 session.json

```
recordings/<tenantId>/<sessionId>/{session.json, windows.jsonl, segments/*.jsonl[.gz], annotations.jsonl}
```

- `session.json` 新增 `tenantId` 字段（ingest 时由 server 写入，不接受客户端值）。
- 存储层函数仍吃 `&Path`，多租户 = 调用方传 `root.join(tenant_id)`。`list_sessions`/`read_session`/`import_bundle` 零改动。

### 2.4 隐式单租户（console 内嵌）

`ServerConfig` 加可选字段：

```rust
pub struct ServerConfig {
    pub bind: String,
    pub data_dir: PathBuf,
    pub auth_token: String,           // 单租户兼容（P8）
    pub enabled: bool,
    pub tenants_file: Option<PathBuf>, // None = 隐式单租户
}
```

- `tenants_file = None`：沿用 P8 行为，`auth_token` 鉴权，root = `data_dir`，扁平目录。**console 内嵌零改动**。
- `tenants_file = Some(p)`：走多租户，`auth_token` 被忽略，root = `data_dir.join(tenant_id)`。

## 3. 安全加固（步骤 1，最先落）

### 3.1 session ID 校验

新增 [observer-storage/src/bundle.rs](../../crates/observer-storage/src/bundle.rs)：

```rust
/// session ID 合法性：纯数字（与 unique_id 生成器一致）。
/// read API 的 /sessions/:id 直接 root.join(id)，未校验可被 ../ 跨租户逃逸。
pub fn validate_session_id(id: &str) -> bool {
    !id.is_empty() && id.bytes().all(|b| b.is_ascii_digit())
}
```

[handle_read_route](../../crates/observer-server/src/routes.rs) 所有取 `id` 的分支开头加：

```rust
("GET", ["sessions", id]) => {
    if !validate_session_id(id) { return Err((400, "invalid session id".into())); }
    let dir = root.join(id);
    // ...
}
```

覆盖 `["sessions", id]`、`["sessions", id, "annotations"]`、`["sessions", id, "export"]`、`DELETE ["sessions", id]`、`PATCH ["sessions", id]`。ingest 侧 `session_id` 同样校验。

### 3.2 appId 越权校验

[handle_route](../../crates/observer-server/src/routes.rs) 的 `/ingest/session` 与 `/ingest/events` 拿到 tenant 上下文后：

```rust
// /ingest/session：meta.appId 必须在 tenant.app_ids 内（app_ids 非空时）
if !tenant.app_ids.is_empty() {
    let app = meta.get("appId").and_then(|v| v.as_str()).unwrap_or("");
    if !tenant.app_ids.iter().any(|a| a == app) {
        return Err((403, format!("appId {app} 不在授权集合")));
    }
}
meta["tenantId"] = json!(tenant.tenant_id); // server 写入，不信客户端
```

`/ingest/events` 需先读 `session.json` 拿 `appId`/`tenantId` 校验归属一致（防用 A 会话 id 往 B tenant 写）。为避免每次读盘，可 cache session->tenant 映射（会话结束即清）。

## 4. gzip（步骤 2，独立高价值）

### 4.1 落盘

[observer-storage/src/storage.rs](../../crates/observer-storage/src/storage.rs) 加 gzip 选项，依赖 `flate2`：

```rust
use flate2::write::GzEncoder;
use flate2::Compression;

pub struct WriteOpts { pub gzip: bool }

/// 追加事件到 segment 文件。gzip=true 写 segments/<id>.jsonl.gz（每行一个事件 gzip 流）。
pub fn append_events_file_with(
    dir: &Path, segment_id: &str, events: &[Value], opts: &WriteOpts,
) -> Result<(), String> {
    let seg_dir = dir.join("segments");
    fs::create_dir_all(&seg_dir).map_err(|e| e.to_string())?;
    let name = if opts.gzip { format!("{}.jsonl.gz", segment_id) } else { format!("{}.jsonl", segment_id) };
    // gzip 模式：追加打开 .gz，逐事件 writeln 进 encoder
    // 非 gzip：沿用现有 O_APPEND
}
```

> 注意：gzip 追加需用 `GzEncoder` 包 `BufWriter<File(append)>`，逐事件 flush 一行。或换格式：每次写一个独立 gzip member（concatenate），读侧 `GzDecoder` 流式读全部。推荐后者（每个事件一个 member，追加安全 + 读侧简单）。

读路径（[bundle.rs](../../crates/observer-storage/src/bundle.rs) 的 `read_session`/`build_export_bundle`/`list_sessions`）按扩展名分派：

```rust
fn read_jsonl_file(path: &Path) -> Vec<Value> {
    let raw = if path.extension().and_then(|e| e.to_str()) == Some("gz") {
        decompress_to_string(path) // GzDecoder
    } else {
        fs::read_to_string(path).unwrap_or_default()
    };
    raw.lines().filter(|l| !l.is_empty()).map(|l| serde_json::from_str(l).ok()).collect()
}
```

向后兼容：旧 `.jsonl` 零迁移，按扩展名透明读。

### 4.2 传输

[respond](../../crates/observer-server/src/lib.rs) 对大 body（>1KB）gzip 后加 `Content-Encoding: gzip` 头。tiny_http 不自动处理，需手动压。小 body 不压（得不偿失）。请求侧 `Accept-Encoding` 探测（可省，自托管客户端默认支持）。

### 4.3 bundle 不动

`build_export_bundle` 输出仍为纯 JSON（version 1）。bundle 体积问题留给 B2 的流式序列化，不在 P9 范围。

## 5. 配额 + 保留（步骤 4）

### 5.1 配额：tenant 级大小缓存

```rust
// observer-server/src/quota.rs
pub struct TenantUsage {
    bytes: std::sync::atomic::AtomicU64,
    // 启动时扫 recordings/<tenantId>/ 累加初始化
}

impl TenantUsage {
    pub fn init(root: &Path, tenant_id: &str) -> Self { /* 递归 du */ }
    pub fn add(&self, n: u64) { self.bytes.fetch_add(n, Relaxed); }
    pub fn bytes(&self) -> u64 { self.bytes.load(Relaxed) }
}
```

- `/ingest/events` 写盘成功后 `usage.add(written_bytes)`；写前 `if usage.bytes() + est > tenant.quota_bytes { return 429 }`。
- 估算：events JSON 序列化字节数（gzip 后更小，按原始估偏保守，安全）。
- 精度：不强求实时准确，周期性（每 N 分钟）重扫校正漂移。

### 5.2 保留：后台清扫线程

```rust
// observer-storage/src/retention.rs
pub fn enforce_retention(root: &Path, policy: &RetentionPolicy) -> Result<usize, String> {
    let mut sessions = list_sessions(root);
    let now = now_ms();
    let mut removed = 0;
    // 超龄：endedAt < now - max_age_days
    if let Some(days) = policy.max_age_days {
        let cutoff = now - (days as i64) * 86_400_000;
        sessions.retain(|s| {
            let keep = s["endedAt"].as_i64().map_or(true, |t| t >= cutoff);
            if !keep { let _ = fs::remove_dir_all(root.join(s["id"].as_str().unwrap())); removed += 1; }
            keep
        });
    }
    // 超量：按 startedAt 倒序保留 max_sessions
    if let Some(max) = policy.max_sessions {
        sessions.sort_by(|a, b| b["startedAt"].as_i64().cmp(&a["startedAt"].as_i64()));
        for s in sessions.iter().skip(max as usize) {
            let _ = fs::remove_dir_all(root.join(s["id"].as_str().unwrap()));
            removed += 1;
        }
    }
    Ok(removed)
}
```

observer-server 启动一个后台线程，每 10 分钟遍历各 tenant 调 `enforce_retention`。console 内嵌模式（无 tenant）也调（用 [SettingsView](../../src/views/SettingsView.vue) 的 `retainMax`），复用同一函数。

### 5.3 SettingsView 接后端

`retainMax` 之前是纯前端占位。P9 加 `get_retention`/`set_retention` 命令（console 本地）+ `GET/PUT /retention`（云端），落到 `ingest-config.json` 或 tenant 配置。UI 变更实施时走 `/frontend-design`。

## 7. 限流（步骤 6）

串行模型下退化为 per-tenant 计数：

```rust
// observer-server/src/rate_limit.rs
use std::collections::HashMap;
use std::sync::Mutex;
use std::time::{Duration, Instant};

pub struct RateLimiter {
    windows: Mutex<HashMap<String, (Instant, u32)>>, // tenant -> (窗口起点, 计数)
    window: Duration, // 60s
}

impl RateLimiter {
    pub fn check(&self, tenant_id: &str, max_rpm: u32) -> bool {
        let mut m = self.windows.lock().unwrap();
        let now = Instant::now();
        let entry = m.entry(tenant_id.into()).or_insert((now, 0));
        if now.duration_since(entry.0) > self.window {
            *entry = (now, 1);
            true
        } else if entry.1 >= max_rpm {
            false
        } else {
            entry.1 += 1;
            true
        }
    }
}
```

- `handle_request` 鉴权拿到 tenant 后、分发前调 `check`，超限返 429 + `Retry-After`。
- console 内嵌（单租户）默认不限；可选配。
- 线程化（D5 非目标）时换 token bucket + per-tenant mutex。

## 8. handle_request 改造后流程

```rust
fn handle_request(state: &Arc<Mutex<Inner>>, mut req: Request) -> Result<(), String> {
    // CORS preflight ...
    let config = state.lock().clone_config();
    if !config.enabled { return 503; }

    // 解析 tenant：多租户走 registry.lookup(bearer)；单租户透传
    let tenant = resolve_tenant(&config, &req)?; // 401 if bad key

    // 限流（多租户）
    if let Some(t) = &tenant {
        if let Some(rpm) = t.rate_limit.max_rpm {
            if !state.rate_limiter.check(&t.tenant_id, rpm) { return 429; }
        }
    }

    // root 解析：多租户 = data_dir/tenant_id；单租户 = data_dir
    let root = tenant_root(&config.data_dir, &tenant);

    let body = json_body(&mut req).unwrap_or(Value::Null);

    if url.starts_with("/ingest/") {
        // appId 越权校验 + session_id 校验 + 配额检查
        handle_route(&root, &mut open, &url, body, &tenant)?
    } else if url.starts_with("/sessions") {
        // session_id 校验 + import 前 redact
        handle_read_route(&root, &method, &url, body, &tenant)?
    }
}
```

## 9. 测试计划

### 9.1 observer-storage 单测（`cargo test`）

- `validate_session_id`：纯数字通过，含 `..`/`/`/字母 被拒。
- gzip 落盘 + 读：写 `.jsonl.gz` 后 `read_session` 透明解压还原；旧 `.jsonl` 仍可读（混合目录）。
- `redact_bundle`：network body/headers 被删；scrubbers 命中替换 `[REDACTED]`；dropConsole 丢事件；DOM 事件不动。
- `enforce_retention`：超龄/超量会话被删，保留集正确；空 policy 不删。
- 现有 9 个测试保持通过。

### 9.2 observer-server 单测 + 端到端

- 多租户隔离：两 key 各 ingest，互不可见（list/read 返 404）。
- 路径穿越：`GET /sessions/../other-tenant/x` 返 400。
- appId 越权：key 授权 `[a,b]`，上报 `appId=c` 返 403。
- 配额：写满后 `/ingest/events` 返 429。
- 保留：构造过期会话，触发 `enforce_retention` 后消失。
- redact：import 含 network body 的 bundle，落盘后 body 为空。
- 限流：连续请求超 `maxRpm` 后返 429。
- 单租户回归：无 `tenants_file` 时 P8 行为不变（11 项冒烟全过）。

### 9.3 console 回归

- 默认本地模式：录制 -> 回放 -> 导出 -> 导入 全链路不变。
- 切云端 + 多租户 key：list/read 正常；越权 appId 上报被云端拒。

## 10. 风险与开放问题

| # | 问题 | 处理 |
|---|---|---|
| R1 | `session.json` 读盘校验 appId 归属（`/ingest/events`）成本 | cache session->tenant 映射，会话结束清 |
| R2 | gzip 追加语义 | 每事件一个 gzip member（concatenate），读侧流式 `GzDecoder`；避免「追加到已关闭 gzip 流」陷阱 |
| R3 | 配额估算偏差 | 周期重扫校正；偏保守（按未压字节数估）安全 |
| R4 | tenant 配置热加载一致性 | `Arc<RwLock>` 读多写少；reload 时不中断在途请求 |
| R5 | redact regex TS/Rust 语义差异 | 共享 fixture bundle 双端比对测试（B5 待补的 fixture 顺带补） |
| R6 | 后台清扫线程与 tiny_http 生命周期 | server 句柄 drop 时停清扫线程；console 进程退出自然回收 |
| R7 | admin API 缺失 | `tenants.json` 手编起步；admin API 留 P9.5 或 P10 |

## 12. 不做什么（scope 纪律）

- admin API / 多租户管理 UI（`tenants.json` 手编起步）。
- OAuth / SSO / 复杂多租户组织模型。
- bundle 内嵌 gzip / bundle version 2。
- tiny_http 线程化（串行够用）。
- DOM 文本节点 redact（与 TS 侧一致，留后续）。
- 浏览器版 web console（留 P10）。
