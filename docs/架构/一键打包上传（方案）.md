# 一键打包上传（最佳实践方案）

> P24「外部观测应用一键打包上传至观测端」的可落地方案。决策依据见 [P24-一键打包上传](../阶段路径/P24-一键打包上传.md) 的「设计决策」表与 [一键打包上传 决策](../决策/一键打包上传.md)，本文不重复论证。

## 1. 总览 ★

打包端（`build_export_bundle` / `buildBundle`）、契约（prism-session v1）、接收端（`POST /sessions/import` + Bearer）全部复用现成资产，本 P 只补「最后一公里」：前端上传执行器 + 批量编排 + 请求侧 gzip + demo 一键入口。改动块图：

```
packages/observer-sdk    : +upload.ts（uploadBundle / probeRequestGzip）+ OfflineController.upload + 导出
packages/observer-tauri  : +TauriController.uploadSessions（串行+onProgress+逐会话回执）+ 类型导出
crates/observer-server   : read_body 请求侧 gzip 解压 + /whoami 增 requestGzip 标记 + 测试
examples/tauri-demo      : +「上传到观测端」按钮（复用 endpoint/token 配置 UI，Local 模式解锁配置）
src/（console 前端）     : 「导入」交互改造——拖放 + 多选 + 逐文件进度/回执（视觉走 /frontend-design）
site/docs + 架构文档     : web.md / concepts.md / tauri.md / deploy.md 落差收敛 + 新章节
```

非目标：自动/定时上传（P16 non-goal 维持）、服务端幂等键、脱敏、分块/断点续传、多会话容器格式、上传登记表、服务端体积上限、console 接收端新命令/端点、插件与 observer-storage 任何改动。

## 3. 设计决策 ★

| # | 决策点 | 选择 | 理由 |
|---|---|---|---|
| D1 | 上传执行器放哪层 | SDK 纯函数 `uploadBundle`，web/tauri 两路复用 | 网络能力本住前端 JS（HttpSink 先例）；不给插件引入首个 HTTP client |
| D2 | 上传端点 | 复用 `POST /sessions/import` | 接收端零改动、契约零变更；console 内嵌与自托管同一份代码 |
| D3 | 脱敏 | upload API 不带 redact 参数 | 用户拍板「不用脱敏」；B4「上云前必经 scrub」张力以本 P 决策收口，责任归接收端策略 + 宿主 `export(redactOpts)` opt-in 组合 |
| D4 | 幂等 | 无（接受重复） | 用户拍板；import 换新 id 语义已被测试锁定，不动 |
| D5 | gzip 能力协商 | `/whoami` 响应加 `requestGzip: true` + SDK 默认不压缩 | 老 server 对 gzip body 静默 400，必须协商；与 P9 排除项「bundle 内嵌 gzip」不同层（传输层 vs 载荷层），文档显式区隔 |
| D6 | 批量形态 | 串行逐会话循环，无批量端点/容器格式 | server 单线程串行；bundle 契约单会话粒度是事实约束；对齐 console batchDelete 范式 |
| D7 | uploadSessions 模式限定 | 仅 Local（与 listSessions 同款 throw 文案） | Remote 数据已在观测端，上传无意义；ensure_local 语义一致 |
| D8 | 超大会话兜底形态 | 失败错误文案引导 + 手册指引 `exportSessionToFile`；不做上传前体积预检 | 预检需整串序列化（172MB 级成本翻倍），v1 不划算 |
| D9 | 上传目标配置 | API 参数化（`{endpoint, token?}`），不进 `RecordOfflineOptions`/`ObserverConfig`，宿主自管存储 | 录制与上传目标正交；不污染 Local 模式「endpoint/token 被忽略」既有语义；demo localStorage 为先例 |
| D10 | uploadSessions ids 缺省 | 缺省 = `listSessions()` 全部 | 一键语义；接受重复故重复点击安全 |
| D11 | console 导入交互形态 | 拖放 + 多选 + 逐文件状态机（等待/导入中/成功/失败）+ 聚合反馈；视觉先走 `/frontend-design` skill | 用户拍板「导入录制文件新增 UX 交互」；现状单文件 + 一条消息零反馈；沿用 P10 设计语言（琥珀信号主色/平铺布局/等宽时间码） |

`OfflineController` 扩展（index.ts）：

```ts

// 不 redact（D3）；RecordOfflineOptions 不动（D9）
```

### 4.2 observer-tauri：uploadSessions

```ts
export interface UploadProgress { sessionId: string; index: number; total: number }
export interface UploadSessionResult { sessionId: string; ok: boolean; remoteId?: string; error?: string }
export interface UploadSessionsOptions {
  endpoint: string;
  token?: string;
  gzip?: "auto" | boolean;   // "auto"（默认）= 批量前 probeRequestGzip 一次，全批生效
  onProgress?: (p: UploadProgress) => void;
  onResult?: (r: UploadSessionResult) => void;
}
// TauriController 新增（仅 Local，!local 时 throw，文案对齐 listSessions）：
uploadSessions(ids: string[] | undefined, opts: UploadSessionsOptions): Promise<UploadSessionResult[]>
// ids 缺省 = await this.listSessions() 全部 id；串行 for-await：
//   exportSession(id) → uploadBundle(bundle, opts) → onResult({ok, remoteId})
// 单会话失败记 {ok:false, error} 不中断（catch 继续）；onProgress 在每会话开始时回调
```

### 4.3 server：请求侧 gzip + 协商标记

- `read_body`（lib.rs）：请求头 `Content-Encoding: gzip` 时走 `GzDecoder`（flate2 已有依赖）读入 → `String::from_utf8` 失败返回解析失败（现有 400 路径）；无该头时行为不变（老客户端零影响）。
- `/whoami`（lib.rs:413-431）：单租户与多租户两个响应分支均加 `"requestGzip": true`。仅 additive 字段。
- cargo test（server）：① gzip 压缩的 bundle POST /sessions/import roundtrip；② 无 Content-Encoding 行为不变（回归）；③ whoami 含 requestGzip。console 内嵌（ingest.rs）零改动同源生效。

### 4.4 tauri-demo：一键上传按钮

- index.html 加「上传到观测端」按钮 + 回执区块；main.ts 调 `controller.uploadSessions(undefined, { endpoint, token, onProgress, onResult })`，逐会话渲染 `ok/remoteId/error`。
- Local 模式解锁配置：去掉 `LOCAL ? { endpoint: "", token: "" }` 清空分支（main.ts:42 一带），Local 下 endpoint/token 语义 = 上传目标；**不实现** `?token=` URL 参数注入（决策·边界）。

### 4.5 console 导入交互（D11）

现状：SessionList「导入」→ `pickBundleFile()`（单文件）→ 单次 `importBundleContent/Path` → `ElMessage.success("已导入会话")`，172MB 级 bundle 导入期间无任何状态反馈。

改造（视觉方案经 `/frontend-design` skill 流程后定稿，此处为交互骨架）：

- **拖放**：会话页头部/列表区接受 `.json` bundle 文件拖放（`dragover/drop` + 视觉高亮态），替代或并列文件对话框入口。
- **多选**：`pickBundleFile(multiple?: boolean)` 扩展——Tauri 侧 dialog `multiple: true` 返回 `{path}[]`；浏览器侧 `<input multiple>` + FileReader 循环。缺省单选，调用方显式开多选。
- **逐文件状态机**：串行 for-await（对齐 batchDelete 范式；import 每文件一次 invoke/POST，172MB 级秒级耗时需要可见状态）：每文件 `等待 → 导入中 → 成功(新 sessionId)/失败(error)`，UI 呈现为导入过程面板（进行中计数 + 逐文件行 + 聚合「成功 n / 失败 m」）。
- **回执**：成功行可含「回放」跳转（复用行内回放按钮的路由形态）；完成后 `refresh()` 刷新列表。
- **不新增 Tauri 命令/端点**：数据面全部复用 `importBundlePath`/`importBundleContent`。

## 7. 不做什么（scope 纪律）★

- **自动/定时上传** —— P16 non-goal 维持；手动单次是本 P 全部触发形态
- **服务端幂等键 / upsert / 客户端去重比对** —— 用户已拍板接受重复
- **脱敏（默认或参数面）** —— upload API 不带 redact 参数
- **分块 / 断点续传 / 流式上传端点** —— gzip 后仍不可行再立项
- **多会话容器格式 / 批量导入端点** —— 契约单会话粒度是事实约束
- **上传登记表 / session.json 上传状态字段 / 上传后自动清理** —— 无 ack 基础，留未来
- **服务端体积上限（bundle-规范.md:73）** —— 正交缺口，记档不在本 P 做
- **console 接收端命令/端点改动** —— import_session/import_session_path 数据面复用；console 仅动导入交互 UI（D11）
- **插件 / observer-storage 任何改动** —— 契约层与落盘层零改动
