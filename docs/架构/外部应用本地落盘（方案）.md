# 外部应用本地落盘（最佳实践方案）

> P16 可落地方案。决策依据见 [P16-外部应用本地落盘.md](../阶段路径/P16-外部应用本地落盘.md) 的「设计决策」表与 [外部应用本地落盘 决策](../决策/外部应用本地落盘.md)，本文不重复论证。

## 1. 总览 ★

把 `tauri-plugin-observer` 的 Local 模式从「console 专属」泛化为「任意宿主 opt-in」：Rust 侧补会话元数据（source/appId）可配置 + 两个只读导出命令；JS 侧 `TauriSink` 下沉进 `@prism-obs/observer-tauri`、`initTauri()` 加 `mode`；闭环走既有 bundle 导出 -> console 导入。改动块图：

```
plugins/tauri-plugin-observer : ObserverConfig +source/appId；新增 list_sessions/export_session + 权限三件套
packages/observer-tauri       : TauriSink 下沉（新 sink.ts）；initTauri 加 mode；controller +listSessions/exportSession
src/composables/sink.ts       : TauriSink 改 re-export（删本地实现）
crates/observer-storage       : 零改动（list_sessions/build_export_bundle 已就绪）
examples/tauri-demo           : 固化双模式开关（VITE_OBSERVER_MODE，D10）+ 端到端验证（不发版）
docs 多处                     : CLAUDE.md（决策#2/插件段/进度表）、被观测侧、bundle-规范、P5 注记、手册、npm-crates发布
```

非目标：外部应用内嵌回放 UI；自动上传/自动导出；插件写命令面（delete/annotations）。见 §7。

## 3. 设计决策 ★

| # | 决策点 | 选择 | 理由 |
|---|---|---|---|
| D1 | JS 模式注入形态 | `initTauri` 加 `mode?: "remote"\|"local"`（默认 remote） | 与 Rust `Mode` 对称；一入口两模式避免双驱动漂移 |
| D2 | TauriSink 归属 | `@prism-obs/observer-tauri` 导出 | observer-sdk 保持零 Tauri 依赖；observer-tauri 本就依赖 `@tauri-apps/api` |
| D3 | source/appId 注入点 | `ObserverConfig`（Rust 装配时声明） | 元数据属部署拓扑；不改命令签名，autoStart/非 autoStart 单一来源 |
| D4 | Local 会话元数据取值 | `source` 默认 `"self"`；外部建议 `"tauri"` + `appId` | console 零变化；`appId` camelCase 与 web ingest 会话字段对齐，console 来源色直接生效 |
| D5 | 导出形态 | `export_session` 返回 bundle JSON（Value），插件不落文件 | 落盘目标由宿主决定（fs/dialog 插件各异）；bundle 契约 version 1 复用 |
| D6 | list/export 仅 Local | Remote 下返回 `Err` | Remote 数据不在本机，命令无意义，防误用 |
| D7 | console 侧去重 | `sink.ts` re-export 包内 `TauriSink` | 消双实现漂移；console 不发布 npm 无依赖方向顾虑 |

## 4. 技术方案

### 4.1 Rust：ObserverConfig + 只读命令

```rust
// config.rs —— 新增两字段（serde camelCase 与现有一致）
pub struct ObserverConfig {
    pub mode: Mode,
    pub main_label: String,
    pub skip_focus_prefix: String,
    #[serde(default = "default_source")]
    pub source: String,                // 默认 "self"
    #[serde(default)]
    pub app_id: Option<String>,        // JSON 键 "appId"，None 不写键
}

// commands.rs —— start_session Local 分支（现 L37-41 硬编码 "self"）改为：
std::fs::write(dir.join("session.json"), json!({
    "id": id,
    "source": config.source,
    "appId": config.app_id,       // D9：None 时省键不写 null，与 console 现网 session.json 形态一致
    "startedAt": started_at,
}).to_string())

// stop_session（现 L131）同步：从 state 读 config.source/app_id 写回，勿再硬编码 "self"。
```

新增只读命令（薄封装 storage，模式限定 + 防路径穿越）：

```rust
#[tauri::command]
pub fn list_sessions<R: Runtime>(app: AppHandle<R>, state: State<'_, SessionState>) -> Result<Vec<Value>, String> {
    ensure_local(state)?;   // mode != Local -> Err("list_sessions is Local-mode only")
    Ok(observer_storage::list_sessions(&recordings_root(&app)))
}

#[tauri::command]
pub fn export_session<R: Runtime>(app: AppHandle<R>, state: State<'_, SessionState>, session_id: String) -> Result<Value, String> {
    ensure_local(state)?;
    observer_storage::validate_session_id(&session_id)?;   // 防路径穿越（P7 既有防护）
    observer_storage::build_export_bundle(&recordings_root(&app).join(&session_id))
}
```

权限三件套：`build.rs` `COMMANDS` 追加 → 重新生成 `allow-list-sessions`/`allow-export-session` → `permissions/default.toml` 追加两行。宿主 capabilities 已含 `observer:default` 即自动获得。

### 4.2 JS：TauriSink 下沉 + initTauri mode

`packages/observer-tauri/src/sink.ts`：移植 console 六方法（`startSession`/`beginSegment`/`appendEvents`/`appendLifecycle`(no-op)/`endSession`/`isRecordingActive`），import `@tauri-apps/api/core` 的 `invoke`。

`InitTauriOptions`：

```ts
export interface InitTauriOptions {
  /** 部署模式。默认 "remote"（HTTP 上报 console）；"local" = 插件 Rust 直接落盘到本应用 appDataDir。 */
  mode?: "remote" | "local";
  appId: string;        // local 模式下 JS 侧仅作 meta 标识；本地 session.json 的 source/appId 由宿主 Rust ObserverConfig 决定
  endpoint?: string;    // remote 必填；local 忽略
  token?: string;       // 同上
  /* env/release/autoStart/signals/recording/meta 原样保留 */
}
```

行为分叉表（impl 时逐条对照，remote 列必须逐行为等价）：

| 行为 | remote（现状不变） | local |
|---|---|---|
| Sink | `HttpSink` | `TauriSink`（包内导出，另 re-export 供直接使用） |
| autoStart | `sink.startSession()` + `bind_session` | `invoke("plugin:observer\|start_session")`（Rust 自广播，**无需 bind**） |
| 收到 `recording-session{active:true}` | 读 `payload.sessionId` 注入 `useSessionId` | 忽略 payload 会话字段（`id` 生命周期在 Rust 侧），直接 `startSegment()` |
| 兜底（晚挂载窗口） | `is_recording_active` + `session_id` | 仅 `is_recording_active` -> `startSegment()`（Local 的 `session_id` 恒 null，**勿调**） |
| `segment:stop` | 停段 + `appendLifecycle(hidden)` | 停段即可（Rust 已落 hidden；`TauriSink.appendLifecycle` 本为 no-op，双保险） |
| `observer-lifecycle` 监听 | 转发 focus 上报 | 不注册（Local 模式 Rust 直接落盘、不 emit） |
| `controller.stop()`（主窗） | `endSession()`（HTTP） | `endSession()` -> `stop_session`（Rust 写 endedAt） |

controller 扩展：

```ts
export interface TauriController {
  stop(): Promise<void>;
  /** 仅 local 模式可用（remote 抛错）：列出本应用本地会话。 */
  listSessions(): Promise<unknown[]>;
  /** 仅 local 模式可用：导出 prism-session bundle（JSON），宿主自行落盘/传输。 */
  exportSession(sessionId: string): Promise<unknown>;
}
```

console [src/composables/sink.ts](../../src/composables/sink.ts)：删 `TauriSink` 本地实现，改 `export { TauriSink } from "@prism-obs/observer-tauri"`；`HttpSink`/`IndexedDBSink` 等既有 re-export 不变。`useRecorder` 无感。

### 4.3 闭环：导出 -> console 导入

1. 外部应用（Local 模式）录制照常落自己的 `appDataDir/recordings/`。
2. 宿主在任意时机 `controller.exportSession(id)` 拿 bundle JSON -> 宿主自行保存（tauri fs/dialog 插件）或传输。
3. console「导入」（P6 `import_session`/`import_session_path`）零改动；会话来源色按 `session.json` 的 `source`/`appId` 生效（`"tauri"` -> `--lane-5`）。
4. [bundle-规范.md](bundle-规范.md)「三条投递路径」扩为四条：新增「外部 Tauri 应用 Local 落盘 -> 导出 -> console 导入」。

## 7. 不做什么（scope 纪律）★

- **外部应用内嵌回放 UI** —— 回放/诊断闭环归 console（锁定决策 #3），bundle 导出即闭环出口。
- **插件写命令面**（`delete_session`/`save_annotations`/`update_session_meta`）—— 危险操作不外放；宿主自行管理自己的 recordings/ 目录。
- **自动/定时导出钩子** —— 手动 `exportSession()` 起步，真需求出现再议。
- **observer-sdk 任何改动** —— 保持纯 web 零 Tauri 依赖，不动不发版。
