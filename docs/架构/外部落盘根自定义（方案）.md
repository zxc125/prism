# 外部落盘根自定义（最佳实践方案）

> P20 可落地方案：`tauri-plugin-observer` Local 模式落盘根可配置（`ObserverConfig.dir_base`/`dir_name`），外部应用可把会话落盘指到安装目录（Windows NSIS 布局下 `resource_dir()` = 主程序 exe 所在目录）。决策依据见 [P20-外部落盘根自定义.md](../阶段路径/P20-外部落盘根自定义.md) 的「设计决策」表与 [决策/外部落盘根自定义.md](../决策/外部落盘根自定义.md)，本文不重复论证。外部输入：bond-sat 提案（2026-09-17，其仓库 docs/observer-recording/bugs/），本方案在其基础上按源码核实修正 3 处（见 §4.3 注记）。

## 1. 总览 ★

纯增量改造：配置加两字段、存储加一函数、4 处调用点切换、文档同步，patch 面 ≈ 4 个源文件 + 2 份手册 + 2 份仓库文档。改动块图：

非目标：历史数据迁移；任意绝对路径落盘根；JS 侧任何变更；新命令/capabilities；落盘根 UI。

## 3. 设计决策 ★

| # | 决策点 | 选择 | 理由 |
|---|---|---|---|
| D1 | 注入点 | `ObserverConfig`（Rust 装配时声明） | 落盘根属部署拓扑，援引 P16 D3 同一理由 |
| D2 | API 形态 | 新增 `recordings_root_with`，原函数委托保留 | console 13 处调用点签名不可变更（实测，非提案的 7+） |
| D3 | 版本 | **0.4.0 minor**（修正提案的 0.3.1 patch） | 锁定惯例「0.x minor = 兼容新增」（P17 D6 / P18 D7 / npm-crates发布.md） |
| D4 | 解析时机 | 惰性逐次、不缓存进 `Session` | 调用频率极低；免 `Session::new` 签名变更 |
| D5 | serde 形态 | `DirBase` camelCase + `#[default] AppData`；`dir_name` default fn | 与 `ObserverConfig` 既有风格一致；缺省 = 现状 |
| D6 | 迁移策略 | 不迁移；进程期固定根；旧根数据不删仅不可见 | bond-sat 全新接入无存量；console 不切根；文档注明 |
| D7 | 顺手修 | site 手册字段表补齐 P16 漏掉的 `source`/`appId` | 既有文档漂移，随本次补表一并修，zh/en 镜像 |

## 4. 技术方案

### 4.1 config.rs：`DirBase` + 两字段

```rust
/// Local 模式落盘基目录（P20）。
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize, Default)]
#[serde(rename_all = "camelCase")]
pub enum DirBase {
    /// `appDataDir`（默认，与 0.3.x 现状一致）。
    #[default]
    AppData,
    /// 资源目录：Windows NSIS 安装布局下为主程序 exe 所在目录。
    ResourceDir,
}

fn default_dir_name() -> String {
    "recordings".to_string()
}

// ObserverConfig 追加两字段（derive 保持 Debug, Clone, Serialize, Deserialize）：
/// Local 模式落盘基目录，默认 AppData（P20）。
#[serde(default)]
pub dir_base: DirBase,
/// 基目录下的子目录名，默认 "recordings"（P20）。
#[serde(default = "default_dir_name")]
pub dir_name: String,

// 手写 impl Default（:54-64）同步补两行：
// dir_base: DirBase::AppData,
// dir_name: default_dir_name(),
```

### 4.2 storage.rs：`recordings_root_with` + 委托保留

```rust
use crate::config::{DirBase, ObserverConfig};

/// recordings 根目录（按配置解析）：`<dir_base>/<dir_name>`（P20）。
/// 基目录缺失 panic 与原实现语义一致（app_data_dir/resource_dir 缺失属环境异常）。
pub fn recordings_root_with<R: Runtime>(app: &AppHandle<R>, cfg: &ObserverConfig) -> PathBuf {
    let base = match cfg.dir_base {
        DirBase::AppData => app.path().app_data_dir().expect("app data dir"),
        DirBase::ResourceDir => app.path().resource_dir().expect("resource dir"),
    };
    base.join(&cfg.dir_name)
}

/// recordings 根目录：`appDataDir/recordings`（默认配置）。
/// 兼容保留：console 宿主 13 处直接调用，签名不可变更（P20）。
pub fn recordings_root<R: Runtime>(app: &AppHandle<R>) -> PathBuf {
    recordings_root_with(app, &ObserverConfig::default())
}
```

### 4.3 commands.rs：4 处调用点切换

| 调用点 | 现状（已核实） | 改法 |
|---|---|---|
| `start_session` :66 | 锁外调用（第一段锁 :49-63 提取 mode/source/app_id 后已释放） | 第一段锁内 `let cfg = s.config.clone();`，:66 改 `recordings_root_with(&app, &cfg).join(&id)`；:73 写回 `dir` 逻辑不变 |
| `list_sessions` :270-271 | `ensure_local(&state.lock()...config)?` 临时锁后 :271 调根 | 锁内 `let cfg = state.lock()...?.config.clone();` 供 ensure_local 与解析根共用，:271 改 `storage_list_sessions(&recordings_root_with(&app, &cfg))` |
| `export_session` :287-291 | 同 `list_sessions` 模式 | 同上模式 |
| `export_session_to_file` :322-326 | 同上 | 同上模式 |

> **对提案 §3.3 的修正**：提案称 `start_session` :66「已在 `s` 可变借用内，直接传引用」——实际锁已释放，须改为第一段锁内 clone（`ObserverConfig` 已 derive `Clone`）。其余 3 处提案的「复用同一次锁」描述与实际锁结构吻合。四处均在 `ensure_local` 之后，`ResourceDir` 只在 Local 模式实际解析，Remote 行为零变化。
>
> 新增 3 测试（`mod tests` 追加，纯 serde 断言，无需 app 环境）：`observer_config_default_uses_app_data` / `observer_config_serde_backward_compat`（`"{}"` 反序列化得默认值）/ `dir_base_serde_camel_case`（`"resourceDir"` 往返 + 未知值报错）。

## 7. 不做什么（scope 纪律）★

- **历史迁移** —— bond-sat 无存量；console 不切根；文档注明「切根不迁移」。
- **任意绝对路径** —— 限定标准基目录，避免非法路径边界。
- **JS 侧发版** —— `ObserverConfig` 仅 Rust 侧；npm 版本号不动。
- **更多基目录枚举** —— 无需求方；枚举向后兼容，后续按需加值。
- **落盘根 UI** —— 设置页不展示落盘路径，无需求。
