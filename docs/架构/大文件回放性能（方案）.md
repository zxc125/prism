# 大文件回放性能（方案）

> P19 的可落地方案。决策依据见 [docs/决策/大文件回放性能.md](../决策/大文件回放性能.md)，本文不重复论证。

## 1. 总览 ★

把「打开即全量、attach 即全建、每次定位即全量重放」三个 O(全量) 打散为按需 + 视口 + 一次，并让长任务不再落在主线程。

```
crates/observer-storage : 新增 read_session_meta（段索引，O(段数)）+ read_segment_json（单段直拼字符串，零 Value 树）
crates/observer-server  : 新增 GET /sessions/:id/meta 与 /sessions/:id/segments/:segId（旧路由保留）
src-tauri               : 新增 read_session_meta / read_segment 两个 async command；read_segment 走 raw IPC
src/composables         : backend.ts 接口 +2（Tauri/HTTP 双实现）；usePlayer.ts 懒建/回收、同步策略、tick 收敛
src/components/player   : Timeline 松手才 seek；DiagnosisPanel 虚拟滚动 + 二分；PlayerShell 加载态/倍速控件
packages/observer-sdk   : （Phase D）recording-profile PRESETS 增 checkoutEveryNms
```

非目标：不改录制产物格式、不改录制默认行为（档位 D 除外）、不做位置精确回放、不做 worker 化、不做二进制事件编码。

## 3. 设计决策 ★

| # | 决策点 | 选择 | 理由（详见决策文档） |
|---|---|---|---|
| D1 | 读路径 | 元信息 + 段索引先到，段按需拉；`read_session` 保留兼容 | 沿用 P7「不过 IPC 大字符串」的尺子 |
| D2 | 段事件传输 | jsonl 直拼 + `tauri::ipc::Response` raw 字节 | 消灭 2.9GB `Value` 树与二次转义 |
| D3 | Replayer 生命周期 | 按需创建 + 回收，删 `pause(0)` | 27 次全量 DOM 重建是打开卡顿主体 |
| D4 | 同步策略 | 废弃播放中阈值纠偏，只在四个时点对齐 | `play(offset)` = 全量重放，纠偏是正反馈 |
| D5 | 方案 A | 正式证伪并回写 skill | 每帧 `pause(offset)` = 每帧全量 cast |
| D6 | seek 交互 | 拖动只预览、松手提交 | 现状每个 pointermove 一次全量重放 |
| D7 | 诊断信号流 | 定高虚拟滚动 + 二分 + 播放中不滚动 | 十万级 DOM + 每 tick O(n) 扫描 |
| D8 | 播放循环 | 活跃集合变化才 diff；播放头 rAF | 每 tick O(labels×segs) 写 style |
| D9 | 录制档位 | `checkoutEveryNms` 按档位暴露，默认值实测后定 | 无 mid-segment 快照 → seek 要重放整段增量 |

## 4. 技术方案

### 4.1 分段读 API

**storage 层**（`observer-storage`，零 tauri 依赖，console 与 server 共用）：

```rust
/// 段索引条目：段元信息，不含段内事件。
/// 首行（Meta）给 width/height/firstTs；尾行给 lastTs——**实施中补的**：
/// 外部应用导出的会话常常既无 endedAt 也无 hidden 事件（实测目标会话 27 shown / 0 hidden），
/// 段尾时间戳是时间轴总时长的唯一来源。
pub struct SegmentIndexEntry {
    pub segment_id: String,
    pub bytes: u64,
    pub width: Option<u32>,
    pub height: Option<u32>,
    pub first_ts: Option<i64>,
    pub last_ts: Option<i64>,
}

/// 元信息 + 段索引。O(段数) 字节，不含任何段内事件。
/// 返回 { session, windows, annotations, segments: [SegmentIndexEntry] }
pub fn read_session_meta(dir: &Path) -> Result<Value, String>;

/// 单段事件直拼为 JSON 数组文本（`[l1,l2,…]`），不做 serde Value 往返。
/// 复用 validate_segment_id 防路径穿越；gz 段先解压到内存再直拼。
pub fn read_segment_json(dir: &Path, segment_id: &str) -> Result<String, String>;

/// 全库诊断信号（type:6）直拼为 JSON 数组文本：只做子串筛选，不 parse 任何事件。
/// 实测信号约占总量 1%，据此让诊断面板首屏就有完整信号流，与按需加载解耦。
pub fn read_session_signals_json(dir: &Path) -> Result<String, String>;
```

要点：
- 段文件首行即 Meta（实测确认），读首行即可拿到 `width/height`——时间轴 bands 与 tile 等比缩放不再依赖段内事件。
- gz 段（P9 `WriteOpts{gzip}`）用 `MultiGzDecoder` 读到第一行即停；直拼路径需先解压全文（gz 无法按行随机访问）。
- 首行缺失/解析失败时 `width/height = None`，回放侧退化为「不缩放」（与今日 origW=0 分支一致）。

**console 命令**：

```rust
#[tauri::command(async)]
async fn read_session_meta(app: AppHandle, id: String) -> Result<Value, String>;

#[tauri::command(async)]
async fn read_segment(app: AppHandle, id: String, segment_id: String)
    -> Result<tauri::ipc::Response, String>;   // UTF-8 字节，JS 侧 TextDecoder + JSON.parse
```

**server 路由**：`GET /sessions/:id/meta`、`GET /sessions/:id/segments/:segmentId`（旧 `GET /sessions/:id` 保留）。

**前端**：

```ts
export interface Backend {
  // …既有不变…
  readSessionMeta(id: string): Promise<SessionMetaPayload>;      // 含段索引
  readSegment(id: string, segmentId: string): Promise<unknown[]>; // 单段事件
}
```

`usePlayer.load()` 改为：先 `readSessionMeta` → 立刻渲染网格骨架 + 时间轴 bands + signals 索引；段事件在 `ensureLoaded(seg)` 时按需拉。

### 4.2 Replayer 生命周期

```ts
type SegState = "cold" | "loading" | "ready";
const PRELOAD_MS = 3000;        // 播放头进入 shownAt-PRELOAD_MS 预取
const EVICT_AFTER_MS = 30_000;  // 非活跃超时回收
const MAX_LIVE_SEGMENTS = 4;    // 同时存活的 Replayer 上限
```

- `ensureLoaded(seg)`：`cold → loading`（调 `readSegment`）→ `ready`（建 Replayer、按需定位）。
- 段**首次活跃**时才 `pause(offset)` 定位一次（删掉 attach 时的 `pause(0)` 全建）。
- 回收：`replayer.destroy()` + `seg.events = null` + `state = "cold"`；当前活跃段与预取窗口内不回收。
- 网格槽位（`.tile-slot/.tile-header`）保持现状——**槽位与 Replayer 解耦**，未加载段显示占位符。

### 4.3 同步策略

删除 `DRIFT_THRESHOLD` 与 tick 内 `play(expect)`。对齐时点收敛为：

| 时点 | 动作 |
|---|---|
| 段激活 | `replayer.pause(absT - firstTs)` 定位一次 |
| 用户 seek | 对所有活跃段 `pause(offset)` |
| 暂停 | 对所有活跃段 `pause(offset)` |
| 切倍速 | `setConfig({speed})`（仅活跃段） |

`play()` 只在段激活时调用一次；此后各段由 rrweb 自己的 timer 驱动，漂移不再被纠正。

### 4.4 seek 交互

```vue
<el-slider :model-value="previewTime" @input="onPreview" @change="onCommit" />
```
- `onPreview(v)`：只更新 `previewTime`（播放头与时间码），不动任何 Replayer。
- `onCommit(v)`：`player.seek(v)`。
- 时间轴色带点击（单次）仍即时 `seek`。

### 4.5 诊断信号流

- **定高虚拟滚动**：行高固定（单行 `nowrap`），`startIdx = floor(scrollTop/rowH)`，渲染 `[startIdx-overscan, startIdx+visible+overscan]`，上下用 spacer 撑高。约 40 行实现，不引三方库。
- **二分查找** `activeSigIdx`（`signals` 已按 `t` 升序）。
- **播放中不 `scrollIntoView`**：仅在用户点击信号/暂停/seek 时对齐；跟随改为直接设 `scrollTop` 计算值。
- **`sigText` 预计算**存入 signal 对象，避免模板内重复 `JSON.stringify`。

### 4.6 播放循环

- `syncVisibility` 改为：先算活跃集合，与上次比较，仅在变化时更新受影响槽位。
- 播放头推进由 `setInterval(50)` 改 `requestAnimationFrame`。
- `applyLayout` 保持「仅在 mainLabel/sideCount 变化时写 grid 模板」。

### 4.7 录制档位（Phase D，可裁剪）

`recording-profile.ts` 的 `PRESETS.balanced` 增 `checkoutEveryNms?: number`（经 `resolveRecordOptions` 透传给 rrweb `record()`）。默认值由 Phase D 的体积实测决定；`full` 档保持零 diff（不设该字段）。

## 6. 分阶段实施 ★

| Phase | 内容 | 产出 | 依赖 |
|---|---|---|---|
| A | 交互与同步止血：4.3 同步策略 + 4.4 seek + 4.5 信号流 + 4.6 循环收敛 | 纯前端改动；172MB 会话「播放/拖动/倍速」症状消除 | 无 |
| B | 读路径分段化：4.1（storage + command + server 路由 + Backend） | 元信息先到 + 段按需拉 + raw IPC；打开不再搬运 180MB | 无（与 A 文件不同，可并行） |
| C | Replayer 生命周期：4.2 | 27 段 → 首屏 1-2 段；attach 卡顿消失 | B |
| D | 录制档位：4.7（先实测体积增幅再定默认值） | `PRESETS` 新字段 + 实测报告 | 无 |
| E | 回归 + 文档 + skill 回写 | 测试流程 + P19 文档 + skill 修正 | A/B/C/D |

每 Phase 结束独立验收（同一 172MB 会话 + 一个小会话对照），不一次性大爆炸。

## 7. 不做什么（scope 纪律）★

- **不做二进制事件编码**（protobuf/msgpack）——先用直拼 + raw IPC 吃掉主要浪费。
- **不做 Worker 化**——rrweb Replayer 依赖 DOM。
- **不做位置精确回放（原方案 C）**——与性能无关，独立候选。
- **不改 bundle 契约 / Sink 接口 / 交错事件模型**。
- **不改录制默认档位**（full 档零 diff 是 P14 的锁定语义）。
- **不做 `inlineStylesheet` 关闭**——牺牲回放保真度。
- **不做 server 端读路径的整体重构**——只加两条路由。
