# 官网文档站与 VitePress 改造（方案评审稿）

本文档回应一个能力诉求，给出最佳实践方案供评审：

**给官网 `site/` 新增「用户手册」**，覆盖 Web SDK 使用、Tauri Plugin 使用、私有化部署详细教程三类长文档内容，并决定承载这些内容（以及未来 API reference / changelog）的技术载体。

> 阶段定位见 [P13-官网文档站](../阶段路径/P13-官网文档站.md)；品牌与官网现状见 [官网（方案）](../品牌/官网（方案）.md) 与 P11 / P12。

---

## 1. 核心论点：营销页与文档必须分载体

现状 [site/](../../site/) 是 12 节单页滚动**营销页**（hero→pain→…→quickstart），纯 CSR、无路由、自建 `useLang` i18n（[useLang.ts](../../site/src/composables/useLang.ts)）。

用户手册是千字级「长正文 + 多段代码 + 表格 + 步骤」，与营销页的「卖」在布局、阅读节奏、信息密度上完全不同。把部署教程塞进同一滚动流是反模式——**营销页负责转化，文档负责教会，二者不能共用一个容器**（Vue / Vite / Tauri / rrweb 官网都是分开的）。

**方案把官网从「纯营销页」演进为「营销页 `/` + 文档站 `/docs/*`」**，并选定 VitePress 作为文档载体，最终统一为单一 VitePress 工程（营销页以自定义 Layout 并入）。

## 2. 三条路径对比与决策

| 路径 | 营销页 | 文档 | 评估 |
|---|---|---|---|
| **A. 全量 VitePress**（选定） | 自定义 Layout（覆盖默认外壳，渲染现有 12 section） | 原生 VitePress | ✅ 单一系统、文档基建免费、营销页顺带获得 SSG/SEO |
| B. VitePress 只做 `/docs`，营销页留现 Vite 应用 | 不动 | VitePress 子工程 | 两套构建/部署/品牌/i18n 永久同步税；放弃 |
| C. 都留现 Vite 应用，md 走 `vite-plugin-md` | 不动 | 自建轻量文档布局 | 局部最优、全局次优：文档一扩张还得再迁，付两遍成本 |

**选 A 的三条理由（权重重排后的结论）：**

1. **营销页当前最大短板恰恰是 CSR**——HTML 到爬虫手里是空壳，SEO / 社交分享卡 / 首屏 FCP 全是弱项。VitePress 的 SSG 把这个长期债务**免费还掉**。这不是「成本」，是「收益」。
2. **B 的两套构建对独立开发者是持续税**：品牌 token（[theme.css](../../site/src/styles/theme.css)）、i18n 文案、组件样式一旦两套系统，永远要同步。A 是一份真理。
3. **文档一定会长过 5 页**：一个有 Web SDK + Tauri 插件 + 私有化 server 三个集成面的产品，迟早加 API reference / 版本说明 / changelog。VitePress 的侧栏 / TOC / 本地搜索 / locale 是为「会长的文档」准备的，C（`vite-plugin-md`）吃到的是局部红利。

**接受的成本（明牌）**：SSG 水合改造（一次性、有边界）、设计 token 映射（一次性）、营销页视觉回归 vigilance（逐页 diff）。

## 3. 信息架构（文档页面树）

```
/docs/
├─ quickstart    3 分钟跑通（总览，新人首站：装 SDK → 起 server → init → 看回放）
├─ concepts      核心概念（session/segment/windows、交错事件 type:6、bundle 契约）—— 前置阅读
├─ web           Web SDK 手册（@prism-obs/observer-sdk）
├─ tauri         Tauri Plugin 手册（tauri-plugin-observer + @prism-obs/observer-tauri）
└─ deploy        私有化部署详细教程（observer-server）⭐
```

左侧栏按上顺序；每页右侧 TOC 由 H2/H3 自动生成。本地搜索用 VitePress 内置 MiniSearch（5 页内本可 YAGNI，但 VitePress 白送，开即用）。

### 三份手册内容要点

**Web SDK**（源自 [index.ts](../../packages/observer-sdk/src/index.ts) + [README](../../packages/observer-sdk/README.md) + [web-demo](../../examples/web-demo/src/main.ts)）：`init()` 实时上报参数表；`recordOffline()` 离线采集 + bundle 导出；诊断信号 `signals: error/console/network` 语义；`redact()` 脱敏（stripNetworkBody/scrubbers）；被观测页需显式设置背景色的注意点；Vue/React 框架入口集成。

**Tauri Plugin**（源自 [plugin README](../../plugins/tauri-plugin-observer/README.md) + [config.rs](../../plugins/tauri-plugin-observer/src/config.rs) + [tauri-demo](../../examples/tauri-demo/src-tauri/src/lib.rs) + [observer-tauri](../../packages/observer-tauri/src/index.ts)）：Local vs Remote 模式；Cargo + npm 安装；Rust 侧 `init_with(Mode::Remote)` + `open_window` label 推导 + `emit_segment_start_if_active`；JS 侧 `initTauri()` 主/子窗口 + `autoStart`；capabilities 授权 `observer:default`；多窗口 close→hide / 复用开新段行为；Remote vs self-obs 差异表。

**私有化部署**（源自 [observer_server.rs](../../crates/observer-server/src/bin/observer_server.rs) + [tenants.example.json](../../crates/observer-server/tenants.example.json)）：三形态选择（桌面 console / 单二进制 / 浏览器化）；单租户 `--bind/--token`；多租户 `tenants.json` 逐字段（key/tenantId/appIds/quotaBytes/retention/redact/rateLimit）；浏览器化 `--web-dir` + `/whoami`；反代 TLS（nginx/caddy 示例）；数据目录与保留；数据卫生（服务端 redact + 限流）；SDK 对接 `init({endpoint,token})` + 离线 bundle `/sessions/import`；升级备份。

> 文档 ≠ 仓库内部方案文档（[被观测侧（采集）.md](./被观测侧（采集）.md) / [离线导出与云端部署（方案）.md](./离线导出与云端部署（方案）.md)）：前者面向用户的「怎么做」操作手册（去架构黑话、给可跑代码），后者是面向开发者的设计记录。手册可引用不照搬；代码片段以 `examples/` 为唯一可信源，避免与实现漂移。

## 4. 技术方案

### 4.1 VitePress + Tailwind v4

VitePress 内核即 Vite + Vue 3，现有依赖（`@vueuse/motion` / `motion-v` / `ogl` / `lucide-vue-next`）均可继续用。Tailwind v4 经 `@tailwindcss/vite` 插件挂进 VitePress 的 `vite` 配置（成熟组合，有现成实践）。

工程结构（Phase 1 后）：

```
site/
  .vitepress/
    config.ts          # nav / sidebar / locales / base（复用现 BASE_URL 逻辑）
    theme/
      index.ts         # extend default theme + 注册营销组件为全局组件 + Tailwind 入口
      style.css        # --vp-* token 映射到 site 的 --color-* + @import tailwindcss
      Layout.vue       # 路由分发：/ -> MarketingLayout；/docs/* -> 默认文档壳
      MarketingLayout.vue   # Phase 2：渲染现有 12 section，隐藏 sidebar/header
  index.md             # Phase 2：营销页（自定义 layout）
  docs/                # zh-CN 默认语种（根）
    quickstart.md  web.md  tauri.md  deploy.md  concepts.md
  en/docs/             # en locale（分阶段补，缺 key 回退 zh，沿用 useLang 既有策略）
  src/                 # 现有营销页组件/composables/styles（Phase 2 搬进全局注册）
```

### 4.2 设计 token 对齐

文档页用 VitePress 默认壳，需把 [theme.css](../../site/src/styles/theme.css) 的 `--color-ink/amber/teal/bone/oxblood...`（P10「现代科技感」）映射到 `--vp-*`（`--vp-c-brand-1/2/3`、`--vp-button-*`、`--vp-bg` 等），否则文档页是「VitePress 默认绿」、营销页是「琥珀冷青」，视觉割裂。一次性映射，写入 `.vitepress/theme/style.css`。

### 4.3 i18n 策略：双轨 → 收敛

- **文档正文**：VitePress 原生 locale 目录（`docs/` zh + `en/docs/`），md 按语种分文件，diff 友好。
- **营销页短文案**：Phase 1 暂保留现 `useLang` + JSON 字典（`t("hero.title")` 体系），Phase 2 并入 VitePress 时评估是否也迁到 locale（或保留 useLang 仅修 SSG）。短文案用 JSON、长正文用 md 是社区共识分界。
- **语言切换器**：复用 [SiteNav](../../site/src/components/SiteNav.vue) 的 `.lang-toggle`，对接 VitePress 的 `themeConfig.locale`。

## 5. 营销页处理（Phase 2）

营销页 12 个 section 组件（CSS/结构）**基本不动**，原样搬进 `.vitepress/theme/` 作全局组件，由 `MarketingLayout.vue` 在 `/` 路由渲染并隐藏文档壳（sidebar/header）。真正的工作是 SSG 适配（见 §6）。

## 6. 边界问题清单

| # | 边界问题 | 影响 | 处理 |
|---|---|---|---|
| B1 | **SSG 水合（最大成本）** | 高 | 现 17 组件中 8 个直碰浏览器全局。[useLang.ts](../../site/src/composables/useLang.ts) 模块顶层 `useLocalStorage` + 顶层 `document.documentElement.lang=`（L16/L64）import 即执行，build 期炸 → 重写为惰性化 + onMounted 包裹；[Aurora.vue](../../site/src/components/Aurora.vue) WebGL（`new Renderer` 在 onMounted L150）→ `<ClientOnly>`；[Reveal.vue](../../site/src/components/Reveal.vue) IntersectionObserver → ClientOnly/守卫；Hero/Diagnosis/MultiWindow/Compare 的 `window.`/`matchMedia`/`navigator` 逐个审。 |
| B2 | **token 割裂** | 中 | 见 §4.2，一次性 `--vp-*` 映射。 |
| B3 | **i18n 双轨** | 中 | 见 §4.3，Phase 2 收敛。 |
| B4 | **og / SEO 静态头** | 中 | VitePress 构建期生成静态 HTML，反而修复了 P12「og 卡仅运行时 patch」的局限；`<html lang>` + title + description 可按 locale 构建期注入。需重做 og 卡（现有 [og-image.svg](../../site/public/og-image.svg) 迁入 VitePress public）。 |
| B5 | **部署产物合并** | 中 | Phase 1 过渡期 `/`（旧 Vite 应用）与 `/docs`（VitePress）共存：要么 VitePress 接管整个 `site/` 构建、营销页暂用一个占位路由，要么短暂数日双构建。建议 Phase 1 直接让 VitePress 接管 `site/`，营销页 Phase 1 先「占位重定向到旧产物」或最小迁移，避免长期双构建。 |
| B6 | **营销页视觉回归** | 中 | 逐页 diff 对齐 P11/P12 视觉；[deploy-site.yml](../../.github/workflows/deploy-site.yml) 已有 GH Pages 预览，改 VitePress 构建命令即可。 |
| B7 | **WebGL 性能/多上下文** | 低 | Aurora 一个 ogl 上下文不变；SSG 下仅客户端运行。 |
| B8 | **base / GH Pages 项目页** | 低 | VitePress 原生支持 `base`（`/${repo}/`），复用现 `BASE_URL` 注入逻辑。 |

## 7. 不做什么（scope 纪律）

- **不在 Phase 1 动营销页**。文档先行，营销页 Phase 2 才并入，降低回归风险。
- **不引 vue-i18n 重库**。沿用 P12「轻量 i18n」决策；VitePress locale + 必要处 useLang。
- **不做 Algolia 等外部搜索**。内置 MiniSearch 够用；外部搜索留待流量真有需要。
- **不重写营销页视觉**。组件原样搬迁 + SSG 适配，不改设计语言（CLAUDE.md「视觉设计约定」）。
- **文档首版只覆盖 5 页**。API reference / 版本站 / changelog 留 P13.x 及以后。

## 8. 分阶段建议

| 阶段 | 内容 | 风险 | 回退点 |
|---|---|---|---|
| **Phase 1（文档先行）** | VitePress 接管 `site/`；Tailwind + token 映射；5 篇 md（zh 优先，en 骨架）；`/docs/*` 上线；营销页最小化保持可访问 | 低（绿地） | 若 VitePress 整合不顺，止损 = 一个 `/docs` 子站（等价路径 B），营销页毫发无损 |
| **Phase 2（营销页并入）** | 12 section 搬进 MarketingLayout；SSG 适配（B1）；i18n 收敛；逐页视觉 diff；下线旧构建 | 中（动存量） | Phase 1 已验证工具链，回归面可控 |

**关键去风险**：先让 VitePress 在新文档（绿地）跑通上线，再回头碰营销页（存量）。Phase 1 完成即可独立交付价值（用户手册上线），不必等 Phase 2。
