# 导出流式化与压缩交付（最佳实践方案）

> P25 的可落地方案：`export_session_to_file` 导出链从全量内存组装改为流式写（O(缓冲) 内存），并新增 `compress` opt-in 参数交付 `.json.zst`。决策依据见 [P25-导出流式化与压缩交付.md](../阶段路径/P25-导出流式化与压缩交付.md) 的「设计决策」表与 [决策](../决策/导出流式化与压缩交付.md)，本文不重复论证。下游原始提案：bond-sat-frontend `docs/observer-recording/2026-11-18-诊断数据导出流式化与压缩交付提案.md`（经上游评审修订后承接）。

## 1. 总览 ★

治两件事：① 导出全程内存恒定（现状 3GB 会话峰值 ≈10GB，Value 树 2~3× + 全量 JSON String 副本，换页抖动/OOM——交易客户端事故源）；② 交付物可压缩转发（IM 单文件超限）。改动块图：

```
crates/observer-storage       : bundle.rs 新增 write_export_bundle_streaming（流式写出，压缩无关）+ 单测   → 0.3.0
plugins/tauri-plugin-observer : commands.rs write_bundle_to_file 切流式；compress 参数 + zstd（单版交付）   → 0.7.0
packages/observer-tauri       : exportSessionToFile opts{compress} + JSDoc（M2，TS 签名扩展）             → 0.8.0
site/docs/tauri.md zh/en      : 示例文件名 / bytes 口径 / 闭环句同步（M2）
src/、src-tauri/、observer-server、observer-sdk : 不动（compress 默认 false，console 零感知）
下游 bond-sat-frontend        : 显式传 compress:true + .zst 命名（含无 ts 兜底分支）+ 文案（宿主仓库接线）
```

非目标：console 导入侧解压嗅探、进度回调、`export_session` 本体流式化、同画像内存链路盘点（console 自有导出 / server export / uploadSessions）、网络流式上传端点——见 §「不做什么」。

## 3. 设计决策 ★

| # | 决策点 | 选择 | 理由 |
|---|---|---|---|
| D1 | compress 形态 | 命令可选参数 `compress: Option<bool>`，默认 false | 默认保 console 闭环（锁定决策 #3）；老调用方零改动；宿主显式 opt-in（P24「默认不压缩+显式启用」同范式） |
| D2 | `.zst` 定位 | 交付文件层第三层；解压后 = v1 原文，契约零 bump | 与 P24 传输层 / P9 载荷层显式区隔，照 P24 手法记档 |
| D3 | 流式 API | storage 新 pub `write_export_bundle_streaming(dir, &mut impl Write) -> Result<u64, String>` | 压缩无关、符合既有 API 风格（`Result<_,String>`）；`build_export_bundle` 不动 |
| D4 | segments 输出序 | segmentId 字典序（必做，非可选项） | 现状 BTreeMap 已是字典序；按枚举序直写是回归且 Value 比对测不出 |
| D5 | 行校验 | parse 校验 + 通过后直写原文行；坏行剔除沿用现状 | 低频操作正确性优先；非法行入 bundle = 导入侧整体拒绝的单点故障 |
| D6 | 坏段语义 | 行级失败（残行/坏 JSON/单行非 UTF-8）剔行继续；流级失败（gz 截断等 read 持续 Err，连续 8 次上限）停止续读该段、**保留已解出行**；段键必存在，导出不因坏段失败 | 实现精确化（2026-11-18 impl）：比全量实现「整段剔空」保留更多有效数据——截断 gz 前段好数据不陪葬；两处差异（截断 gz/整文件非 UTF-8）为预期改进，单测与 build 路径对照钉死 |
| D7 | 返回值 | 实际落盘文件字节数，`.metadata().len()` 取 | compress 关=现状口径；开=压缩后字节；宿主 client_log `compress_to` 先例 |
| D8 | 版本切分 | 单版 storage 0.3.0 + plugin 0.7.0 + npm 0.8.0；M1/M2 里程碑由 compress 参数提供（缺省 false = M1 行为） | **论证改判**：M1 快照不存在于版本控制；新参数进 patch 违反惯例；宿主 zstd 已在依赖树——版本切分无增量价值（依据见 P25 论证改判记录） |
| D9 | zstd 依赖位置 | 只进 plugin crate（M2）；storage 压缩无关 | flate2(gzip) 备选记档（O1）；console M2 起被动引入 zstd-sys 已评估接受 |
| D10 | 原子写 | 保持 `.tmp`+rename；失败路径 `remove_file(&tmp)` | 现状 fs::write 失败同样残留，顺手治理 |
| D11 | 内存口径 | 文档措辞 O(缓冲+最长单事件行) | rrweb FullSnapshot 单行可达数十 MB，纯「O(1)」失实 |
| D12 | 闭环处置 | `.zst` 手册注明「`zstd -d` 后即可回导 console」 | 闭环对人工转发一步可达，不声明放弃；console 原生解压留后续 |

## 4. 技术方案

### 4.1 storage：流式 bundle 写出（M1）

```rust
/// 流式导出 bundle 到 writer。骨架手写 JSON，segments 按 segmentId 字典序逐段流式：
/// 明文段 BufRead::read_line 逐行；gz 段（.jsonl.gz）MultiGzDecoder 流式解压（复用
/// read_segment_first_line 已验证的多 member 模式）。每行 trim → 空行跳过 →
/// serde_json::from_str::<Value> 校验 → 通过则直写原文行文本（不重序列化）。
/// 校验失败行剔除（与 read_segment_events 语义一致）；行级失败剔行继续，
/// 流级失败（read 持续 Err）停段保留已解出行（D6 精确语义）。段键必存在。
/// 内存 O(缓冲+最长单事件行)。返回未压缩写出字节数。
pub fn write_export_bundle_streaming(dir: &Path, w: &mut impl Write) -> Result<u64, String>;
```

骨架：`{"format":"prism-session","version":1,"exportedAt":<now>,"session":<小件整读序列化>,"windows":[...],"segments":{` + 逐段 `"id":[lines…]`（逗号分隔、字典序）+ `},"annotations":[...]}`。session/windows/annotations 维持 `serde_json::to_string` 内嵌（KB~MB 级）；缺失文件沿用现状默认空语义（bundle.rs 既有行为）。小件内嵌前须做 JSON 字符串拼接的安全性由「to_string 产物即合法 JSON 字面量」保证，与现状拼装方式同构。

### 4.2 plugin：切流式 + compress 参数（M1 切换 / M2 加参）

```rust
fn write_bundle_to_file(dir: &Path, path: &str, compress: bool) -> Result<u64, String> {
    let tmp = format!("{path}.tmp");
    let res = (|| -> Result<u64, String> {
        let f = File::create(&tmp).map_err(|e| e.to_string())?;
        if compress {   // M2 起；zstd::Encoder 套在流式 writer 外
            let mut enc = zstd::Encoder::new(BufWriter::new(f), 3).map_err(|e| e.to_string())?;
            let n = write_export_bundle_streaming(dir, &mut enc)?;
            let mut inner = enc.finish().map_err(|e| e.to_string())?;
            inner.flush().map_err(|e| e.to_string())?;
            let _ = n;
        } else {
            let mut wtr = BufWriter::new(f);
            write_export_bundle_streaming(dir, &mut wtr)?;
            wtr.flush().map_err(|e| e.to_string())?;
        }
        Ok(std::fs::metadata(&tmp).map_err(|e| e.to_string())?.len())
    })();
    match res {
        Ok(n) => { std::fs::rename(&tmp, path).map_err(|e| e.to_string())?; Ok(n) }
        Err(e) => { let _ = std::fs::remove_file(&tmp); Err(e) }
    }
}

#[tauri::command(async)]
pub async fn export_session_to_file(
    app: AppHandle, session_id: String, path: String,
    compress: Option<bool>,          // M2 新增；老调用方不传 = None = false
) -> Result<u64, String> { /* ensure_local + validate_session_id 门禁不变；spawn_blocking 不变 */ }
```

命令名/门禁/capability（`observer:default` 已含 allow-export-session-to-file）不变，新增可选参数向后兼容。npm 包装层（M2）：

```ts
exportSessionToFile(sessionId: string, path: string, opts?: { compress?: boolean }): Promise<number>
```

### 4.3 测试计划

**storage 单测**（M1）：流式输出（compress 无关层）解压/解码后与 `build_export_bundle` 做 **canonical Value 等价比对**（exportedAt 对齐，commands.rs:472 先例）；混合会话（多 segment、明文+gz 并存）；空行/残行/非法 JSON 行剔除行为一致；CRLF 残行；gz 截断 member → 保留损坏点前已解出行且导出不失败（D6 预期差异，与 build 路径不同）；segments 键序 = segmentId 字典序（字节级断言）；windows/annotations 缺失默认空；消费链用例（截断 gz → 导出 → import → read_session_meta，前缀形态钉死）。

**plugin 单测**：M1 既有 `to_file_matches_export_ignoring_exported_at` / `to_file_overwrites_existing_target` **原样通过**（compress 关路径 = 明文 JSON，read_to_string+from_str 不变）——这是 D8 两里程碑切分的验收锚点；M1 新增失败清理用例（create 后失败无 `.tmp` 残件）；M2 新增 compress=true 用例（zstd 解码后与 export_session bundle Value 比对、返回值 == 文件字节（压缩后）、`.tmp` 中间态、压缩产物非 UTF-8 即非明文 JSON）。

**回归面**：`cargo test`（storage + plugin）+ console `pnpm build`（M2 起编译含 zstd-sys 的插件）+ M2 `pnpm --filter @prism-obs/observer-tauri`（若有 typecheck/build）+ `pnpm build:site`。

**运行时验证（宿主实机，测试流程文档细化）**：GB 级会话导出内存曲线平稳（预期 <200MB）、导出期间交易窗口无感；M1 `.json` 产物可直导 console；M2 `.zst` 体积实测 + `zstd -d` 后回导 console 回放成功；与日志导出（`.log.zst`）并存走查；压缩比实测记录。

## 7. 不做什么（scope 纪律）★

- **console 导入侧解压嗅探** —— 后续 P（可参考 P24 server Content-Encoding 协商先例）；本 P 靠 D12 手册句保闭环可达。
- **`export_session` 本体流式化/改契约** —— 「只加变体不改本体」延续；同画像内存链路盘点另 P。
- **进度回调** —— 宿主自行改 loading 文案先顶；插件侧后续再议。
- **落盘格式 / 录制侧改动** —— 零改动（JSONL / gz member 原样）。
- **网络流式上传端点** —— P24 决策留的「P25+」占位指它，与本 P 不同层，另行立项。
