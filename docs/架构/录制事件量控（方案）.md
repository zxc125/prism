# 录制事件量控（方案）

> P14「录制事件量控（录制档位）」的可落地方案。决策依据见 [docs/决策/录制事件量控.md](../决策/录制事件量控.md)，本文不重复论证。

## 1. 总览 ★

给录制链路加「档位制」量控制：SDK 层新增 `RecordProfile` 预设 + `domBlocks` 免录区，console 设置页落地选择 UI（顺带接线既有未接线的采集信号开关）。存储/传输/回放零改动。

```
packages/observer-sdk   : types.ts 新类型 + segment-recorder.ts record options 组装 + index.ts 对外参数
packages/observer-tauri : InitTauriOptions 透传 recording 配置
src (console)           : useRecorder.ts 读设置传参 + CaptureTab.vue 录制档位 UI + 信号开关接线
site (文档站)           : SDK 手册补 recording 配置章节（随发版）
```

非目标：mutation 级丢帧（P.x）、session.json 档位字段（P.x）、裸 record options 透传（P.x）。

## 3. 设计决策 ★

| # | 决策点 | 选择 | 理由 |
|---|---|---|---|
| D1 | 配置形态 | `RecordProfile` 预设（full/balanced/minimal）+ `domBlocks[]` | 用户要的是选档位，不是学 rrweb sampling 语义；细调留 P.x |
| D2 | 实现落点 | SDK `resolveRecordOptions()` 纯函数组装 record options | 可独立验证；console 与外部 SDK 消费者共享同一份映射 |
| D3 | full 档语义 | 返回 `{}`，与现状零 diff | 已发布包升级无感 |
| D4 | domBlocks 映射 | `domBlocks.join(",")` → rrweb `blockSelector` | rrweb 原生能力：不序列化、不进流、回放显示占位 |
| D5 | 持久化 | localStorage（key 前缀 `prism.capture.*`） | 录制档位是纯前端策略；ingest config（Rust）管 HTTP server，正交不混 |
| D6 | 信号开关接线 | 本 P 顺带接线 CaptureTab 既有四开关（localStorage → `signals`） | 同一落点、同一持久化机制、本就是 P1 占位欠账 |
| D7 | 回放侧 | 零改动 | type:2/4/6 永不丢；Replayer 原生支持流内多次 full snapshot |

## 4. 技术方案

### 4.1 类型与预设（packages/observer-sdk/src/recording-profile.ts）

```ts
// types.ts 新增
export type RecordProfile = "full" | "balanced" | "minimal";
export interface RecordingOptions {
  profile?: RecordProfile;   // 默认 "full"
  domBlocks?: string[];      // CSS selector 列表 → blockSelector（免录区）
}
```

```ts
// recording-profile.ts —— 纯函数，无副作用
import type { recordOptions } from "rrweb"; // 实施时以 rrweb 实际导出类型名为准

const PRESETS: Record<Exclude<RecordProfile, "full">, Partial<recordOptions>> = {
  balanced: {
    sampling: { mousemove: 100, scroll: 200, input: "last", /* slimDOM preset */ },
  },
  minimal: {
    sampling: {
      mousemove: false,                       // 关
      scroll: 500,                            // 类型只收 number，无法全关
      // 对象形式是「禁用表」（false=关、未列出=记录，实施时核实的 rrweb 语义，
      // 与本方案起草时的直觉相反，见 P14 关键陷阱 2）；保留 Click/TouchStart/TouchEnd
      mouseInteraction: { MouseUp: false, MouseDown: false, ContextMenu: false,
        DblClick: false, Focus: false, Blur: false, TouchCancel: false },
      input: "last",
    },
    // slimDOMOptions: preset 剪 script/comment/stylesheet/headFavIcon
  },
};

export function resolveRecordOptions(recording?: RecordingOptions): Partial<recordOptions> {
  if (!recording || (recording.profile ?? "full") === "full") return {};   // D3
  const opts = { ...PRESETS[recording.profile] };
  if (recording.domBlocks?.length) opts.blockSelector = recording.domBlocks.join(",");
  return opts;
}
```

> 参数名/枚举值以 rrweb 2.1.1 实际类型为准（`SamplingStrategy`：`mousemove: boolean|number` / `mouseInteraction: boolean|Record<string,boolean>` / `scroll: number` / `input: 'all'|'last'`；`slimDOMOptions` 含 `preset` 字段），实施时对照 `node_modules/rrweb/dist/rrweb.d.ts` 校准并实测行为。

### 4.3 对外 API 变更（发版 0.2.0）

```ts
// observer-sdk index.ts
init({ appId, endpoint, ..., recording?: RecordingOptions })   // → SegmentRecorder
recordOffline({ ..., recording?: RecordingOptions })
// observer-tauri index.ts
initTauri({ ..., recording?: RecordingOptions })
```

全可选、full 档零 diff → 兼容新增，minor bump。发版遵循 [npm-crates发布](../决策/npm-crates发布.md) 流程，随版更新 site 文档站 SDK 手册。

**三消费路径统一覆盖**：过滤在 webview 内 rrweb `record()` 处生效（`SegmentRecorder` 组装 options），Local/Remote 模式、`TauriSink`/`HttpSink` 均不感知——外部 Tauri 应用只升 npm 两包（`observer-sdk` + `observer-tauri` 0.2.0），**crates.io 的 Rust 插件零改动零发版**（透传点 `packages/observer-tauri/src/index.ts:62` `new SegmentRecorder({ sink, label, signals, recording })`，与 signals 同构）。

**配置语义边界**：外部 Tauri / Web 应用的档位为接入时静态配置（`initTauri`/`init` 参数）；console 远程下发/热更档位不做（需新通道，偏离本地优先）。console 设置页 UI 只管 self-obs 自录。

### 4.4 console 接线

- `useRecorder.ts`：启动时读 localStorage（`prism.capture.profile` / `prism.capture.domBlocks` / `prism.capture.signals`），组装 `SegmentRecorderOptions`。设置变更在下一段生效（不中断当前录制）。
- `CaptureTab.vue` 新增「录制档位」field-group：
  - `el-radio-group`：全量（默认）/ 均衡 / 精简，hint 逐档说明（精简档注明「高频通道静默，画面可能滞后；行情等密集渲染区请配免录区域」）。
  - 「免录区域」`el-input type=textarea`：每行一个 CSS selector，保存时 `document.querySelector` 试解析校验 + 非空校验。
  - 既有「采集信号」四开关（D6）：`v-model` 照旧，另接 localStorage 持久化 → `useRecorder` 读为 `signals`。
- 沿用既有 field-group / field-hint 形态与 theme.css token，无新视图无配色变更。

### 4.5 回放兼容性论证

- 过滤只作用于：高频增量通道（mousemove/scroll/input/interaction 采样）+ domBlocks 区域。**type:2 FullSnapshot / type:4 Meta / type:6 信号永不丢**。
- `usePlayer` 依赖首个 type:4 取视口尺寸 → 不受影响（仍取首个）。
- Replayer 对流内后续 full snapshot 有原生重建路径 → 若未来开 `checkoutEveryNms` 也零改动兼容。
- domBlocks 区域回放显示 rrweb block 占位块（rrweb 原生语义）。
- Timeline/DiagnosisPanel 只消费 bands/errorMarks（来自 type:6）→ 与 mutation 零耦合。

## 7. 不做什么（scope 纪律）★

- **mutation 级丢帧/预算**（emit 层自建过滤）—— 唯一降 mutation 量的通用手段，但引入画面陈旧 + 复杂度；等 domBlocks + minimal 实测不满足再上（P.x）。
- **裸 `RecordTuning` options 透传** —— 等有进阶需求（P.x）。
- **session.json `recordProfile` 字段 + 回放「画面滞后」提示** —— 动 observer-storage → `cargo test`，P.x。
- **服务端/存储侧过滤** —— P9 配额/保留体系已覆盖量问题，不在录制侧重复造。
