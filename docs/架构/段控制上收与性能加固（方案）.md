# 段控制上收与性能加固（最佳实践方案）

> P17（段控制上收 + 录制链路性能加固）的可落地方案。输入：bond/frontend 0909 提案（方案 A 手动档）+ 本仓性能归因。决策依据见 [段控制上收与性能加固.md](../决策/段控制上收与性能加固.md)，本文不重复论证。

## 1. 总览 ★

外部应用实测录制卡顿的三个成本中心与本方案改动块的对应：

| 成本中心 | 归因 | 改动块 |
|---|---|---|
| 空闲期常录 | MutationObserver 回调内同步序列化照跑（rrweb 无 mutation 采样，P14 决策） | ④ controller 手动档 → 宿主门控，空闲期整条管线归零 |
| flush 主线程阻塞 | `append_events` 非 async 命令跑在主线程（macOS = NSApplication 事件循环，阻塞全进程窗口） | ③ `#[tauri::command(async)]` |
| 活跃期 mutation 洪峰 | 虚拟表行挂载/卸载逐帧序列化；`.prism-block` 只罩价格 cell 未罩行容器 | ⑤ 手册量控章（落地在宿主 domBlocks） |

```
packages/observer-sdk        : SegmentRecorder.signal() 公开 + flush 串行化（防并发 invoke 乱序）
packages/observer-tauri      : controller 暴露 startSegment/stopSegment/signal（默认零行为变化）
plugins/tauri-plugin-observer: append_events `#[tauri::command(async)]`（一行 + 保序论证）
examples/tauri-demo          : VITE_OBSERVER_GATING=manual 验收开关（demo 内置最小门控策略）
site/docs (+en 镜像)         : web.md 量控节「高频渲染场景」扩展 + tauri.md controller 新方法 + 版本锚点
docs/决策/npm-crates发布.md   : 包清单版本回写（0.3.0 / 0.4.0 / 0.2.1）
```

非目标：bond/frontend 迁移与 `.prism-block` 扩展（下游消费方动作）；通用门控模块（方案 B）；mutation 预算/丢帧；checkoutEveryNms / inlineStylesheet / 裸 RecordTuning 透传；bundle 契约与 Sink 接口变更。

## 3. 设计决策 ★

| # | 决策点 | 选择 | 理由 |
|---|---|---|---|
| D1 | 信号注入入口 | `SegmentRecorder.signal(plugin, payload)`，type:6 进既有 emit buffer | 锁定决策 #4 交错模型；P14 D8 信号豁免；零新通道 |
| D2 | 保序机制 | JS 层 flush 串行队列（`flushing` 标志），不改 Sink 接口 | Sink 六方法是既有契约（被观测侧（采集）.md）；HttpSink 同步入队本无此问题，串行化对其无害 |
| D3 | async 化形态 | `#[tauri::command(async)]` 属性（签名不变） | 官方语义：非 async 关键字命令默认跑主线程，加 `(async)` 脱离；比 async fn + spawn_blocking 改动最小；权限按命令名授权不受影响 |
| D4 | 手动档 API 面 | `startSegment(): Promise<void>` / `stopSegment(): Promise<void>` / `signal()` | bond 提案方案 A；void 不回传 segmentId（消费方无需求）；幂等复用 `rec.active` 守卫 |
| D5 | 手动停段 lifecycle | 不补 hidden | hidden 语义归 Rust on_window_event / `segment{stop}`；手动停段是策略边界非窗口隐藏 |
| D6 | 版本 | sdk 0.3.0 / tauri 0.4.0（additive minor）+ crates 0.2.1（patch） | 0.x minor = 兼容新增（P14/P16 先例）；async 执行模型变更非 API 变更 |
| D7 | demo 验收开关 | `VITE_OBSERVER_GATING=manual`，缺省常录 | 循 P16 D10 `VITE_OBSERVER_MODE` 单一来源模式；门控纯 JS 侧，Rust 无需同读 |
| D8 | JS 测试设施 | observer-sdk 最小引入 vitest（flush 串行化 + signal 注入 2-3 用例） | 保序是静默回归高危区，A/B 实测无法隔离；仅 sdk 包内不铺开（2026-09-09 拍板） |
| D9 | 自动开段抑制 + 段状态判据 | `InitTauriOptions.gating?: "manual"`（抑制 :142/:197 自动开段）+ controller `readonly active` getter | impl 预检发现的方案 A 隐含缺口：无抑制则会话广播压过宿主门控，demo 验收与 bond 迁移均不成立；语义对齐提案 §3 Plan B 合并表；纯 additive 缺省零 diff；active 属机制非策略（2026-09-09 impl 补记） |

## 4. 技术方案

### 4.1 observer-sdk（0.3.0）：signal() + flush 串行化

```ts
// segment-recorder.ts 新增/改动（示意）
private flushing: Promise<void> | null = null;

/** 注入 type:6 诊断信号进当前段流（幂等于 installSignalHooks 的产出）。段未活跃时丢弃。 */
signal(plugin: SignalPlugin, payload: unknown): void {
  if (this.segmentId == null) return;
  emitSignal((e) => this.buffer.push(e), this.segStart, plugin, payload);
}

async flush(): Promise<void> {
  if (this.flushing || !this.segmentId || this.buffer.length === 0) return;
  const events = this.buffer;
  this.buffer = [];
  const seg = this.segmentId;          // 先抓段 id：stop 期间 in-flight 批仍归属原段
  this.flushing = this.opts.sink
    .appendEvents(seg, events)
    .finally(() => { this.flushing = null; });
  try { await this.flushing; } catch (e) { console.error("[recorder] append_events failed", e); }
}
```

- 串行语义：`flushing` 在途时新到事件留在 buffer，下一轮 tick 或 stop 尾 flush 发送；批次 N+1 的 invoke 发生在批次 N 响应之后 → **到达序 = 发送序**，async 执行模型不再破坏顺序。
- `stop()`：先 `await this.flushing`（在途批归属原段），再执行现有尾 flush；`destroy()` 经 `stop()` 串接，无需单独处理。
- `stopSync()`（HttpSink beforeunload 路径）不入队列——同步入队本就保序，保持原样。
- signal 的 `segStart` 用 `this.segStart`（delay 与 hook 产出一致，回放按时间轴定位）。

### 4.2 observer-tauri（0.4.0）：controller 手动档

```ts
export interface TauriController {
  stop(): Promise<void>;
  /** 段是否活跃（D9）：宿主门控策略判据（如异常兜底只在段未活跃时注入）。 */
  readonly active: boolean;
  listSessions(): Promise<unknown[]>;
  exportSession(sessionId: string): Promise<unknown>;
  /** 手动开段（幂等）：门控策略（交互/判闲/异常兜底）由宿主实现。 */
  startSegment(): Promise<void>;
  /** 手动停段（幂等）：不补 hidden lifecycle（见 D5）。 */
  stopSegment(): Promise<void>;
  /** 信号注入透传（type:6 进当前段流）；段未活跃时丢弃。 */
  signal(plugin: SignalPlugin, payload: unknown): void;
}
```

实现 = 把既有局部闭包挂进返回对象：`startSegment` 即 `:108-112` 闭包；`stopSegment` 包装 `:113-127` 闭包传 `reportHidden=false`；`signal` 透传 `rec.signal`。`gating: "manual"`（D9）抑制 `:142` 广播开段与 `:197` 兜底开段（`segment{start/stop}` 事件与 `:210` autoStart 不受影响）；不配 gating 且不调用新 API 的宿主逐行为等价。

### 4.3 插件（crates 0.2.1）：append_events 脱离主线程

```rust
#[tauri::command(async)]   // 原 #[tauri::command]：仅加属性，签名/权限/注册不变
pub fn append_events(state: State<'_, SessionState>, segment_id: String, events: Vec<Value>) -> Result<(), String>
```

保序论证（三段）：① 同窗口——SDK flush 串行化保证同一 recorder 至多一个在途 invoke，下一批发送在前一批响应之后；② 跨窗口——segmentId 不同即文件不同，`OpenOptions::append` 只保单文件完整性且互不交叉；③ begin/append 无竞态——`rec.start()` await `begin_segment` 之后才启动 rrweb 与 flush 定时器。P14「append 链路零过滤」语义不变。
