# 被观测侧（采集）

本文档描述「前端观测平台」的采集端架构：被观测应用如何嵌入采集器、采集哪些信号、如何上报到分析侧（console）。

## 定位

采集端是被观测 App 内部不可见的「传感器」，职责是：录制 DOM 变更 + 用户交互 + 诊断信号，按交错事件流上报到 console。它**不负责存储、回放、分析**。

平台支持两类被观测端，共享同一事件模型与传输协议，差异仅在「是否有 Rust 侧窗口协调」：

| 采集器 | 宿主 | 多窗口 | 传输 |
|---|---|---|---|
| Web SDK（npm 包） | 任意 web 应用（浏览器） | 单 tab | HTTP -> console |
| Tauri Plugin（`tauri-plugin-observer`） | 任意 Tauri 2 应用 | 多窗口对齐 | HTTP -> console |

## Sink 抽象（平台化第一块骨牌）

当前 `useRecorder` 直接 `invoke("begin_segment")`，与 Tauri 强耦合。平台化要求把「采集逻辑」与「落盘/上报」解耦，抽成 `Sink` 接口：

```ts
interface Sink {
  startSession(meta: SessionMeta): Promise<SessionId>
  beginSegment(label: string): Promise<SegmentId>
  appendEvents(segmentId: string, events: RRWEBEvent[]): void
  appendLifecycle(ev: LifecycleEvent): void
  endSession(): void
}
```

三个实现：

| Sink | 场景 | 行为 |
|---|---|---|
| `TauriSink` | console 自录（self-obs） | `invoke` 现有命令，进程内、零序列化 |
| `HttpSink` | Web SDK / Tauri Plugin 外部观测 | POST 到 console 本地 HTTP server，批量 + 重试 |
| `IndexedDBSink` | 纯 web 独立回放（无 console） | 本地缓存，可后续导出 |

采集逻辑（rrweb `record()` + 信号 hooks）只依赖 `Sink` 接口，三种环境同一份代码。详见 [阶段路径/P3-sink抽象](../阶段路径/P3-sink抽象.md)。

## 交错事件模型

所有信号以 rrweb plugin 事件（`type: 6`）交错进同一条 `emit` 流，与 DOM 事件共享时间轴，无需跨流对齐：

```ts
{ type: 6, timestamp, data: { plugin: 'error' | 'console' | 'network', payload } }
```

- **error**：`{ message, stack, source, lineno, colno, kind: 'onerror' | 'unhandledrejection' }`
  - 来源：`window.onerror` + `window.addEventListener('unhandledrejection')`
- **console**：`{ level: 'log'|'warn'|'error'|'info'|'debug', args: serialized[], trace? }`
  - 来源：monkey-patch `console.*`
- **network**：`{ url, method, status, duration, reqHeaders?, resHeaders?, reqBody?, resBody?, kind: 'fetch'|'xhr' }`
  - 来源：monkey-patch `fetch` + `XMLHttpRequest`
  - body / headers 默认关，按需开（本地优先场景 PII 压力小，留开关）

rrweb `Replayer` 对 `type:6` 事件交给已注册的 replay plugin；不注册则不动 DOM mirror，但仍留在时间轴上。采集侧只管 emit，不关心回放如何消费。详见 [阶段路径/P2-诊断信号采集](../阶段路径/P2-诊断信号采集.md)。

## 会话与段的生命周期

沿用现有多窗口 segment 模型，外部化到被观测侧：

- **Web SDK**：一次页面访问 = 一个 session；单「窗口」（即页面本身）= 一个 segment，跨 SPA 路由连续（rrweb 处理 DOM 连续性），整页刷新 = 新 segment（新全量快照）。
- **Tauri Plugin**：完整复刻现 `lib.rs` 逻辑--Rust 侧管窗口 show/hide/focus，每次 show ~ hide = 一段，segmentId `<label>#<n>`。这是 Web SDK 无法复制的多窗口对齐能力，是平台核心论点。

被观测侧自行分配 segmentId 并上报生命周期事件，console 只存储、不参与分配（避免跨进程协调）。

## 传输协议（HttpSink）

console 本地起 HTTP server（见 [分析侧](./分析侧（平台布局结构、功能）.md)），采集端 POST 上报：

| 路径 | 方法 | 体 | 说明 |
|---|---|---|---|
| `/ingest/session` | POST | `{ appId, env, release, userAgent, viewport, url }` | 建会话，返回 sessionId |
| `/ingest/segment` | POST | `{ sessionId, label, segmentId, startedAt }` | 注册段 |
| `/ingest/events` | POST | `{ sessionId, segmentId, events: [...] }` | 追加事件（批量） |
| `/ingest/lifecycle` | POST | `{ sessionId, type, label, segmentId?, t }` | 窗口生命周期 |
| `/ingest/session/end` | POST | `{ sessionId, endedAt }` | 结束会话 |

约束：
- **批量 + 定时 flush**（默认 1s 或 N 条），降低请求频率。
- **离线队列**：失败入队、指数退避重试；页面 unload 用 `navigator.sendBeacon` 兜底 flush。
- **体积上限**：单批 events 体积超阈值拆包；network body 截断。
- **时间戳**：绝对 epoch ms（与 DOM 事件一致），跨进程靠墙上时钟；同会话单源，无时钟漂移问题。

## 上下文采集

会话开始时采集环境上下文，随 `/ingest/session` 上报：

- `appId` / `env`（dev/staging）/ `release`（版本）
- `userAgent` / `platform` / `viewport` / `devicePixelRatio`
- 初始 `url` / `referrer`
- 用户标识（匿名 id 持久化在 localStorage；登录态可选传入 userId）
