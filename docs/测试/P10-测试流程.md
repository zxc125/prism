# P10 测试流程

> P10（console 2.0 重设计 + 浏览器化）本地测试指南。覆盖七条验收线：app shell + 路由重组、视觉现代科技感、`GET /whoami`、静态文件托管、浏览器端到端、多租户产品化、Tauri 桌面回归（P1-P9 不退化）。

## 准备：构建二进制 + console 产物 + tenants.json

```sh
# 1. 构建 observer-server 二进制（含 P10 静态托管 + /whoami）
cd crates/observer-server
cargo build --bin observer-server

# 2. 构建 console 前端产物并拷到 observer-server/web/
cd ../..
pnpm build:web
# 等价于：vue-tsc --noEmit && vite build && cp -r dist/* crates/observer-server/web/
ls crates/observer-server/web/
# 应看到 index.html + assets/ + vite.svg + tauri.svg
```

准备多租户配置（沿用 P9，加配额便于验证顶栏配额条）：

```sh
mkdir -p /tmp/observer-p10-test
cat > /tmp/observer-p10-test/tenants.json <<'EOF'
[
  {
    "key": "sk_acme",
    "tenantId": "acme",
    "appIds": ["shop-web"],
    "quotaBytes": 1048576,
    "retention": { "maxSessions": 50 },
    "rateLimit": { "maxRpm": 60 }
  },
  {
    "key": "sk_beta",
    "tenantId": "beta",
    "appIds": []
  }
]
EOF
```

启动浏览器化 server（单二进制零安装）：

```sh
cd crates/observer-server
./target/debug/observer-server \
  --bind 127.0.0.1:18299 \
  --data-dir /tmp/observer-p10-test/data \
  --tenants-file /tmp/observer-p10-test/tenants.json \
  --web-dir ./web
```

看到三行日志即就绪：
- `绑定 127.0.0.1:18299`
- `模式: 多租户（tenants.json）`
- `静态托管: ./web（浏览器开 http://<bind>）`

浏览器打开 `http://127.0.0.1:18299` 应见登录页（不是 JSON 404）。

## 场景 B：`GET /whoami`（P10 新端点）

### B1 多租户：返回 tenant 上下文 + 配额余量

```sh
# 无 key -> 401
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:18299/whoami

# 错 key -> 401
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:18299/whoami -H "Authorization: Bearer wrong"

# acme key -> 200 + 完整 tenant 信息
curl -s http://127.0.0.1:18299/whoami -H "Authorization: Bearer sk_acme" | jq .
# 应含：
#   "multiTenant": true
#   "tenantId": "acme"
#   "appIds": ["shop-web"]
#   "quotaBytes": 1048576
#   "usageBytes": 0      <- 还没数据
#   "rateLimit": {"maxRpm": 60}
#   "retention": {"maxSessions": 50}
```

### B2 usageBytes 随写入增长

```sh
# 建会话 + ingest 一批事件
SID=$(curl -s http://127.0.0.1:18299/ingest/session \
  -H "Authorization: Bearer sk_acme" -H "Content-Type: application/json" \
  -d '{"appId":"shop-web","source":"web"}' | jq -r .sessionId)

curl -s http://127.0.0.1:18299/ingest/events \
  -H "Authorization: Bearer sk_acme" -H "Content-Type: application/json" \
  -d "{\"sessionId\":\"$SID\",\"segmentId\":\"web#1\",\"events\":[{\"type\":2,\"timestamp\":1},{\"type\":6,\"timestamp\":2,\"data\":{\"plugin\":\"console\",\"payload\":{\"level\":\"log\",\"args\":[\"hello\"]}}}]}"

# 再查 whoami，usageBytes 应 > 0
curl -s http://127.0.0.1:18299/whoami -H "Authorization: Bearer sk_acme" | jq .usageBytes
```

### B3 单租户：返回 multiTenant:false

```sh
# 单租户启动（无 --tenants-file，用 --token）
./target/debug/observer-server \
  --bind 127.0.0.1:18099 \
  --data-dir /tmp/observer-p10-single \
  --token my-secret-key &

# 对 token -> 200 + {multiTenant:false}
curl -s http://127.0.0.1:18099/whoami -H "Authorization: Bearer my-secret-key"
# {"multiTenant":false}
```

## 场景 C：静态文件服务（P10 浏览器化托管）

### C1 SPA 入口 + MIME 分派

```sh
# GET / -> index.html + text/html
curl -s -D - http://127.0.0.1:18299/ -o /dev/null | grep -i "content-type"
# Content-Type: text/html; charset=utf-8

# GET /assets/<hash>.js -> JS MIME
JS=$(curl -s http://127.0.0.1:18299/ | grep -o '/assets/[^"]*\.js' | head -1)
echo $JS
curl -s -D - "http://127.0.0.1:18299$JS" -o /dev/null | grep -i "content-type"
# Content-Type: application/javascript; charset=utf-8

# GET /assets/<hash>.css -> CSS MIME
CSS=$(curl -s http://127.0.0.1:18299/ | grep -o '/assets/[^"]*\.css' | head -1)
curl -s -D - "http://127.0.0.1:18299$CSS" -o /dev/null | grep -i "content-type"
# Content-Type: text/css; charset=utf-8
```

### C2 SPA fallback（未知路径回 index.html）

```sh
# 浏览器 hash 路由实际 path 永远是 /，但若直链 /unknown-page 也应回 index.html
curl -s http://127.0.0.1:18299/some-unknown-page | grep -o "<title>.*</title>"
# 应返回 index.html 的 title，不是 404
```

### C3 API 路由不被静态拦截

```sh
# /sessions 仍走 API（返回 JSON，不是 index.html）
curl -s http://127.0.0.1:18299/sessions -H "Authorization: Bearer sk_beta"
# []  (JSON 空数组，不是 HTML)

# /whoami 仍走 API
curl -s http://127.0.0.1:18299/whoami -H "Authorization: Bearer sk_beta" | jq .tenantId
# "beta"
```

### C4 路径穿越防护

```sh
# .. 穿越 -> 403 或 404（不应泄露 web_dir 外文件）
curl -s -o /dev/null -w "%{http_code}\n" "http://127.0.0.1:18299/../recordings"
# 403 或 404

# 验证读不到敏感文件
curl -s "http://127.0.0.1:18299/../../etc/passwd" | head -1
# 不应返回 /etc/passwd 内容
```

> tiny_http 可能在客户端层规范化 `../`，server 侧 `resolve_web_path` 的词性检查（拒绝 `..` 段）是第二道防线。自动化测试 `web_path_resolution_safe` 已覆盖。

### C5 不带 --web-dir 时无静态服务（纯 API）

```sh
# 单租户 server（场景 B3 起的，未传 --web-dir）
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:18099/
# 404 + {"error":"unknown route"}  (纯 API 模式)
```

### E2 录制 + 回放（P1-P5 核心）

1. 「实时」页 -> 本机通道点 ● 录制 -> 操作几下窗口 -> ■ 停止
2. 「会话」页 -> 列表出现新会话 -> 点「回放」
3. 进 player（`#/s/<id>`）-> 面包屑「会话 / <id>」-> 回放正常
4. 点面包屑「会话」-> 返回列表

### E3 录制 + player 路由隔离（P10 新增守卫）

验证 in-app player 不会把回放录进会话：

1. 「实时」页开始录制（计时器走动）
2. 不停止录制，切到「会话」-> 点某条会话「回放」进 player
3. URL 变成 `#/s/<id>`，useRecorder 检测到 player 路由 -> 暂停当前段
4. 面包屑返回「会话」-> useRecorder 检测到离开 player -> 会话仍活跃则开新段
5. 停止录制 -> 回放刚才录的会话 -> 不应包含 player 回放画面

> 这修复了 P10 把 player 从独立窗口改 in-app 路由后的潜在回归。守卫在 [useRecorder.ts](../../src/composables/useRecorder.ts) 的 `isPlayerRoute()` + `hashchange` 监听。

### E4 导入/导出/标注/编辑（P6）

- 会话行 ⋯ -> 导出 -> 得 `.rrweb-session.json`
- 顶部「导入」-> 选回这个文件 -> 列表多一条「导入」标记
- player 诊断栏「标注」tab -> 在某时间点输入文本标记 -> 时间轴骨白圆点出现
- 会话行 ⋯ -> 编辑信息 -> 改名 + 标签 -> 保存

### E5 设置分 tab（P10 重构）

- 「连接」tab：本地/云端切换 + endpoint/key（Tauri 可切云端）
- 「采集」tab：信号开关 + HTTP 接收（端口/token/接入点）-- 仅 Tauri 可见
- 「保留」tab：最大会话数 -- 仅 Tauri 可见
- 「关于」tab：版本 + 模式（v2.0.0 · Tauri 桌面）

切到云端模式（填 `http://127.0.0.1:18299` + `sk_acme`）-> 应用 -> 顶栏应变成 `acme` + 配额条。

### E6 多窗口「新窗口打开」（兼容）

`open_window` 仍可用于新窗口场景（如 player 新窗口）。在 console DevTools Console 里：

```js
// Tauri 2：window.__TAURI__.core 不再默认暴露（withGlobalTauri=false），
// 用内部桥 __TAURI_INTERNALS__.invoke（@tauri-apps/api/core 的 invoke 底层即此）
await window.__TAURI_INTERNALS__.invoke('open_window', { route: '/s/1784921067372' })
// 应开新窗口标题「播放器」，加载 /#/s/<id>
```

> 不要用 `window.__TAURI__.core.invoke(...)`--那是 Tauri 1 的全局暴露方式，Tauri 2 默认不挂 `window.__TAURI__`。应用代码走 ES import `import { invoke } from "@tauri-apps/api/core"`，DevTools 里用 `__TAURI_INTERNALS__.invoke` 等价。

旧 `/player/:id` 路由重定向到 `/s/:id`，已开过的旧窗口 hash 仍可用。

> E6 是兼容性检查（`open_window` 命令仍工作），player 主路径已改为 in-app 路由（E2/E3）。新窗口打开是可选场景，非默认交互。

## 排查

| 现象 | 查什么 |
|---|---|
| 浏览器开 `http://host:port` 是 JSON 404 | server 启动没传 `--web-dir`；或路径不存在（启动日志会告警「--web-dir 不存在，跳过静态托管」） |
| 浏览器开页面白屏 | DevTools Console 看报错；`/assets/*` 是否 200（MIME 是否对）；hash 路由是否 `#/` |
| LoginGate 验证失败 | DevTools Network 看 `/whoami` 请求状态；key 是否对；endpoint 末尾有没有多余 `/` |
| 顶栏不显示 tenant | /whoami 返回 `multiTenant:false`（单租户模式）；或 localStorage 配置没生效（设置页「应用」后 resetBackend） |
| 顶栏配额条不动 | usageBytes 只在 `/ingest/events` 写入后增长；建会话本身不记账 |
| 静态文件 MIME 错 | 扩展名不在 `mime_for` 覆盖范围（见 [lib.rs](../../crates/observer-server/src/lib.rs) `mime_for`）；返回 `application/octet-stream` |
| `..` 路径穿越返回 200 | 不应发生；若发生查 `resolve_web_path` 词性检查是否被绕过（自动化测试 `web_path_resolution_safe` 应覆盖） |
| player 录进会话 | useRecorder 的 `isPlayerRoute()` 没生效；hash 是否 `#/s/` 开头；`hashchange` 监听是否注册 |
| Tauri 桌面 Live 页消失 | `isTauri()` 返回 false（不应在桌面发生）；SideNav 的 `visibleNav` 过滤逻辑 |
| 设置页缺「采集」「保留」tab | 浏览器模式（非 Tauri）刻意隐藏；`SettingsView` 的 `tabs` computed 按 `tauri` 过滤 |
| ⌘K 不弹 | 焦点不在 document；或被其他快捷键拦截；CommandPalette 的全局 keydown 监听 |
| DevTools `window.__TAURI__.core` undefined | Tauri 2 默认 `withGlobalTauri=false` 不挂 `window.__TAURI__`；用 `window.__TAURI_INTERNALS__.invoke(cmd, args)` 代替（内部桥，`@tauri-apps/api/core` 的 invoke 底层即此） |
| 视觉退化回旧暖褐 | theme.css 没重新构建；或组件用了硬编码旧色值（应走 `var(--*)` token） |

## 与 P8/P9 测试流程的关系

- **P8 测试流程**：验证自托管 server 可用 + bundle 上传还原 + 本地模式不退化。P10 在此基础上加 `--web-dir` 静态托管 + `/whoami`，P8 场景 B/C/D 仍应通过（单租户 + `--token`）。
- **P9 测试流程**：验证多租户隔离 + 配额/保留 + gzip + redact + 限流。P10 不动 P9 服务端逻辑，全部 45 测试保留 + 新增 7 项 = 52 项。P9 场景 B-F 仍应通过（多租户 + `--tenants-file`，不传 `--web-dir`）。
- **P10 新增**：浏览器端到端（场景 D）+ app shell/视觉/组件化（场景 E/G/H）是 P10 独有，P8/P9 不涉及。

> P10 是 P1-P9 功能积累的产品化收口，不是新功能堆叠。回归保险 = 场景 A（自动化 52 tests）+ 场景 E（Tauri 桌面全功能）。
