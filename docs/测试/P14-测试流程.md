# P14 测试流程

> P14（录制事件量控）本地测试指南。覆盖 6 条验收线：构建链、full 档零回归、minimal/balanced 档行为、免录区域、诊断信号开关接线、下段生效语义；外加前序阶段回归（P2/P3 录制与回放不退化）与 3.1 实测对比步骤。

## 准备：构建 + 配置

```sh
# 验证链（顺序敏感：console 经 workspace dist 消费 SDK，见 P14 关键陷阱 1）
pnpm --filter @prism-obs/observer-sdk typecheck   # SDK 类型
pnpm build:sdk                                    # SDK dist（console 消费它）
pnpm --filter @prism-obs/observer-tauri typecheck # tauri 包类型
pnpm build                                        # console vue-tsc + vite
```

预期：四条全过（vue-tsc 零错误）；`pnpm build` 的 webviewWindow 混合 import / chunk>500kB 两条 warning 为既有现象。

运行时验证：`pnpm tauri dev`，设置页 → 采集 tab。

## 场景 1：full 档零回归（默认行为不变）

**目标**：未配置任何采集设置时，录制行为与 P14 之前逐参一致（D3）。

```sh
rm 以下 localStorage 键（或首次运行即缺省）：
prism.capture.profile / prism.capture.domBlocks / prism.capture.signals
```

**预期**：
- 开始录制 → 操作 → 停止，segment 正常落盘、回放正常
- segment 事件构成与旧会话一致（mousemove 事件存在，间隔 ≈50ms 聚合）

## 场景 2：minimal 档高频通道静默

**目标**：精简档下 mousemove / Focus / Blur / 双击等事件不再进入事件流（验收线 2.3）。

1. 设置页 → 采集 → 档位选「精简」→ 保存
2. 开始录制 → 移动鼠标、切换输入框焦点、双击 → 停止录制
3. 回放该会话，打开 player 路由 `#/s/<id>`，检查 segment jsonl

**预期**：
- `<sessionId>/segments/*.jsonl` 中无 IncrementalSource 为 MouseMove（2 或 1 时的 mousemove 聚合事件）的新增流；无 type:2 中 interaction 为 Focus/Blur/DblClick/ContextMenu 的事件
- Click 事件仍存在（保留项）
- 回放可正常播放，交互操作（点击）有响应

## 场景 3：免录区域（domBlocks）

**目标**：selector 命中元素的 DOM 变更不进事件流，回放显示占位（验收线 D4）。

1. 设置页 → 免录区域填入一个稳定 selector（如 console 会话里录 `.session-card`，或任意页面区块类名）→ 保存（非法 selector 应被拒并提示「无效 CSS selector」）
2. 录制一段（该区块发生可见变化）→ 停止 → 回放

**预期**：
- 该区块在回放中显示为 rrweb 占位块（不随实际 DOM 变化）
- jsonl 中无该子树的 mutation 事件
- 留空保存 = 清空免录区，恢复全量

## 场景 4：诊断信号开关接线（P1 欠账还账）

**目标**：关掉某信号开关后，下一段不再产生对应 type:6 信号（D6）。

1. 设置页 → 采集信号 → 关「Console」→ 保存
2. 开始录制 → 执行任意触发 console.log 的操作（如开关子窗口）→ 停止 → 检查 jsonl

**预期**：
- 无 `type:6, data.plugin:"console"` 事件；error/network 信号不受影响
- 重启 app 后开关状态保持（localStorage 持久化）
- 「请求体」开关 disabled + hint「未实现」

## 场景 5：下段生效语义

**目标**：录制进行中修改档位，当前段不变、下一段生效（configure 语义）。

1. 开始录制（full 档）→ 录 10 秒
2. 设置页切「精简」→ 继续录 10 秒 → 停止 → 停止会话
3. 重新开始会话录一段 → 停止

**预期**：
- 第一会话两段均为 full 行为（mousemove 存在）
- 第二会话段为 minimal 行为（无 mousemove）

## 场景 6：3.1 实测对比（高频页面量控效果）

**目标**：量化 full vs minimal+domBlocks 的数据量差异（方案 O3，产出记入 P14 文档）。

1. 准备高频页面：用 `examples/web-demo` 或自建 ~50 行行情模拟页（`setInterval` 每 100ms 更新表格数字）
2. SDK `init({ appId, endpoint, recording: { profile: "full" } })` 录 2 分钟 → 记录 `/ingest` 落盘 segment 总字节 + 事件行数
3. 改 `recording: { profile: "minimal", domBlocks: ["<行情表 selector>"] }` 同页面录 2 分钟 → 同样统计
4. 对比数据写入 P14 文档实施顺序 3.1 行

**预期**：minimal+domBlocks 下字节数显著下降（量级目标 ≥80%，视页面而定）；若降幅不达标 → 触发方案开放问题「emit 层 mutation 丢帧」的升格讨论。
