# P15 测试流程

> P15（手册小白化）本地测试指南。覆盖 6 条验收线：site 构建 + 死链、quickstart 零基础全链路、API 选项表 vs 真实导出（D8）、deploy 命令真实性、zh/en 结构同步、examples README 声明 vs 源码；外加前序阶段回归（P13 文档站、P14 3.3 手册义务、产品代码零改动核验）。本阶段零产品代码改动，`cargo test` / `pnpm build` 非验收线（见回归段）。

## 准备：构建

```sh
pnpm build:site    # VitePress 构建（含死链校验，config 未设 ignoreDeadLinks）
```

预期：`build complete`，无任何 `Found dead link` 输出。已知陷阱：`<http://…>` 自动链接语法会被 VitePress 当内部链接校验，指向运行期本地服务的 URL 必须写成行内代码（P15「关键陷阱」段）。

## 场景 1：构建 + 死链

**目标**：10 个手册页 + 营销页构建通过，内链/锚点零死链。

```sh
pnpm build:site 2>&1 | grep -i "dead\|complete"
```

**预期**：仅 `build complete`，无 dead link。**regress 实测（2026-09-08）**：通过（修复 2 处 `<http://localhost:1422>` 死链后）。

## 场景 2：quickstart 零基础全链路（手动，需桌面环境）

**目标**：零基础读者按 [quickstart](../../site/docs/quickstart.md) 逐步操作可独立跑通（验收口径 = 全链路无歧义步骤）。

```sh
git clone https://github.com/zxc125/prism.git && cd prism
pnpm install
pnpm tauri dev          # 第 1 步：console；验证：主窗口出现；设置页记 127.0.0.1:1421
pnpm dev:web-demo       # 第 2 步：被测示例；验证：http://localhost:1422 徽标「采集中」绿
# 第 3 步：console 会话浏览器出现 source=web / appId=web-demo 会话，点入可回放
```

**预期**：每一步都有手册明示的 ✅ 验证点可对照；故障排查表覆盖「连接失败 / 列表为空 / 端口占用 / Rust 缺失」四类。

> 注：本批 /regress 做了代码级一致性核验（端口 1422/1421、script 名、徽标文案、URL 参数均与源码逐项比对一致），**全链路 live run 未在本批执行**（需桌面 GUI），留作发版前手动场景。

## 场景 3：API 选项表 vs 真实导出（D8 契约比对）

**目标**：手册所有 API 签名/选项/默认值与 SDK 真实导出逐项一致。

| 手册内容 | 对照源 |
| --- | --- |

## 场景 4：deploy 命令真实性

**目标**：deploy.md（zh/en）没有任何「照做必失败」的命令。

```sh
cargo install --path crates/observer-server --locked 2>&1 | tail -1   # 或 cargo build -p observer-server
observer-server --help    # ⚠️ 不是 --version：bin 只处理 --help/-h，未知 flag 静默落默认值
```

**预期**：`--bind/--data-dir/--token/--tenants-file/--web-dir` 五个 flag 与 `crates/observer-server/src/bin/observer_server.rs` 一致；`OBSERVER_BIND/OBSERVER_DATA_DIR/OBSERVER_TOKEN` 环境变量存在；`GET /whoami`、`POST /sessions/import` 路由存在；tenants.json 字段与 `TenantConfig` camelCase 契约一致。**regress 实测**：首轮 `--version` 为不存在的 flag（subagent 实测其会静默启动 server 并阻塞），已改 `--help`。
