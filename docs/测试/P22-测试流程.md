# P22 测试流程

> P22（会话用户归属与会话级启停）本地测试指南。覆盖 5 条验收线：宿主 meta 注入（单测）· Local 会话带 user 落盘→stop 封口→导出/导入闭环 · Remote 双模会话级启停（幂等收口 + D6a 重绑 + 竞态实测）· console 自录元信息 stop 保留 · 文档/版本；外加前序阶段回归（P16/P17/P18/P19/P7 不退化）。

## 准备：构建 + 配置

```sh
# npm 两包（sdk 改 types + HttpSink 封口缓解；tauri 改 controller）
pnpm --filter @prism-obs/observer-sdk typecheck && pnpm --filter @prism-obs/observer-sdk test && pnpm --filter @prism-obs/observer-sdk build
pnpm --filter @prism-obs/observer-tauri typecheck && pnpm --filter @prism-obs/observer-tauri build

# 插件（meta 注入 + stop 写路径）
cargo test --manifest-path plugins/tauri-plugin-observer/Cargo.toml

# 手册
pnpm build:site
```

无新增 capabilities/权限/命令——命令面不变（`start_session` 仅加 `meta: Option<Value>`，缺省 None 存量零 diff）。

## 场景 1：宿主 meta 注入（Rust 单测）

**目标**：`merged_meta` 合并语义 + D3 保留键保护 + 非 object 防呆的自动化断言。

```sh
cargo test --manifest-path plugins/tauri-plugin-observer/Cargo.toml
```

**预期**：13 passed; 0 failed（12 既有 − 1 删除 + 3 新增；删除的 `stop_overwrite_keeps_app_id` 防护对象随整文件重建消失，改由 merge 结构性保证）：
- `merged_meta_merges_user`——`user` 并入且基础键（id/source/appId/startedAt）齐全
- `merged_meta_base_keys_win`——宿主塞 id/startedAt/source/appId 假值全部被基础键压住，非保留键照常并入
- `merged_meta_rejects_non_object`——字符串/数组/数字报 Err；`None` 与 `null` 等价（原样返回 base）

## 场景 2：Local 会话带 user 落盘 → stop 封口 → 导出/导入闭环

**目标**：P22 主链路（bond-sat 对应路径）端到端：登录区间划会话 + user 全链存活。

1. `examples/tauri-demo` 临时接线（`VITE_OBSERVER_MODE=local`）：主窗口不传 `autoStart`，登录回调处 `await ctrl.startSession({ user: { id: "u1", name: "阿真" } })`，登出处 `await ctrl.stopSession()`
2. 启动 → 登录 → 录一段（开/关子窗口）→ 登出
3. 检查 `<落盘根>/<sessionId>/session.json`
4. `ctrl.listSessions()` 按 user 过滤 + `ctrl.exportSessionToFile(id, path)` 导出 → console 会话页「导入」→ 回放 + 诊断信号

**预期**：
- session.json 含 `"user": { "id": "u1", "name": "阿真" }` 与 `"endedAt"`；`id`/`source`/`appId`/`startedAt` 与注入值不冲突（保留键保护）
- 重复登录/登出多轮：每轮新 sessionId、各自带 user（D2：stop 只补 endedAt，不冲 start 期字段）
- 导出 bundle 的 `session.user` 存活；console 导入回放正常（读路径裸 Value 透传）
- 验证完成后**还原 tauri-demo 临时改动**（examples 零改动是本阶段红线）

## 场景 3：Remote 双模会话级启停（含幂等收口竞态实测——/regress 重点）

**目标**：controller 会话级 API 双模语义 + D6a 第二会话重绑 + /regress 发现的 end 竞态实测把关。

1. tauri-demo `VITE_OBSERVER_MODE=remote` 接 console（同场景 1 接线）
2. **幂等收口**：autoStart 开会话后直接再调 `ctrl.startSession({ user })`（已活跃重叠）→ 观察旧会话封口与新会话建立
3. **D6a**：第二次 `startSession` 后继续录段 → 检查段事件归属
4. `ctrl.stopSession()` 收尾

**预期**：
- 旧会话 `/ingest/session/end` 打到**旧 sessionId**（缓解后常见序必然）；新会话 meta 带 user、段事件进新会话（server 无 404、无串会话）
- 第二会话的 bind 广播被子窗口正常消费（`sessionBound` 已重置），段事件不落在已 end 的旧会话
- ⚠️ 若出现新会话被提前写 endedAt / 段事件消失 → 竞态残留窗口复现（两类：监听 handler 晚于 create 响应启动；或 `rec.stop()` 达量网络批慢于 create 往返），按 P 文档陷阱段升格处理（三方向：end 显式 sid 参数化 / controller 串行化 / endedSid 集合）

## 场景 4：console 自录元信息 stop 保留（顺带修复）

**目标**：D2 改造对 console 的正外溢——`update_session_meta` 写入的 name/note/tags 不再被 stop 冲掉。

1. `pnpm tauri dev` → 开始录制 → 会话行「编辑」写入 name/note/tags → 停止录制
2. 刷新会话列表 / 直接看 `appDataDir/recordings/<sessionId>/session.json`

**预期**：
- 停止后 name/note/tags 仍在（改造前会被整文件重建冲掉）
- `endedAt` 正常回填，录制/回放无其他差异

## 场景 5：文档与版本锚点

**目标**：手册与实现一致。

- `site/docs/tauri.md` / `site/en/docs/tauri.md`：「会话级启停与用户归属（P22）」节方法表/示例/保留键/幂等广播窗口注记与实现相符；版本锚点 = observer-tauri **0.6.x**（sdk 0.4.x）/ plugin **0.5.x**
- `docs/架构/bundle-规范.md`：session 示例含 `user` 可选行，`BUNDLE_VERSION` 仍为 1（加可选字段不 bump）
