## 排障速查（2026-11-04 实测踩坑）

| 症状 | 根因 | 解法 |
|---|---|---|
| 上传目标打到 `127.0.0.1:18099` | demo 旧配置提示把自托管示例端口放显眼位（已修） | 「连接配置」改 console 实际地址并应用重载 |
| `Could not connect to the server`（1421 无人监听） | **console 没启动**——demo 与 console 是两个进程，起 demo 不等于起 console | 仓库根另起 `pnpm tauri dev`；Live 页源机架应显「监听 127.0.0.1:1421」 |
| `Request header field Content-Encoding is not allowed by Access-Control-Allow-Headers` | server CORS 预检白名单缺 `Content-Encoding`（P24 实施遗漏，已修 + 集成测试钉死） | 重启 console 使新 server 生效 |
| webview 侧对 `127.0.0.1` 连接异常 / 预检行为怪异 | macOS 15+ WebKit 对 IP 直连 loopback 的限制 | endpoint 用 `http://localhost:1421`（WebKit 对 localhost 有豁免）；**手册推荐写法即 localhost** |

## 场景 1：server 请求侧 gzip + 能力协商

**目标**：压缩 bundle 可被 import；无 Content-Encoding 行为不变；whoami 暴露能力标记。

```sh
# 能力标记（单租户）
curl -s http://127.0.0.1:1421/whoami
# 压缩上传（任一 bundle 文件）
gzip -kc session.prism-session.json | curl -s -X POST http://127.0.0.1:1421/sessions/import \
  -H "Content-Encoding: gzip" -H "Content-Type: application/json" --data-binary @-
# 明文上传（回归：无 CE 头，行为与历史一致）
curl -s -X POST http://127.0.0.1:1421/sessions/import -H "Content-Type: application/json" -d @session.prism-session.json
```

**预期**：
- `/whoami` 响应含 `"requestGzip": true`，且既有键（multiTenant 等）形状不变
- 压缩与明文均返回 `200 {"sessionId": "<新id>"}`，console 会话列表出现带「导入」标记的会话
- 损坏 gzip body（`Content-Encoding: gzip` + 非 gzip 字节）返回 400 `{"error": "缺少 format..."}`，不 panic

## 场景 2：demo 一键上传 + 接受重复语义

**目标**：uploadSessions 全链路（导出→POST→回执）与重复导入语义（决策 D4）。

1. tauri-demo（Local）录一段 → 「连接配置」填 `http://127.0.0.1:1421` 应用重载
2. 点「上传到观测端（Local）」

**预期**：
- 进度头「上传中 k/N」→ 逐会话 `✓ <id> → 已导入（观测端 id <new>）`，完成行「导入完成：成功 N · 失败 0（重复点击会在观测端产生重复会话）」
- console 列表出现 N 个「导入」标记会话，回放正常（多窗口对齐、诊断信号在）
- **再点一次上传**：console 再出现 N 个重复会话（预期行为，不做去重）
- token 配置：console 设置页给 server 配 token 后，demo 不带 token 上传应 401，配置 token 后成功

## 场景 3：SDK upload API（web 路径）

**目标**：`OfflineController.upload` / `uploadBundle` / `probeRequestGzip` 可独立使用。

在被观测页面控制台（web-demo 或任意接 SDK 页面）：

```js
const ctrl = await recordOffline({ appId: "t" }); /* 录几秒后 */
await ctrl.upload(undefined, { endpoint: "http://127.0.0.1:1421" });
```

**预期**：console 列表出现 `source:"web"` 导入会话；对无 `requestGzip` 标记的地址传 `gzip:true` 会被服务端 400（「缺少 format」）——按手册须先 `probeRequestGzip` 协商。

## 场景 4：console 导入交互（拖放 + 多选 + 回执）

**目标**：导入通道托盘（逐文件状态机）与拖放接收框（D11）。

1. 会话页把 1–3 个 `.json` bundle 文件拖进窗口
2. 多选路径：点「导入」按钮，文件对话框多选

**预期**：
- 拖入悬停时全视图变暗 + 琥珀虚线接收框「松开以导入会话 bundle」；松开后进入队列
- 「导入通道」托盘逐行：等待（暗灰 LED）→ 导入中（琥珀脉冲）→ 已导入（冷青 + 观测端 id + 「回放」按钮）或 失败（牛血 + 错误文案）
- 顶部导入按钮运行中变「导入中 k/N」且禁用；托盘关闭钮在运行中禁用
- 完成后列表自动刷新；成功行点「回放」直接跳 `/s/<新id>`
- 拖入非法 json（如空对象）：该行失败显服务端错误文案，托盘底部出现兜底提示，其余文件不受影响
- 空列表页拖放同样可用（EmptyState 态）

## 场景 5：超大会话兜底引导（D8）

**目标**：大会话上传失败的引导路径。

上传一个 172MB 级会话（或断开 server 模拟失败）。

**预期**：失败行显错误；托盘底部提示「大会话导入失败时，可在来源应用『导出 bundle 文件』后在此重新导入」；改走「导出 bundle（Local）」→ console 导入可成功。
