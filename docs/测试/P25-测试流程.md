# P25 测试流程

> P25（导出流式化与压缩交付）本地测试指南。覆盖 5 条验收线：M1 流式导出（内存 O(缓冲) + 明文 `.json` 产物闭环不变）、M2 compress 压缩交付（`.json.zst` + `zstd -d` 回导）、坏数据健壮性（跳段不炸导出）、返回值口径（落盘文件字节数）、site 手册一致性；外加前序阶段回归（导出/导入闭环、uploadSessions、录制回放不退化）。

## 准备：构建 + 配置

```sh
# Rust 侧（storage + plugin）
```

无新配置项；`compress` 为命令可选参数，缺省 false。

- 产物文件 = 合法 v1 bundle（`format: prism-session`），console 导入回放正常

## 场景 2：M2 压缩交付（compress=true）

**目标**：`.json.zst` 产物解压后即 v1 bundle 原文，可回导 console。

```sh
cd plugins/tauri-plugin-observer && cargo test
# 用例：to_file_compress_produces_zstd_bundle（magic bytes 28 B5 2F FD + 解码后 Value 级相等
# + 返回值==压缩文件字节）/ to_file_compress_errors_clean_tmp
```

宿主侧端到端（bond-sat 随 0.7.0 接线后）：

```ts
const bytes = await ctrl.exportSessionToFile(id, "/path/诊断数据-<ts>-<id>.json.zst", { compress: true });
```

```sh
zstd -d "/path/诊断数据-<ts>-<id>.json.zst"   # 研发侧一步还原
```

**预期**：
- 产物头 4 字节 = zstd magic；`zstd -d` 后 JSON 可解析且 `format: prism-session`
- console 会话页「导入」解压后文件 → 回放 + 诊断信号正常
- 返回字节数 = `.json.zst` 文件大小（压缩后口径）

## 场景 4：内存实测（宿主实机，bond-sat 联调——**B′ 两阶段接线**，论证裁决）

**目标**：GB 级会话导出内存恒定，交易窗口无感；压缩链路实测。0.7.0 缺省 compress=false 与假想 M1 是同一运行时路径（commands.rs:386）——两阶段接线零成本复得全部隔离，无需 0.6.1 中转。

**准备**：验证夜现录或保活一个 GB 级会话（宿主双 7 retention 会清 7 天前样本；retention 为编译期常量 `observer_config.rs`，临时调大需重编译），两阶段共用同一样本。

**阶段一（升 0.7.0，不传 compress = M1 验收）**（宿主实机，盘后时段）：
1. 宿主 Cargo.toml 精确钉 `tauri-plugin-observer = "=0.7.0"` + `cargo update -p tauri-plugin-observer`（连带 observer-storage 0.3.0）；invoke 一行不动
2. 「日志信息」页导出 GB 级会话（明文 `.json`），任务管理器观察内存曲线；同时操作交易窗口验证无感
3. 导出产物回导 console → 回放 + 诊断信号正常

**阶段二（小补丁，启压缩 = M2 验收）**：
1. `LogInfoSettings.vue` invoke 加 `compress: true` + `sessionFileName` 两分支同补 `.zst`（含无 ts 兜底分支，单条不可拆项）+ tooltip「压缩包，研发 zstd -d 解压」+ loading/success 文案（补时长预期与回执字节数）
2. 盘后实测：`.zst` 体积、`zstd -d` 回导 console 回放、与 `.log.zst` 并存（场景 5 合并走查）
3. 补用例：无 `startedAt` 会话走兜底分支导出 + `zstd -d` 校验

**三级回退阶梯**：① 删 `compress: true` 留 0.7.0（压缩链路回退）；② 钉 `=0.6.0` + 通知上游（执行模型回退——注意内存峰值问题回归）；③ 同② + 通知研发勿用已收产物。

**⚠️ 唯一副本警示**：宿主 retention 双 7 天，导出件是会话唯一长期副本——压缩化后该副本唯一性不变，但坏段产物（gz 截断等）会静默缺数据且无完整性标记，重要会话导出后建议以 console 导入回放核对完整性。

**预期**：
- 阶段一内存曲线平稳（预期 < 200MB；0.6.0 基线为 ≈10GB 峰值换页）；交易窗口零卡顿
- 阶段二压缩交付闭环全通；两阶段回执与实测值回写方案 O3

## 场景 5：与日志导出并存 + 压缩比/墙钟实测（双 codec 对照）

**目标**：宿主「当日全部」合并包导出全链路走查；压缩比与墙钟校准预期（论证裁决：本管线双 codec 数据补齐）。

**步骤**：宿主一次导出「当日全部」（客户端日志 `.log.zst` + 诊断数据 `.json.zst` 并存）。同会话先测一次 `compress=false` 明文导出**墙钟**作对照，再测 `compress=true` 的墙钟与体积，一并记录。

**预期**：
- 两类产物共存不互相干扰；`.log.zst` 走查通过（既有能力不回归）
- 压缩比落在 5-12x 区间（图片多会话 4-6x）；`.zst` 墙钟显著短于明文对照的落盘+压缩总耗时模型预期（3GB 明文对照预计 45-90s 串行 parse 主导）
- 实测值回写方案 O3/手册预期
