# P8 测试流程

> P8（云端 server 抽取 + Backend 抽象）本地测试指南。覆盖三条验收标准：自托管 server 可用、bundle 上传还原、本地模式不退化。

## 准备：构建 observer-server 二进制

```sh
cd crates/observer-server
cargo build --bin observer-server
```

产物在 `crates/observer-server/target/debug/observer-server`。验证：

```sh
./target/debug/observer-server --help
```

---

## 场景 A：本地模式回归（确认 P8 没破坏现有功能）

验证默认 TauriBackend 路径完好。

```sh
pnpm tauri dev
```

1. 主窗口左侧「本机」通道点 ● 录制，操作几下窗口，■ 停止
2. 会话列表出现刚录的会话 -> 点「回放」能正常回放
3. 会话行 ⋯ -> 导出 -> 得到一个 `.rrweb-session.json`
4. 顶部「导入」选回这个文件 -> 列表多一条「导入」标记的会话

主窗口表头应显示 `● 本地`（灰色点）。

---

## 场景 B：云端模式核心闭环（P8 重点）

验证 console 连自托管 server 的读/管理链路。开两个终端。

### 终端 1 - 启动云端 server

模拟用户自托管：

```sh
cd crates/observer-server
./target/debug/observer-server \
  --bind 127.0.0.1:18099 \
  --data-dir /tmp/observer-cloud-test \
  --token my-secret-key
```

看到 `绑定 127.0.0.1:18099` + `鉴权: 开启` 即就绪。数据落 `/tmp/observer-cloud-test/`。

### 终端 2 - 启动 console

```sh
pnpm tauri dev
```

### console 内操作

1. 打开「设置」-> 滚到「云端连接」分组
2. 数据来源选「云端」
3. Endpoint 填 `http://127.0.0.1:18099`
4. API Key 填 `my-secret-key`
5. 点「应用云端连接」-> 提示「已切换到云端连接」
6. 回主窗口 -> 表头指示器变橙色 `● http://127.0.0.1:18099`
7. 会话列表应为空（云端 server 还没数据）

### 测导入到云端

用场景 A 导出的 `.rrweb-session.json`：

8. 点顶部「导入」-> 选 bundle 文件
9. 列表出现该会话（云端 server 落盘了）
10. 点「回放」-> 正常回放（数据从云端 HTTP 拉的）
11. ⋯ -> 编辑信息 -> 改名保存 -> 列表更新
12. ⋯ -> 导出 -> 能下载（从云端拉 bundle）
13. ⋯ -> 删除 -> 列表移除

### 验证 server 侧落盘

```sh
ls /tmp/observer-cloud-test/
# 应看到以时间戳命名的会话目录
```

### 切回本地

设置 -> 数据来源选「本地」-> 应用 -> 表头变回灰色 `● 本地`，列表恢复成本地会话。

## 场景 C：SDK 直上报云端（完整链路）

让 web-demo SDK 直报云端 server，验证 ingest + 读闭环。

### 改 web-demo endpoint

编辑 [examples/web-demo/src/main.ts](../../examples/web-demo/src/main.ts)：

```ts
const ENDPOINT = "http://127.0.0.1:18099";
// ...
init({
  appId: "web-demo",
  endpoint: ENDPOINT,
  token: "my-secret-key",   // 云端鉴权
  env: "dev",
  release: "0.1.0",
})
```

### 终端 3 - 启动 web-demo

```sh
cd examples/web-demo
pnpm dev
```

浏览器开 `http://localhost:1422`，页面显示「采集中」（绿）。点 `logThings` / `boom` / `fetchThing` 产生信号，然后点 `stopSdk`。

### console 侧

保持云端模式 + endpoint 指向 18099：

- 切回主窗口 -> 点「↻ 刷新列表」-> 出现一条 `web` 来源会话
- 点「回放」-> 看到 web-demo 页面的录制 + 诊断信号流

走通完整链路：**SDK HttpSink -> 云端 /ingest -> 云端存储 -> console HttpBackend 读 -> 回放**。

## 排查

| 现象 | 查什么 |
|---|---|
| 切云端后列表一直空 | 终端 1 server 日志有没有收到 `GET /sessions`；endpoint/token 拼对没 |
| 导入失败 401 | API key 与 server `--token` 是否一致 |
| 导入失败 400 | bundle 是否 `format: rrweb-demo-session`（场景 A 导出的肯定对） |
| web-demo「连接失败」 | 浏览器 devtools Network 看 `/ingest/session` 是否 401（token 没传或不对） |
| 回放白屏 | devtools Network 看 `GET /sessions/:id` 响应体有没有 segments |
| 想看 server 实时请求 | 终端 1 打印 `[observer-server]` 日志；或手动 `curl` 查 |

### 单命令验证 server 活着

```sh
# 带 token 应返回会话数组（初始 []）
curl -s http://127.0.0.1:18099/sessions -H "Authorization: Bearer my-secret-key"

# 不带 token 应返回 401
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:18099/sessions
```

## 端口约定

| 服务 | 端口 | 说明 |
|---|---|---|
| console 本地 ingest server | 1421 | 默认，console 自录 + 本地 SDK 上报 |
| web-demo | 1422 | 被观测样例应用 |
| 云端 observer-server（测试） | 18099 | 自托管模拟，可改 |

## 验收对照

| P8 验收标准 | 对应场景 |
|---|---|
| 自托管 server 跑起来，SDK 上报，console 连云端读/回放 | 场景 B + C |
| 离线 bundle `POST /sessions/import` 上传，回放还原 | 场景 B 步骤 8-10 |
| 本地模式（默认）行为不变 | 场景 A |

建议至少跑场景 B + C，场景 A 作回归保险。
