# P9 测试流程

> P9（多租户与运营加固）本地测试指南。覆盖六项新能力：多租户隔离、配额/保留、gzip、服务端 redact、限流、session ID 校验；外加单租户回归（P8 不退化）。

## 准备：构建二进制 + 写 tenants.json

```sh
cd crates/observer-server
cargo build --bin observer-server
```

准备多租户配置（覆盖所有特性，便于逐场景验证）：

```sh
mkdir -p /tmp/observer-p9-test
cat > /tmp/observer-p9-test/tenants.json <<'EOF'
[
  {
    "key": "sk_acme",
    "tenantId": "acme",
    "appIds": ["shop-web"],
    "quotaBytes": 100,
    "retention": { "maxSessions": 2 },
    "redact": {
      "stripNetworkBody": true,
      "stripNetworkHeaders": true,
      "scrubbers": ["Bearer\\s+[\\w.-]+"]
    },
    "rateLimit": { "maxRpm": 3 }
  },
  {
    "key": "sk_beta",
    "tenantId": "beta",
    "appIds": []
  }
]
EOF
```

- `acme`：appId 校验 + 小配额（100 字节，易触发）+ 保留 2 条 + redact + 限流 3 rpm
- `beta`：全开放（不校验 appId、无配额/保留/redact/限流）

启动多租户 server：

```sh
cd crates/observer-server
./target/debug/observer-server \
  --bind 127.0.0.1:18199 \
  --data-dir /tmp/observer-p9-test/data \
  --tenants-file /tmp/observer-p9-test/tenants.json
```

看到 `模式: 多租户（tenants.json）` 即就绪。数据落 `/tmp/observer-p9-test/data/<tenantId>/<sessionId>/`。

## 场景 B：多租户隔离 + appId 越权 + session ID 校验

### B1 鉴权

```sh
# 无 key -> 401
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:18199/sessions
# 错 key -> 401
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:18199/sessions -H "Authorization: Bearer wrong"
# beta key -> 200，空数组（还没数据）
curl -s http://127.0.0.1:18199/sessions -H "Authorization: Bearer sk_beta"
```

### B2 appId 越权

```sh
# acme 用未授权 appId -> 403
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:18199/ingest/session \
  -H "Authorization: Bearer sk_acme" -H "Content-Type: application/json" \
  -d '{"appId":"other-app"}'

# acme 用授权 appId -> 200，拿到 sessionId
curl -s http://127.0.0.1:18199/ingest/session \
  -H "Authorization: Bearer sk_acme" -H "Content-Type: application/json" \
  -d '{"appId":"shop-web","source":"web"}'
# 记下返回的 sessionId，下文用 <ACME_SID> 代指
```

### B3 租户隔离

```sh
# acme list -> 1 条
curl -s http://127.0.0.1:18199/sessions -H "Authorization: Bearer sk_acme"

# beta list -> 0 条（看不到 acme 的会话）
curl -s http://127.0.0.1:18199/sessions -H "Authorization: Bearer sk_beta"

# beta 读 acme 的会话 -> 404（不同 tenant root，找不到）
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:18199/sessions/<ACME_SID> -H "Authorization: Bearer sk_beta"
```

验证 server 侧目录隔离：

```sh
ls /tmp/observer-p9-test/data/
# 应只看到 acme/ 目录（beta 还没建会话）
```

### B4 session ID 校验（路径穿越防护）

```sh
# 非数字 id -> 400
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:18199/sessions/abc -H "Authorization: Bearer sk_acme"
# ".." 作为 id -> 400
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:18199/sessions/.. -H "Authorization: Bearer sk_acme"
# ingest 用非法 sessionId -> 400
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:18199/ingest/events \
  -H "Authorization: Bearer sk_acme" -H "Content-Type: application/json" \
  -d '{"sessionId":"../1","segmentId":"web#1","events":[]}'
```

验证 session.json 写入 tenantId：

```sh
cat /tmp/observer-p9-test/data/acme/<ACME_SID>/session.json
# 应含 "tenantId":"acme"
```

## 场景 C：配额 + 限流

### C1 配额超限（acme quotaBytes=100）

先给 acme 建会话并 ingest 一批事件（任何 > 100 字节的 events 都超）：

```sh
# 建会话
SID=$(curl -s http://127.0.0.1:18199/ingest/session \
  -H "Authorization: Bearer sk_acme" -H "Content-Type: application/json" \
  -d '{"appId":"shop-web"}' | grep -o '"sessionId":"[^"]*"' | cut -d'"' -f4)
echo $SID

# ingest events -> 429（配额 100 字节，事件体远超）
curl -s -w "\n%{http_code}\n" http://127.0.0.1:18199/ingest/events \
  -H "Authorization: Bearer sk_acme" -H "Content-Type: application/json" \
  -d "{\"sessionId\":\"$SID\",\"segmentId\":\"web#1\",\"events\":[{\"type\":2,\"timestamp\":1,\"data\":\"this payload is intentionally longer than one hundred bytes to exceed the tiny quota\"}]}"
# 末行应为 429，body 含 "quota exceeded"
```

> 配额按请求体字节估算（偏保守），100 字节配额下几乎任何 events 都会超。

### C2 限流（acme maxRpm=3）

```sh
# 连发 4 次 GET /sessions
for i in 1 2 3 4; do
  curl -s -o /dev/null -w "req $i: %{http_code}\n" http://127.0.0.1:18199/sessions -H "Authorization: Bearer sk_acme"
done
# 前 3 次 200，第 4 次 429
```

等 60 秒（窗口重置）后再试应恢复 200。beta 不受限（无限流配置），连发不触发 429。

## 场景 D：gzip 压缩 + 服务端 redact

### D1 gzip 响应

需要 > 1KB 的响应才触发压缩。先造一批会话：

```sh
for i in $(seq 1 50); do
  curl -s http://127.0.0.1:18199/ingest/session \
    -H "Authorization: Bearer sk_beta" -H "Content-Type: application/json" \
    -d '{"appId":"app","env":"perf-test"}' > /dev/null
done

# 带 Accept-Encoding: gzip 请求 list
curl -s -D - http://127.0.0.1:18199/sessions \
  -H "Authorization: Bearer sk_beta" -H "Accept-Encoding: gzip" -o /dev/null
# 响应头应含 Content-Encoding: gzip
```

### D2 服务端 redact（import 入库前脱敏）

构造含 network body 的 bundle 上传给 acme（stripNetworkBody=true）：

```sh
cat > /tmp/observer-p9-test/bundle.json <<'EOF'
{
  "format": "prism-session",
  "version": 1,
  "session": {"id":"orig","startedAt":1,"appId":"shop-web"},
  "windows": [],
  "segments": {"web#1":[{"type":6,"timestamp":1,"data":{"plugin":"network","payload":{"reqBody":"{\"password\":\"hunter2\"}","resBody":"data","reqHeaders":{"Authorization":"Bearer leak-token"},"method":"GET"}}}]},
  "annotations": []
}
EOF

NEW_SID=$(curl -s http://127.0.0.1:18199/sessions/import \
  -H "Authorization: Bearer sk_acme" -H "Content-Type: application/json" \
  -d @/tmp/observer-p9-test/bundle.json | grep -o '"sessionId":"[^"]*"' | cut -d'"' -f4)
echo "imported: $NEW_SID"

# 读回，检查 network payload
curl -s http://127.0.0.1:18199/sessions/$NEW_SID -H "Authorization: Bearer sk_acme"
# segments.web#1[0].data.payload 应：
#   - 无 reqBody / resBody / reqHeaders（被剥离）
#   - method: "GET" 保留
#   - "Bearer leak-token" 被 scrubber 替换为 [REDACTED]（若出现在保留字段中）
```

验证落盘文件也脱敏（不可逆）：

```sh
cat /tmp/observer-p9-test/data/acme/$NEW_SID/segments/web#1.jsonl
# reqBody/resBody/reqHeaders 不应出现
```

> 对比：上传给 beta（无 redact 配置），reqBody 应原样保留。可改 `-H "Authorization: Bearer sk_beta"` 重试验证差异。

## 场景 E：保留策略 + console 接线

保留清扫是后台线程，每 **10 分钟**跑一次（[lib.rs](../../crates/observer-server/src/lib.rs) `run_retention_sweep`）。`enforce_retention` 的超龄/超量逻辑由单测覆盖（见场景 A `retention::tests`）。手动验证分两部分：

### E1 console 保留配置接线（单租户）

```sh
pnpm tauri dev
```

1. 设置 -> 「保留」分组 -> 「最大会话数」改为 2
2. 点「保存设置」
3. 重启 console
4. 重开设置 -> 「最大会话数」应为 2（已持久化到 `ingest-config.json`）

验证 console 内嵌 server 收到 retention：

```sh
# macOS: appDataDir = ~/Library/Application Support/com.prism.observer/
cat ~/Library/Application\ Support/com.prism.observer/ingest-config.json
# 应含 "retainMax":2
```

### E2 后台清扫（可选，需等待）

acme tenant 配了 `maxSessions: 2`。造 3 个会话后等 10 分钟（或临时改 [lib.rs](../../crates/observer-server/src/lib.rs) 的 `Duration::from_secs(600)` 为更小值重跑）：

```sh
# 造 3 个 acme 会话
for i in 1 2 3; do
  curl -s http://127.0.0.1:18199/ingest/session \
    -H "Authorization: Bearer sk_acme" -H "Content-Type: application/json" \
    -d '{"appId":"shop-web"}' > /dev/null
done

# 等清扫后，acme 应只剩 2 条（最老的被淘汰）
curl -s http://127.0.0.1:18199/sessions -H "Authorization: Bearer sk_acme" | grep -o '"id"' | wc -l
```

> 想快速验证清扫逻辑，直接看单测：`cargo test -p observer-storage retention`。

## 场景 F：单租户回归（P8 不退化）

确认 `tenants_file=None` 时 P8 行为完全不变。

```sh
# 单租户启动（用 --token，不传 --tenants-file）
./target/debug/observer-server \
  --bind 127.0.0.1:18099 \
  --data-dir /tmp/observer-p8-test \
  --token my-secret-key
```

跑 [P8 测试流程](P8-测试流程.md) 场景 B/C/D，应全部通过（console 连云端、SDK 上报、bundle 导入导出）。关键差异：

| 项 | P8（单租户） | P9（多租户） |
|---|---|---|
| 鉴权 | `--token` 单 Bearer | `--tenants-file` per-tenant key |
| 目录 | `recordings/<sessionId>/` | `recordings/<tenantId>/<sessionId>/` |
| session ID 校验 | 有（P9 新增，单租户也生效） | 有 |
| 配额/限流/redact/保留 | 无（除非 console 设 retainMax） | per-tenant |

console 内嵌模式（`pnpm tauri dev`）默认单租户，P8 全部行为不变；新增的 `retainMax` 接线是唯一可见变化（设置页保存生效）。

## 排查

| 现象 | 查什么 |
|---|---|
| 多租户启动报「加载 tenants.json 失败」 | JSON 语法；`tenantId` 含非 `[A-Za-z0-9_-]` 字符；scrubbers regex 非法 |
| 401 unauthorized | key 拼对没；`Authorization: Bearer <key>` 头格式（注意 Bearer 后有空格） |
| 403 appId 不在授权集合 | `tenants.json` 该 tenant 的 `appIds` 是否包含上报的 `appId`；空数组 = 不校验 |
| 429 quota exceeded | 请求体字节超过 `quotaBytes`；调大配额或减小 events |
| 429 rate limit exceeded | 60 秒窗口内请求超 `maxRpm`；等窗口重置 |
| 400 invalid session id | session id 非纯数字；`/sessions/<id>` 的 id 不能含 `..`/`/`/字母 |
| gzip 响应没触发 | 响应体需 > 1024 字节；请求需带 `Accept-Encoding: gzip` 头 |
| redact 没生效 | 该 tenant 的 `redact` 配置是否加载；`stripNetworkBody` 默认 true，但 `RedactConfig` 显式传 false 时不剥 |
| 保留清扫没跑 | 后台线程 10 分钟一次，刚启动需等；`enforce_retention` 逻辑看单测 |

### 单命令速查

```sh
# server 活着 + 多租户鉴权
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:18199/sessions -H "Authorization: Bearer sk_acme"

# 看 server 模式（日志打印「模式: 多租户」或「单租户」）
# 启动时 stdout 即输出

# 看 tenant 目录结构
find /tmp/observer-p9-test/data -maxdepth 2
```

## 验收对照

| P9 验收标准 | 对应场景 |
|---|---|
| 不同 key 数据隔离；`../` 跨租户访问被拒；越权 appId 上报被拒 | 场景 B |
| 配额超限上报被拒（429） | 场景 C1 |
| 过期会话被后台清扫 | 场景 E2（+ 单测覆盖逻辑） |
| gzip 压缩比显著，回放无感 | 场景 D1 |
| 服务端 redact：network body/headers 被剥离，scrubbers 命中 | 场景 D2 |
| 限流：超阈值请求被拒（429） | 场景 C2 |
| console 本地模式（默认）行为不变 | 场景 F |
| `cargo test` 全过 + 多租户端到端冒烟 | 场景 A |

建议至少跑场景 A + B + C + D（核心新能力）；场景 E2 因 10 分钟清扫周期可选；场景 F 作回归保险。
