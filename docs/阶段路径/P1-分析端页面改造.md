# P1：分析端页面改造

> 阶段路径第 1 阶段。目标：把 console 从「录制器 + 播放器」重做为「观测站」--整体页面改造，使交互符合观测平台范式。

## 背景

当前 MainView 的 hero 是 REC 按钮（「我录自己」），会话只是录制日志；PlayerView 是裸播放器，缺诊断上下文。这与观测平台「多来源会话为重心、自录只是其一」的范式错位，不是加面板能补的，需整体重做。

视觉语言（琥珀/牛血/等宽/控制台）是 subject-driven 的好选择，**全部保留**；改的是信息架构与布局。

## 目标

- MainView：从「录制器」重做为「会话观测台」。
- PlayerView：从「裸播放器」重做为「诊断工作台」。
- SettingsView：轻改，补平台配置项。

## 设计计划（已 brainstorm + 自评）

**Color/Type**：复用 [theme.css](../../src/styles/theme.css) 既有 token，不引新值。新增**来源色**（复用 lane 调色板）：本机=`--amber`、web=`--lane-7 #6FA8DC`、tauri=`--lane-5 #8AB36A`，每个来源在全 UI 有稳定身份色。

### MainView = 会话观测台

左 rail 从「REC 控件」改成**源监控机架（source rack）**--平台的输入 bay，每来源一条通道：本机通道承袭 REC 按钮的 DNA（环形 + 录制中脉冲），web/tauri 为「待接入」暗通道（[P4](./P4-Web-SDK.md)/[P5](./P5-Tauri-Plugin.md) 落地即点亮）。右内容区是**会话浏览器**（hero）：来源过滤 chip + 搜索 + 富行（来源色点·时间·时长·错误数·窗口数·ID·回放/更多）。

**签名**：源监控机架--「一个源 -> 多源」的平台转向浓缩在一个元素，仍在广播控制台语境内。

### PlayerView = 诊断工作台

左主区保留 spotlight 多窗口回放网格（crown jewel，不动）+ 底部 transport（时间轴色带 + focus 标记 + playhead，**叠加 error 红标**）。右侧加可折叠**诊断栏**：统一的**信号流**（console/network/error 混排在一条时间流 + 来源过滤），行带等宽时间码，播放头 ±N ms 的行高亮，点击行 seek。

```
┌──────────────────────────────────────────────┬─────────────────┐
│ ◀ a4f2  本机 · 3 窗口 · 08:32   ⚠3           │ 诊断 [全部▾]     │
├──────────────────────────────────────────────┤                 │
│                                              │ 14:22:03.12     │
│                                              │ ▸ log  clicked  │

│                                              │ 14:22:04.01     │
│                                              │ ▸ GET /api/user │
│                                              │   200  120ms    │
├──────────────────────────────────────────────┤ (行随播放头高亮 │
│ ▶  ▮━━━━━━━━━━━━ bands + ⚠err marks          │  点击行 -> seek) │
│ 00:42 / 08:32   1x   ⊙跟随                    │                 │
```

**Chanel 式裁剪**：诊断栏不用 console/network/error 三 tab（太像 DevTools 泛模板），改统一信号流 + 过滤--恰好把交错事件模型在 UI 上显形。error 另在主时间轴加红标做概览。

### SettingsView = 安静配置

保持安静。新增：HTTP server（端口/token/开关）、采集开关（哪些信号、network body 是否记）、保留策略。

## 落地说明

- **诊断栏用 mock 数据**：采集侧（[P2](./P2-诊断信号采集.md)）还没建。`usePlayer` 生成严格按 `type:6` 信封造的 mock 信号，P2 落地后只换数据源、面板逻辑零改动。
- **来源/错误数字段**：会话暂无这些，`list_sessions` 返回占位（本机来源、error 数 0），真实字段随 P2 补。
- 视觉走 `/frontend-design` skill 流程（已 brainstorm，构建时再 critique）。

## 构建顺序

1. [theme.css](../../src/styles/theme.css) 加来源色 token + 诊断栏变量。
2. [usePlayer.ts](../../src/composables/usePlayer.ts) 加 mock 信号生成 + 信号流/错误红标数据。
3. [MainView.vue](../../src/views/MainView.vue) 重做为会话观测台。
4. [PlayerView.vue](../../src/views/PlayerView.vue) 加诊断栏 + 时间轴 error 红标。
5. [SettingsView.vue](../../src/views/SettingsView.vue) 轻改配置项。

每步 `pnpm build`（含 vue-tsc）验证。

## 不做

- 不做真实信号采集（[P2](./P2-诊断信号采集.md)）。
- 不抽 Sink 接口（[P3](./P3-sink抽象.md)）。
- 不做外部 SDK / plugin / 导出标注分享（[P4](./P4-Web-SDK.md) / [P5](./P5-Tauri-Plugin.md) / [P6](./P6-导出标注分享.md)）。

## 验收

- MainView：源机架（本机通道可录/停、web/tauri 待接入占位）+ 会话浏览器（来源过滤、搜索、富行、回放入口）。
- PlayerView：spotlight 回放 + 诊断信号流（mock 数据，随播放头高亮、点击 seek）+ 时间轴 error 红标。
- SettingsView：平台配置项就位。
- `pnpm build` 通过。
