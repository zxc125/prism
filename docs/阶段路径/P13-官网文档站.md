# P13：官网文档站（VitePress 改造 + 用户手册）

> 阶段路径第 13 阶段。目标：给官网 `site/` 新增「用户手册」（Web SDK / Tauri Plugin / 私有化部署），并把官网从「纯营销页」演进为「营销页 + 文档站」，载体定为 VitePress，分两阶段落地。方案见 [官网文档站（方案）](../架构/官网文档站（方案）.md)。承接 P11（官网与品牌）/ P12（官网 i18n）。

> **进度**：Phase 1（文档先行）✅ 落地（VitePress 接管 `site/` + 5 篇手册 zh/en + 营销页 ClientOnly 保活，`vitepress build` 通过）；Phase 2（营销页 SSG 并入）待办。

## 目标

P11/P12 把营销官网（12 节单页 + 双语 i18n）做完了，但对外缺「教用户怎么用」的长文档：Web SDK 怎么嵌、Tauri Plugin 怎么装、私有化怎么部署。P13 补上文档站这一环：

1. **用户手册**：5 篇可跑操作手册（quickstart / concepts / web / tauri / deploy），代码片段以 `examples/` 为唯一可信源
2. **载体升级**：官网从纯 CSR Vite 应用演进为 VitePress，文档基建（侧栏/TOC/搜索/highlight/locale）开箱即用
3. **顺带偿债**：营销页获得 SSG 预渲染，修复 CSR 时代 SEO / 社交分享卡 / 首屏 FCP 的长期短板

不是产品功能阶段，是对外文档 + 官网基建阶段。与 console（P1-P10）正交，仅动 `site/`。

## 范围

1. **覆盖**：仅官网 `site/`。新增 `/docs/*` 文档区（5 篇 md，zh-CN 优先 + en 骨架）；工程载体迁移到 VitePress；营销页以自定义 Layout 并入。

## 关键陷阱：旧 `vite.config.ts` 必须删除（Phase 1 实施时发现）

方案原计划把「下线旧 Vite 应用」留到 Phase 2 末。**实施时发现必须提前**：VitePress 内部用 Vite 跑构建，而 Vite 会**自动加载项目根的 `vite.config.ts`** 并合并。旧 `site/vite.config.ts` 里的 `vue()`（`@vitejs/plugin-vue`）与 VitePress 自己注册的 plugin-vue **同时生效，导致 `.vue` 被编译两次**——第二个 plugin-vue 收到第一个已编译成 JS 的产物（`_sfc_render`），再 `parse` 报 `At least one <template> or <script> is required`，构建失败。

排查路径（备查）：症状 = VitePress 自带组件编译失败；孤立 `/tmp` VitePress 构建正常 → 非版本问题；patch plugin-vue 打印 source 发现收到的是已编译 JS → 定位到双重 `vite:vue` 插件 → 删 `site/vite.config.ts` 即解。

**因此 Phase 1 已退场**：`site/vite.config.ts` / `site/src/main.ts` / `site/index.html` / `site/src/App.vue` / `site/tsconfig.node.json`。营销页改由 [MarketingPage.vue](../../site/.vitepress/theme/components/MarketingPage.vue) 在 `<ClientOnly>` 内渲染（Phase 1 保 CSR 行为、零回归；Phase 2 再逐组件水合拿 SSG）。

## 风险与边界

- **SSG 水合是 Phase 2 最大成本**：8 个组件碰浏览器全局，[useLang.ts](../../site/src/composables/useLang.ts) 顶层副作用 + Aurora WebGL 需重点改造（方案 B1）。一次性、有边界。
- **营销页视觉回归**：P11/P12 是精品资产，Phase 2 逐页 diff；若回归严重可停留在 Phase 1（文档独立价值已交付，营销页保持旧 Vite 应用，等价路径 B）。
- **过渡期双构建**：Phase 1 若需 `/`（旧）与 `/docs`（新）短暂共存，控制过渡天数；优先让 VitePress 直接接管 `site/` 避免长期双构建。
- **og/SEO 重做**：VitePress 构建期生成静态 HTML，反而修复 P12「og 卡仅运行时 patch」局限，但需重做 og 卡注入（[og-image.svg](../../site/public/og-image.svg) 迁入）。
- **文档与实现漂移**：代码片段以 `examples/` 为唯一可信源；后续 SDK/plugin/server API 变更需同步手册（无自动化，靠纪律）。
- **Tailwind v4 + VitePress 兼容**：成熟组合但有摩擦，Phase 1.1 先验证。
