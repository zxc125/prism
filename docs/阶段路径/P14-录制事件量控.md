> 阶段路径第 14 阶段。目标：给录制链路加档位制量控制，解决高频页面（行情推送 → 密集 DOM mutation）下录制开销卡顿与无效数据。方案见 [录制事件量控（方案）](../架构/录制事件量控（方案）.md)，决策见 [录制事件量控](../决策/录制事件量控.md)。
>

## 目标 ★

交易系统等高频页面：行情推送触发密集 DOM mutation，rrweb 全量默认录制导致 (a) 录制开销（MutationObserver + 序列化 + pack）引发页面卡顿掉帧 (b) segment 膨胀、大量无回放价值数据。P1–P13 的量控制全在传输/存储侧（批量 flush、gzip、配额），**录制侧零量控制**。

本阶段给 SDK 录制层加档位制配置：`RecordProfile` 预设（sampling 高频通道关停/粗化）+ `domBlocks` 免录区（rrweb `blockSelector`，mutation 完全不进流且跳过序列化）。三消费路径（console self-obs / 外部 Tauri / 纯 Web）统一覆盖，Rust 全链零改动；full 档零 diff 保升级无感。

## 范围 ★

1. **覆盖**：
   - SDK：`RecordingOptions` 类型 + `recording-profile.ts` 预设映射 + `SegmentRecorder` / `init` / `recordOffline` 透传
   - observer-tauri：`InitTauriOptions` 透传（Rust crate 零改动零发版）
   - console：`useRecorder` 接线 + CaptureTab 录制档位 UI + 免录区编辑 + 采集信号四开关接线还账
   - 发版：observer-sdk / observer-tauri 0.2.0 + site 手册更新
2. **不在本阶段**（留 P.x）：emit 层 mutation 丢帧（唯一通用降 mutation 手段，等实测不满足再上）、裸 `RecordTuning` options 透传、session.json `recordProfile` 字段 + 回放滞后提示、console 远程下发档位到被观测应用

## 风险提醒（来自方案 §2.4/§8）

- ⚠️ **高概率**：误以为 minimal 档能降行情 mutation 量——sampling 管不到 mutation。UI hint 与手册必须写明「minimal 降交互事件；降 mutation 请配免录区域」。
- domBlocks selector 写错/命中过宽 → 保存时 `document.querySelector` 试解析 + 非空校验。
- 开放问题：O1 `slimDOMOptions.preset` 精确取值（实施时对照 rrweb 2.1.1 类型 + 实测）；O2 `pnpm build` 的 vue-tsc 是否覆盖 packages/（不覆盖则补 typecheck 脚本）。

## 实测数据（3.1 · 2026-09-01）

web-demo 行情模拟页（10×5 报价表，100ms 刷 20 格），SDK 0.2.0（npm dist），两 tab 并行各 ~4.3 min：

| 指标 | Run A（full） | Run B（minimal + domBlocks:[.quote-table]） | 变化 |
|---|---|---|---|
| **报价文本 mutation**（行情数据核心指标） | **3,432 条** | **0 条** | **-100%（block 完全生效）** |
| 事件总数 | 345 | 195 | -43% |
| segment 字节 | 1,138K | 764K | -33% |
| mousemove 事件 | 6 | 0 | minimal 生效 |
| interaction / input | 0 / 0 | 8 / 2 | 保留项正常 |
| type:6 诊断信号 | 112 | 150 | 不降级（豁免成立，B 侧多出的信号来自更多 console 按钮点击） |

**判读**：行情数据零入流（domBlocks 是高频 DOM 场景的主收益）；字节 -33% 为**下界**——Run B 的增量里有 ~463K 是浏览器扩展（read-frog）注入的 `<style>` 噪声，非应用数据；且后台 tab 被 Chrome 节流，模拟器实际 ~13 条/s（前台应为 200/s），真实前台交易页的差距会大得多。emit 层 mutation 丢帧（第三层工具）**无需升格**——domBlocks 已覆盖核心诉求。

**附带发现**：rrweb 会把浏览器扩展注入的 DOM（带 222K 属性的 style）一并录进来——真实部署建议干净 profile 测试，或后续考虑过滤非页面根注入节点（P.x 备选）。

## 关键陷阱（实施时发现）

1. **console 经 workspace dist 消费 observer-sdk**：`node_modules/@prism-obs/observer-sdk` 符号链接到包目录，`main`/`types` 指向 `dist/`——改 SDK 源码后若不 `pnpm build:sdk`，console 的 vue-tsc 与运行时用的都是旧 dist。验证顺序必须是 typecheck → `pnpm build:sdk` → `pnpm build`。根 tsconfig 只含 `src/**`，packages 各自 `typecheck` 脚本负责（O2 结论）。
2. **rrweb `mouseInteraction` 对象形式是「禁用表」**：`false` = 关，未列出/`true` = 记录（rrweb observer 源码 `disableMap[key] !== false` 才注册）。与类型直觉相反——白名单要把不要的交互显式设 false。
3. **`sampling.scroll` 类型只收 number**（节流 ms），无法全关，minimal 档用 500ms。
