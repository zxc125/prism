# P16：外部应用本地落盘

> 阶段路径第 16 阶段。目标：`tauri-plugin-observer` 的 Local 模式从「console 自录专属」泛化为「任意宿主 opt-in」——外部 Tauri 应用可本地落盘到自己的 `appDataDir/recordings/`，经 bundle 导出闭环回 console 回放。承接 P5（Tauri 插件双模式）/ P7（bundle 契约）。方案见 [外部应用本地落盘（方案）](../架构/外部应用本地落盘（方案）.md)，决策见 [外部应用本地落盘 决策](../决策/外部应用本地落盘.md)。
>
> **进度**：🚧 进行中。impl 1.1-3.2 ✅（3.2 用户实测通过）+ 回归 ✅（fresh subagent 独立复核）+ 4.2 文档同步 ✅；余 4.1 发版。

## 目标 ★

[离线导出与云端部署（方案）](../架构/离线导出与云端部署（方案）.md) B11 条目（「Tauri plugin 离线 = plugin 写外部 app 自己的数据目录 + Rust export 命令」）自 Phase A 后一直悬空，无 P 承接。本阶段落地它：

1. **数据 own 在被观测方**：外部 Tauri 应用不想连 console server 时，可 opt-in Local 模式——插件 Rust 直接落盘到该应用自己的 `appDataDir/recordings/`，多窗口协调/关闭=隐藏/分段机制原样复用。
2. **闭环仍收敛 console**（锁定决策 #3）：本地会话经插件 `export_session` 导出 `prism-session` bundle -> console 既有「导入」回放诊断，bundle 契约 version 1 不动，新增第四条投递路径。
3. **锁定决策 #2 显式 opt-in 放宽**（有 P8 放宽 #1 先例）：外部应用默认仍走 HTTP 上报（Remote），本地落盘为可选第二通路。

与 console 正交：console 自身装插件方式、命令面、前端行为零变化。

## 范围 ★

1. **覆盖**：
   - Rust：`ObserverConfig` 增 `source`/`appId`；`start_session`/`stop_session` 元数据去硬编码；新增 `list_sessions`/`export_session` 只读命令 + 权限三件套。
   - JS：`TauriSink` 下沉进 `@prism-obs/observer-tauri`；`initTauri({ mode })`（默认 remote，存量零改动）；controller 增 `listSessions`/`exportSession`。
   - console：`sink.ts` 改 re-export 消双实现；其余不动。
   - 验证：`examples/tauri-demo` 固化双模式开关，Local 端到端实测（录 -> 导出 -> console 导入回放）。
   - 发版 + 文档同步（CLAUDE.md 决策 #2 表述、被观测侧、bundle-规范、P5 注记、P15 手册、npm-crates发布）。
2. **不在本阶段**：外部应用内嵌回放 UI（闭环归 console，锁定决策 #3）；插件写命令面（`delete_session`/annotations 写入——危险操作不外放）；自动/定时导出钩子；`observer-sdk` 任何改动（保持纯 web 零 Tauri 依赖，不动不发版）。

## 设计决策（已拍）★

| # | 决策点 | 选择 | 理由 |
|---|---|---|---|
| D1 | JS 模式注入形态 | `initTauri` 加 `mode?: "remote"\|"local"`，默认 remote | 与 Rust `Mode` 对称；一入口两模式避免双驱动漂移；存量 API 兼容 |
| D2 | TauriSink 归属 | `@prism-obs/observer-tauri` 导出（不进 observer-sdk） | observer-sdk 保持零 Tauri 依赖；observer-tauri 本就依赖 `@tauri-apps/api`。B11 预留名「TauriLocalSink」落定为复用 `TauriSink` |
| D3 | source/appId 注入点 | `ObserverConfig`（Rust 装配时声明），不改命令签名 | 元数据属部署拓扑；autoStart/非 autoStart 单一来源 |
| D4 | Local 会话元数据取值 | `source` 默认 `"self"`；外部建议 `"tauri"` + `appId` | console 零变化；`appId` camelCase 与 web ingest 会话对齐，来源色直接生效 |
| D5 | 导出形态 | `export_session` 返回 bundle JSON，插件不落文件 | 落盘目标由宿主决定；bundle 契约 version 1 复用 |
| D6 | list/export 仅 Local | Remote 下返回 `Err` | Remote 数据不在本机，防误用 |
| D7 | console 侧去重 | `sink.ts` re-export 包内 `TauriSink` | 消双实现漂移；console 前端不发布 npm |
| D8 | local 模式 `appId` 必填性 | **保持必填**（spec 确认 2026-09-08） | 与 remote 一致避免条件必填心智负担；本地会话标识实由 Rust config 决定，文档写清分工 |
| D9 | `appId` 为 None 时 session.json | **省键不写 null**（spec 确认 2026-09-08） | 与 console 现网 session.json 形态一致，列表/导入解析零分支 |
| D10 | tauri-demo 形态 | **固化 Remote/Local 双模式开关**（spec 确认 2026-09-08） | 一份样例展示两种接入，文档写清两种跑法 |

## 关键陷阱（预防性，源自方案 §2.4 中风险项）

- **`initTauri` mode 分叉漏改**：Local 下 `session_id` 命令恒返回 null（它读的是 Remote 专用 `remote_session_id`）——兜底路径若照抄 remote 逻辑会死等。impl 2.2 时逐条对照方案 §4.2 行为分叉表，remote 列必须逐行为等价。
- **`stop_session` 覆写 session.json 丢字段**：现 L131 整文件覆写 `{id, source:"self", ...}`——若只改 `start_session` 不改 `stop_session`，endedAt 回写会把 `appId` 冲掉。两处必须同改（1.2 单测断言 roundtrip 覆盖）。
