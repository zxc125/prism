## 目标 ★

外部应用（bond/frontend）实测录制期间切页/滚动卡顿，归因三成本中心：① 空闲期常录——MutationObserver 回调内同步序列化照跑（rrweb 无 mutation 采样，P14 决策边界）；② flush 主线程阻塞——`append_events` 非 async 命令跑在 NSApplication 主线程，阻塞全进程窗口事件循环；③ 活跃期 mutation 洪峰——虚拟表行挂载/卸载逐帧序列化。bond 侧 0909 提案给出上收路径（方案 A 手动档：机制上收、策略留宿主），与本仓性能归因合并为同一阶段，一次发版三包。

与主线关系：不触四条锁定决策、不改 bundle 契约与 Sink 接口；消费方为外部 Tauri 应用（观测外部决策）与 console self-obs（flush 串行化同链路受益）。

## 关键陷阱（可选，实施时发现）

- **flush 串行化的 stop 竞争**（方案 §2.4 中风险）：`stop()` 必须先 `await this.flushing`（在途批归属原段，segmentId 在 flush 起点抓取）再执行尾 flush，否则段残留事件可能落入下一段或丢失；`destroy()` 经 `stop()` 串接，不单独处理。vitest 用例必须覆盖此场景。
- **「零过滤」语义声明**：P14 决策「不动 Rust 侧」语义 = append 链路零过滤；本 P 只改执行模型（async），不改任何过滤行为——文档已声明，实施时不得顺手加过滤/采样。
