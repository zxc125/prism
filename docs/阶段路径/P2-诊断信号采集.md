# P2：诊断信号采集

> 阶段路径第 2 阶段。目标：把 P1 诊断栏的 mock 数据换成真实采集的 error/console/network 信号。

## 目标

在采集侧（self-obs）加 error/console/network hook，emit `type:6` 交错事件，产出真实数据接入 [P1](./P1-分析端页面改造.md) 的诊断栏。

## 范围

在 **self-obs**（现有自录）上做，验证采集逻辑。外部 SDK 的信号采集在 [P4](./P4-Web-SDK.md)/[P5](./P5-Tauri-Plugin.md) 复用同一份代码。

## 采集侧（纯逻辑，无视觉）

改 [useRecorder.ts](../../src/composables/useRecorder.ts) 的 `record({ emit, ... })`：

1. **error hook**：`window.onerror` + `unhandledrejection` -> emit `{ type:6, data:{ plugin:'error', payload:{...} } }`。
2. **console hook**：patch `console.log/warn/error/info/debug` -> emit `{ plugin:'console', payload:{ level, args, trace } }`。args 序列化（基本类型直传、对象 JSON、循环引用截断、DOM 节点转简述）。
3. **network hook**：patch `fetch` + `XMLHttpRequest` -> emit `{ plugin:'network', payload:{ url, method, status, duration, ... } }`。默认不记 body/headers（PII），留开关。

三 hook 复用 rrweb 的 `emit`，事件与 DOM 同流同 segment 落盘，**存储零改动**（交错事件模型见 [被观测侧](../架构/被观测侧（采集）.md)）。

### 实现选择

倾向**自写最小版**，不引入 `@rrweb/record` 的 console/network 插件重依赖：error 最简单先上；console 次之；network 最繁（async 时序 + 体积控制），最后上，可分两步（先只记 url/method/status/duration，body 后加）。

## 回放侧（P1 已就位）

[P1](./P1-分析端页面改造.md) 的诊断信号流与时间轴 error 红标已用 mock 数据建好。本阶段只需让 `usePlayer` 从真实 `type:6` 事件取数据（替换 mock），面板逻辑零改动。

## 不做

- 不抽 Sink 接口（[P3](./P3-sink抽象.md)）。
- 不做外部 SDK（[P4](./P4-Web-SDK.md)/[P5](./P5-Tauri-Plugin.md)）。

## 验收

- 自录一段含 console.log / 报错 / fetch 的操作，回放时诊断信号流显示真实事件、随播放头高亮、点击 seek。
- error 红标点出现在时间轴对应时刻。
- `pnpm build` 通过。
