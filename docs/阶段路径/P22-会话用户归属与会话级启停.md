# P22：会话用户归属与会话级启停

> 阶段路径第 22 阶段。目标：会话可携带宿主注入的用户信息（`user`），controller 提供会话级启停（监听不销毁），使外部应用可按「登录区间」划会话、按用户过滤导出。承接 P17（段控制上收——会话级启停叠加在段级门控之上，门控语义零改动）。外部输入：bond-sat 提案（2026-09-17）。方案见 [会话用户归属与会话级启停（方案）](../架构/会话用户归属与会话级启停（方案）.md)，决策见 [决策/会话用户归属与会话级启停.md](../决策/会话用户归属与会话级启停.md)。
>
> **进度**：✅ 全部完成（2026-09-18）。1.1–1.5 实施 + 1.7 独立复核与用户实测 + 1.9 console 用户列增量 + 1.6 发版（sdk 0.4.0 / tauri 0.6.0 / crates 0.5.0，registry 可拉取）。待 bond-sat 回改依赖锁（O1：crates 0.4.0→0.5.0 / npm 0.5.0→0.6.0 / sdk →0.4.0，其提案「上游 P21」更正为 P22）。

## 目标 ★

bond-sat「日志信息」页需按当前登录用户过滤/导出会话。现状三重缺口（已核实）：① 插件 `start_session` 无参数，动态用户信息无处可放；② 会话边界 = 进程启动（autoStart），登录前即开会话，多用户混录同一会话；③ `stop_session` 整文件重建 session.json，即使加字段也会在登出时被冲掉。本阶段给平台补「会话归属」能力：宿主可在会话级启停时注入任意轻量 meta（user 为首个具名字段），会话边界归宿主策略。

与主线关系：不触四条锁定决策、不改 bundle 契约版本（加可选字段）、storage/server/console 零改动（裸 `Value` 透传与 Remote meta 通路均已源码核实）。消费方为外部 Tauri 应用（观测外部决策延伸）；console 读路径自动透传 user 但不加 UI。

## 关键陷阱（可选，实施时发现）

- **stop 整文件覆写**（spec 已预识别，D2 根除）：`stop_session` 旧实现用内存态重建 session.json（commands.rs:162-175），任何 start 期 merge 进文件的字段都会在登出（= bond-sat 必经的 stopSession）时被冲掉。照提案原样实现（payload 第 6 参 + Session 态存 extra）不解决状态/文件漂移，必须走 read-modify-write。
- **Remote 第二会话不重绑**（spec 已预识别，D6a）：`sessionBound` 一次性守卫（index.ts:173）在主窗/子窗各自成立——若只在新 `startSession` 里置 `sessionBound = true` 而不在会话结束时重置，第二次 `bind_session` 广播会被全部窗口忽略，`HttpSink` 继续向已 endSession 的旧 sessionId 上报段事件（server 侧 404 或数据丢挂）。
- **幂等 startSession 的广播窗口**：已活跃时先 `stop_session` 再 start，各窗经历一次 `active:false→true`；manual gating 宿主无感，默认 gating 宿主有一次 <100ms 空段窗口。不做平台级消音（O3 留观察），手册注明即可。
- **impl 偏离①——stop 写路径直接用 `finalize_session`**：observer-storage `finalize_session`（storage.rs:210）本身即 read-modify-write 只补 endedAt，与方案 §4.1 的「finalize 后再 merge_session_meta」等价且少一轮文件读写；故 stop 只调 finalize，storage.rs 的 `merge_session_meta` re-export 免除（该函数 console 侧本就自用）。
- **impl 顺带修复——console 自录 name/note/tags 不再被 stop 冲掉**：console 经 `update_session_meta`（merge）写入 session.json 的 name/note/tags，旧 stop 整文件重建会全部冲掉（与 user 同型陷阱，D2 改造一并根除）。
- **impl 细节——`meta: null` 视同 None**：JS `invoke(..., { meta: null })` 反序列化为 `Some(Value::Null)`，`merged_meta` 将 Null 与 None 同置为「无 extra」，仅拒绝其余非 object（字符串/数组/数字）。
- **/regress 发现——Remote 幂等 startSession 的 end 竞态（已收窄，非封死，留观察）**：Remote 主窗已活跃时 `startSession`，监听 `!active` 分支的 `endSession()` 与续体 `sink.startSession(meta)` 并发——若 endSession 读取 sessionId 晚于重绑，end 标记/残留 flush 会打到新会话（subagent 回归发现，Local 不受影响）。缓解：`HttpSink.endSession` 改「进入即捕获并解绑」（封口目标锁定进入时 sid，`flush(sid)` 显式带参，重复 end no-op，定时器随解绑即清防误杀新会话 flush 周期；顺带修正 endSession 后 `isRecordingActive` 仍 true 的旧 wart）。聚焦复核定位的两类错配残留窗口：① 监听 handler 晚于 create 响应才启动；② handler 先启动但 `rec.stop()` 的达量网络批（≥batchSize）慢于 create 往返——竞态从「必现」收窄为低概率窗口，Remote-only + 需幂等重叠（bond-sat 主路径 Local）。1.7 实测 Remote 双模场景；复现再升格彻底收口（end 显式 sid 参数化 / controller remote 分支串行化 / sink 记 endedSid 集合，聚焦复核已给出三方向）。
- **/regress 备查——宿主 meta 塞 `endedAt` 会原样入 session.json**：start 期基础载荷无 endedAt 键，D3 保留键列表（id/startedAt/source/appId）不含它；与决策一致，仅记档（宿主无合理动机塞此键，不加白名单）。
