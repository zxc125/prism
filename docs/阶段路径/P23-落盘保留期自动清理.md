# P23：落盘保留期自动清理（retention）

> 阶段路径第 23 阶段。目标：给 `tauri-plugin-observer` Local 落盘加保留期自动清理，封顶外部宿主（bond-sat）本机诊断数据无界增长。承接 P16（外部应用本地落盘）与 P9（retention 能力沉淀）。方案见 [落盘保留期自动清理（方案）](../架构/落盘保留期自动清理（方案）.md)，决策见 [落盘保留期自动清理](../决策/落盘保留期自动清理.md)，需求源为 bond-sat 定稿提案（bond-sat 仓 `docs/observer-recording/bugs/2026-10-20-observer-plugin-诊断数据保留期提案.md`）+ 本仓 2026-10-20 五路代码核对。
>
> **进度**：📋 计划。spec 已定稿（决策 + 方案两文档落盘，归属判定「全新 P23」经用户确认）。

## 目标 ★

bond-sat Local 模式诊断数据无任何保存时效：macOS AppData 完全无界，Windows 仅「升级即清」兜底。能力层 `observer-storage::retention`（`RetentionPolicy` + `enforce_retention`，P9 沉淀、server 已接线）在插件侧接线空白。本阶段把同一能力接到插件 Local 落盘：storage 加保护名单变体 + 孤儿清理维度，插件 `ObserverConfig` 加策略字段、setup 起周期清扫线程，随版发 storage 0.2.0 / 插件 0.6.0（npm 不动）。

## 范围 ★

1. **覆盖**：storage `enforce_retention_protect`（protect 三路跳过 + 孤儿维 + `Some(0)` 防呆 + `validate_session_id` 前置 + 实际成功计数）；`RetentionPolicy.orphan_max_age_days`；插件 `retention` 字段 + lib 根 re-export + setup 清扫线程（catch_unwind / filter(active) / id 日志）；文档（tauri.md zh/en、插件 README、模块头、发版台账）；发版与 bond-sat 衔接。
2. **不在本阶段**：手动清理命令、server 现网回接、体积维度、残缺目录（无/坏 session.json）兜底、旧根治理、会话级滚动、console 保留策略 UI（P10 方案 RetentionTab 规划位）——均记档于决策文档「未做」。

## 设计决策（已拍）★

| # | 决策点 | 选择 | 理由 |
|---|---|---|---|
| D1 | `retention` 字段形态 | 非 `Option` + Default 空策略 | 对齐 server `ServerConfig.retention`；`is_empty()` 已有，空策略早退不扫描 |
| D2 | protect 变体位置 | storage 新增函数，`enforce_retention` 委托空名单：签名不变，既有调用方正常路径行为不变（仅 D7 删除纪律三纪律点随变体生效，现网无触发面） | 两 crate 共用、server 可后续 opt-in；P9 调用面签名不可变 |
| D3 | 孤儿维度 | 进本期，独立字段 `orphan_max_age_days`（None = 不清，不与 `max_age_days` 联动） | P19 实证无 endedAt 是常态（崩溃/强杀/直接退出，全链路无退出兜底）；显式 opt-in 守「缺省=现状」 |
| D4 | 清扫周期 | 首跑延迟 30s + 周期 1h，仅 Local 且策略非空启动 | server 10min 无必要，24h 长挂机漏扫 |
| D5 | protect 名单 | `try_state` 后 `filter(\|s\| s.active)` 取 id | `stop_session` 不清 `s.id`，不看 active 会无限期豁免已收口会话 |
| D6 | 线程护栏 | 循环体包 `catch_unwind`，panic 记日志后 continue | `recordings_root_with` 有现成 `expect` 源；静默停摆最难发现 |
| D7 | 删除纪律 | `Some(0)` 视同 None；删除前 `validate_session_id`；返回实际删除数 | 防呆 + 纵深（id≠目录名/`../`）+ Windows 锁不计成功 |
| D8 | 版本 | storage 0.1.0→0.2.0 / 插件 0.5.0→0.6.0 双 minor；npm 不动 | additive minor（段控 D6 惯例）；TS 零面 |
| D9 | annotations scope | 随整目录连带删，手册注明「需长期保留先 export」 | 会话从属数据同生命周期（bond-sat 侧待通知确认） |
| D10 | 手动清理命令 | 不做 | API 面最小（提案 §九.4）；联调造数 = 预置目录 + 手改时间戳 |
| D11 | 清扫范围 | 仅当前配置落盘根 | P20 D6 切根不迁移，跨根清理即违规 |
| D12 | 自动清理授权模型 | 宿主声明策略 = opt-in 授权，非外放删除命令 | 循 P16「危险操作不外放」边界的扩展声明 |

## 关键陷阱（实施前已知，来自 2026-10-20 五路核对）

1. **setup 的 `app` 是引用**——不能直接 move 进 `'static` 线程，spawn 前 `let app = app.clone();`（先例 [lib.rs:85-88](../../plugins/tauri-plugin-observer/src/lib.rs#L85-L88) config clone 进闭包）。
2. **`SessionState` 是 lib.rs 私有别名**（`std::sync::Mutex<session::Session>`）；清扫逻辑若独立成模块需写全类型。且 `stop_session` 不清 `s.id`——protect 必须看 `active`（D5），否则已收口会话被无限期豁免。
3. **锁纪律**：锁只包 id 提取、绝不跨 `enforce_retention_protect` 调用；全 crate 对毒化锁按静默 no-op 处理，持锁跨 IO 或持锁 panic = 录制整体哑火。实现处加注释固化。
4. **插件依赖行漏改本地不可见**：path+version 双指定下 path 掩盖 version req 错误，`cargo check`/`test` 全绿，直到 `cargo publish` 才炸——dry-run ×2 进清单（方案 §4.3）。
5. **storage 0.2.0 是搭车发版**：P19 六个读路径 pub API 在 git main 而 registry 0.1.0 没有——changelog 必须分两批列，否则「0.1.0 与 0.2.0 差了什么」排查失真。
6. **eprintln 在 release GUI 不可达**（`windows_subsystem=windows` 吞 stderr，console 自家 main.rs:2 即如此）：日志是尽力而为的可观测性，bond-sat 侧排查通道（如接 client.log）留衔接讨论，不阻塞本阶段。
7. **console 内嵌 server 清扫与插件清扫同根**（2026-10-21 回归复核修正：原「双清扫、数据面不重叠」表述失实）：内嵌 server 的 data_dir 就是落盘根 `appDataDir/recordings`（[src-tauri/src/lib.rs:228](../../src-tauri/src/lib.rs#L228)），两条清扫作用于同一目录。实际拓扑：原装 console 插件 retention 缺省空 → 插件线程不启动，只跑 server 一条（10min）；外部宿主声明策略 → 只跑插件一条（1h）；未来 console 若声明插件 retention，两条独立策略清同一根——均幂等只删、无锁冲突，但策略叠加需宿主自审。
8. **插件 Builder setup 参数是 `&AppHandle<R>`**（非宿主 `tauri::Builder` 的 `&mut App`）：`app.clone()` 直接进线程；且 `try_state` 的锁守卫借自 `State`，不能从 `and_then` 闭包返回（E0515）——active 判定 + id 提取须在闭包内完成、只把 `Option<String>` 带出来。
9. **测试 id 必须过 `validate_session_id` 纯数字白名单**：删除纪律前置校验后，storage 既有测试的字母 id（`"old"`/`"s1"`）会被静默跳过删除——测试 id 已全部改数字串（与 `unique_id` 毫秒时间戳形态一致）。副作用注记：meta.id 非数字的目录从此**永不可清扫且无日志信号**（有意为之的纵深防御）——现网 id 全为 `unique_id` 数字串、导入重分配数字 id，无实际影响。
