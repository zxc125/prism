# P24：一键打包上传

> 阶段路径第 24 阶段。目标：外部观测应用（Tauri Local 落盘 / web 离线录制）内手动一键把本地已录会话批量上传到观测端，兑现 P16 遗留的「真需求出现再议」。承接 P16（外部应用本地落盘）+ P18（导出 to-file 变体，超大会话兜底）。方案见 [一键打包上传（方案）](../架构/一键打包上传（方案）.md)。
>
> **进度**：✅ 落地（2026-11-04）。spec / 实施 / fresh subagent 回归（4 条建议已修）/ 发版 sdk 0.5.0 + observer-tauri 0.7.0 全过；运行时实测通过（批量上传 + 「选择 bundle 文件上传」入口端到端；过程中修复 CORS 预检 Content-Encoding 等三处，见修复记录）。

## 目标 ★

打包端（`build_export_bundle` / `buildBundle`）、契约（prism-session v1）、接收端（`POST /sessions/import` + Bearer）均已完备且跨四条投递路径通用，缺的只是外部应用侧「最后一公里」：上传执行器、目标配置位、批量编排、结果反馈。现状闭环是「应用导出 bundle 文件 → 人工导入 console」（P16 定义），跨机场景体验断裂；site/docs 手册已把「下载或上传」写成既定路径（web.md:96）而 SDK 无 upload API，存在文档-实现落差。本阶段在前端编排层补齐该腿：网络能力住前端 JS（与 HttpSink 先例一致），插件 Rust 侧零改动零权限变更。

## 范围 ★

1. **覆盖**：observer-server 请求侧 gzip 解压 + `/whoami` 能力协商标记；observer-sdk `uploadBundle`/`probeRequestGzip` + `OfflineController.upload`；observer-tauri `TauriController.uploadSessions`（串行 + onProgress + 逐会话回执）；tauri-demo 一键上传按钮 + Local 模式配置解锁；**console「导入录制文件」交互改造（D11：拖放 + 多选 + 逐文件进度/回执，视觉先走 `/frontend-design`，用户 2026-11-02 追加）**；手册与架构文档落差收敛（web.md / concepts.md / tauri.md / deploy.md / 被观测侧.md / demo README + sdk docstring）；发版 sdk 0.5.0 + observer-tauri 0.7.0。
2. **不在本阶段**：自动/定时上传（P16 non-goal 维持）；服务端幂等键/upsert 与客户端去重（用户拍板接受重复）；脱敏（upload 不带 redact 参数）；分块/断点续传/流式上传端点；多会话容器格式与批量导入端点；上传登记表/session.json 上传状态字段/上传后自动清理；服务端体积上限（bundle-规范.md:73 缺口，正交记档）；console 接收端命令/端点改动（仅动导入交互 UI）；插件、observer-storage 任何改动。

## 设计决策（已拍）★

| # | 决策点 | 选择 | 理由 |
|---|---|---|---|
| D1 | 上传执行器放哪层 | SDK 纯函数 `uploadBundle`，web/tauri 两路复用 | 网络能力本住前端 JS（HttpSink 先例）；不给插件引入首个 HTTP client |
| D2 | 上传端点 | 复用 `POST /sessions/import` | 接收端零改动、契约零变更；console 内嵌与自托管同一份代码 |
| D3 | 脱敏 | upload API 不带 redact 参数 | 用户拍板「不用脱敏」；责任归接收端多租户策略 + 宿主 `export(redactOpts)` opt-in 组合 |
| D4 | 幂等 | 无（接受重复） | 用户拍板；import 换新 id 语义已被测试锁定，不动 |
| D5 | gzip 能力协商 | `/whoami` 响应加 `requestGzip: true` + SDK 默认不压缩 | 老 server 对 gzip body 静默 400，必须协商；与 P9 排除项「bundle 内嵌 gzip」不同层（传输层 vs 载荷层） |
| D6 | 批量形态 | 串行逐会话循环，无批量端点/容器格式 | server 单线程串行；bundle 契约单会话粒度是事实约束；对齐 console batchDelete 范式 |
| D7 | uploadSessions 模式限定 | 仅 Local（与 listSessions 同款 throw 文案） | Remote 数据已在观测端；ensure_local 语义一致 |
| D8 | 超大会话兜底形态 | 失败错误文案引导 + 手册指引 `exportSessionToFile`；不做上传前体积预检 | 预检需整串序列化（172MB 级成本翻倍） |
| D9 | 上传目标配置 | API 参数化 `{endpoint, token?}`，不进 `RecordOfflineOptions`/`ObserverConfig`，宿主自管存储 | 录制与上传目标正交；不污染 Local 模式「endpoint 被忽略」语义 |
| D10 | uploadSessions ids 缺省 | 缺省 = `listSessions()` 全部 | 一键语义；接受重复故重复点击安全 |
| D11 | console 导入交互形态 | 拖放 + 多选 + 逐文件状态机（等待/导入中/成功/失败）+ 聚合反馈；视觉先走 `/frontend-design` skill | 用户拍板（2026-11-02 追加）；现状单文件 + 一条消息零反馈；数据面复用既有 import 命令，不动接收端 API |

论证细节见 [决策/一键打包上传.md](../决策/一键打包上传.md)；API 签名与逐文件改动见方案 §4。

## 关键陷阱（可选，实施时发现）

- **gzip 静默打死老 server**：老 `read_body` 对 gzip body `read_to_string` 失败 → body=Null → 400「缺少 format」，客户端无从分辨。解法：SDK 默认不压缩；压缩必须经 `probeRequestGzip`（whoami `requestGzip===true`）确认后启用——禁止「默认 auto 压缩」。
- **大上传阻塞实时流**：server 单线程串行 + `read_body` 整体入内存，大 bundle 上传期间 `/ingest/*` 全部停摆。解法：串行逐会话（不并发）+ 手册标注避开录制高峰 + gzip 减体积；不做分块（scope 外）。
- **`/whoami` 是既有消费面**：console LoginGate/TopBar 读该端点，加 `requestGzip` 必须是 additive 字段，不得改既有键形状。
- **200 ≠ 全段落盘**：import 对 segments 值非数组静默跳过（storage `write_import_bundle` 无 else 报错），回执文案不得夸大为「全部段落盘成功」。
- **demo 的 `?token=` URL 注入不照抄**：会进浏览器历史；token 只走 localStorage 配置 UI。
