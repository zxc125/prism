## 目标 ★

下游 bond-sat（交易客户端）实测 GB 级会话导出内存峰值 ≈10GB（Value 树 2~3× 膨胀 + 全量 JSON String 副本）：16GB 办公机换页抖动拖垮整机（盘中不可接受），极端 OOM 崩进程；且裸 JSON 大文件超 IM 单文件限制无法转发。本阶段把导出链改为流式写（内存 O(缓冲+最长单事件行)，不随会话体量增长），并以 opt-in 参数提供 zstd 压缩交付（预期 5-12x，IM 可转发）。

单版 0.7.0 交付（**P25 论证改判**，原两里程碑切分的两个前提被证伪：M1 代码快照不存在于版本控制、宿主 zstd 已在依赖树——见修复记录段）：M1/M2 里程碑由 **compress 参数**而非版本号提供——缺省 false 的执行路径与假想 M1 逐字节一致（宿主渐进验证照常），显式 true 才启压缩。默认关 = console「导出→导入」闭环（锁定决策 #3 落地形态）零变化。

## 设计决策（已拍）★

| # | 决策点 | 选择 | 理由 |
|---|---|---|---|
| D1 | compress 形态 | 命令可选参数 `compress: Option<bool>`，默认 false | 默认保 console 闭环；老调用方零改动；P24「默认不压缩+显式启用」同范式 |
| D2 | `.zst` 定位 | 交付文件层第三层；解压后 = prism-session v1 原文，契约零 bump | 与 P24 传输层 / P9 载荷层显式区隔 |
| D3 | 流式 API | storage 新 pub `write_export_bundle_streaming(dir, &mut impl Write) -> Result<u64, String>` | 压缩无关、符合既有 `Result<_,String>` 风格；`build_export_bundle` 不动 |
| D4 | segments 输出序 | segmentId 字典序（**必做**非可选） | 现状 serde_json Map(BTreeMap) 已是字典序；按枚举序直写是回归且 Value 比对测不出 |
| D5 | 行校验 | parse 校验 + 通过后直写原文行；坏行剔除沿用现状 | 低频操作正确性优先；非法行入 bundle = 导入侧整体拒绝的单点故障 |
| D6 | 坏段语义 | 行级失败（残行/坏 JSON/单行非 UTF-8）剔行继续；流级失败（gz 截断等 read 持续 Err，连续 8 次上限）停止续读该段、**保留已解出行**；段键必存在，导出不因坏段失败 | 实现精确化：比全量实现「整段剔空」保留更多有效数据（截断 gz 前段好数据不陪葬）；两处与 build 路径的预期差异经单测对照钉死 |
| D7 | 返回值 | 实际落盘文件字节数，`.metadata().len()` 取 | compress 关 = 现状口径；开 = 压缩后字节；宿主 client_log `compress_to` 先例 |
| D8 | 版本切分 | 单版：storage 0.3.0 + plugin 0.7.0（新参数=minor）+ npm 0.8.0；M1/M2 里程碑由 compress 参数提供（缺省 false = M1 行为） | **论证改判**：M1 快照不存在于版本控制（发 0.6.1 必是完整 M2 代码）；新参数进 patch 违反版本惯例；宿主 zstd 已在依赖树（消费者集合为空）；渐进性由参数提供，版本切分无增量价值 |
| D9 | zstd 依赖位置 | 只进 plugin crate（M2）；storage 压缩无关 | 宿主 client_log 同款已实证；gzip 备选记档（方案 O1） |
| D10 | 原子写 | 保持 `.tmp`+rename；失败路径 `remove_file(&tmp)` | 现状失败同样残留，顺手治理 |
| D11 | 内存口径 | 文档措辞 O(缓冲+最长单事件行) | rrweb FullSnapshot 单行可达数十 MB，纯「O(1)」失实 |
| D12 | 闭环处置 | 手册注明「`.zst` 经 `zstd -d` 后即可回导 console」 | 闭环对人工转发一步可达，不声明放弃；console 原生解压留后续 |

## 关键陷阱（预判，实施时补充）

1. **跳段不炸导出**：gz 截断 member / 非 UTF-8 行（`BufRead::read_line` 返回 `InvalidData`）必须按 D6 剔段继续，禁止 Err 冒泡中断整个导出——否则宿主「导出报错→重试→又全量解析」反复烧 CPU。
2. **等价验收口径**：流式直写原文行与 `build_export_bundle` 的 Value 重序列化**字节级必然不等价**（键序/空白），验收只认解压后 Value 级 canonical 等价（exportedAt 对齐）；segments 不排序则产生不可复现输出且 Value 比对测不出（D4 必做的原因）。
3. **压缩字节取法**：`finish()` 后取文件 `.metadata().len()`（宿主 client_log.rs:241-247 先例）；`into_inner() as u64` 编译不过（`BufWriter::into_inner()` 产出 `File`）。
4. **flush 链**：`enc.finish()` → 底层 `BufWriter` flush 缺一步 = 产物尾部截断。
5. **console 被动引入 zstd-sys（M2 起）**：`pnpm tauri dev` 首次编译会拉 C 工具链（cc），rsproxy 镜像下拉包慢属正常；若目标环境编译失败，回退决策点见方案 O1（gzip 备选）。
6. **err_streak 的固有近似**（/regress 备注）：连续 8 条非 UTF-8 行会被当流级失败停段——后果良性（保留已解出行、导出继续），不区分「连续坏行」与「解压卡死」。
7. **同一 segmentId 的 `.jsonl` 与 `.jsonl.gz` 并存**（/regress 备注，纯理论）：流式输出会重复 JSON 键（build 路径 Map 去重）；写侧不会并存，serde_json 解析取后者，下游无碍。
8. **宿主 caret 依赖的被动漂移**（论证裁决 upgrade-修订2）：宿主 `Cargo.toml` 现为 caret `"0.6.0"`——若发 0.6.1，任意 `cargo update` 会把它被动漂进一次执行模型重写；升级指引第一步 = **精确钉 `=0.7.0`**（最终单版方案下 caret 不跨 minor 本就安全，钉版仍为交接清单第一项）。
9. **坏段回放形态双态**（论证裁决 d6）：同一坏文件两种产物形态——build 路径空段被 usePlayer 跳过（窗口缺席），流式路径前缀保留 → 段在 hiddenAt 前恒 active、播完前缀**提前定格**；消费链形态已由 `streaming_truncated_gzip_survives_import_chain` 钉死，site 手册注明核对口径。
