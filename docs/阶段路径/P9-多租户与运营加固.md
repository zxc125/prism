# P9：多租户与运营加固

> 阶段路径第 9 阶段（✅ 已完成）。目标：从单租户走向多租户自托管 + 运营级能力。详细方案见 [P9-多租户运营加固（方案）.md](../架构/P9-多租户运营加固（方案）.md)。

## 落地结果

- **[observer-storage](../../crates/observer-storage)**：新增 [`validate_session_id`](../../crates/observer-storage/src/bundle.rs)（`^[0-9]+$`，堵 read API 路径穿越）；gzip 落盘 [`append_events_file_with`](../../crates/observer-storage/src/storage.rs) + [`WriteOpts`](../../crates/observer-storage/src/storage.rs)（每批一个 gzip member，可追加）+ [`read_segment_events`](../../crates/observer-storage/src/storage.rs)（`MultiGzDecoder` 透明解压，按扩展名分派 plain/gz）；[`redact.rs`](../../crates/observer-storage/src/redact.rs) Rust 移植 [redact.ts](../../packages/observer-sdk/src/redact.ts)（`RedactConfig`/`RedactOpts` + `redact_bundle`，strip network body/headers + scrubbers 递归）；[`retention.rs`](../../crates/observer-storage/src/retention.rs) `enforce_retention`（超龄 + 超量淘汰）。`read_session`/`build_export_bundle` 改用 gzip 感知读路径，旧 `.jsonl` 零迁移。
- **[observer-server](../../crates/observer-server)**：新增 [`tenant.rs`](../../crates/observer-server/src/tenant.rs)（`TenantConfig` + `TenantRegistry`，`tenants.json` 加载 + key 查找 + tenantId 路径穿越校验 + scrubbers 启动期编译）、[`quota.rs`](../../crates/observer-server/src/quota.rs)（`QuotaTracker` 惰性扫描初始化 + 写入累加，per-tenant `AtomicU64`）、[`rate_limit.rs`](../../crates/observer-server/src/rate_limit.rs)（`RateLimiter` 滑动窗口）；[lib.rs](../../crates/observer-server/src/lib.rs) `ServerConfig` 加 `tenants_file`/`retention`，[`handle_request`](../../crates/observer-server/src/lib.rs) 串起 tenant 解析（bearer key -> registry.lookup）+ 限流（429）+ 配额预检/记账（429）+ gzip 响应（`Content-Encoding: gzip`，>1KB 且 Accept-Encoding 时压缩）+ 后台保留清扫线程（每 10 分钟）；[routes.rs](../../crates/observer-server/src/routes.rs) 所有 `:id` 路由过 `validate_session_id`，`/ingest/session` 加 appId 越权校验（403）+ 写入 tenantId，`open_segments` 用 `<tenantId>/<sessionId>` 复合键防跨租户同 id 冲突，`POST /sessions/import` 入库前过 `redact_bundle`；[bin/observer_server.rs](../../crates/observer-server/src/bin/observer_server.rs) 加 `--tenants-file`。
- **console**：[ingest.rs](../../src-tauri/src/ingest.rs) `IngestConfig` 加 `retain_max` -> `ServerConfig.retention`（`RetentionPolicy { max_sessions }`），`get/set_ingest_config` 透传；[SettingsView.vue](../../src/views/SettingsView.vue) `retainMax` 接 load/save（UI 已有字段，纯数据接线，无视觉变更）。
- **6 项决策全部落实**：tenants.json 配置源 / session ID `^[0-9]+$` / bundle 契约不动（gzip 限落盘+传输）/ console 内嵌隐式单租户（`tenants_file=None` 透传）/ 串行 + 计数限流 / redact 不可逆。
- **验收**：`cargo test` 45 passed（observer-storage 22 + observer-server 18 lib + 5 多租户端到端集成）；集成测试覆盖多租户隔离 + appId 越权 + 路径穿越 400 + 限流 429 + 配额 429 + gzip 响应 + 单租户向后兼容；`pnpm build`（含 vue-tsc）通过；整图 `cargo check` 通过。

## 目标

多租户隔离 + 存储压缩 + 保留策略 + 服务端脱敏 + 写限流，使自托管 server 可团队/多应用使用，达到运营级。**不动采集层与 bundle 契约**，所有改动集中在 observer-server / observer-storage 两 crate + console 设置页。

## 现状基线（P8 已就位）

- [observer-storage](../../crates/observer-storage) 全部吃 `&Path`，`list_sessions`/`read_session`/`import_bundle` 按 root 扫--多租户只需传 `root.join(tenant_id)`，**存储层零改动**（除新增校验/压缩/redact 工具函数）。
- [observer-server](../../crates/observer-server) 单 `ServerConfig` + 单 `auth_token` + 单 `data_dir`；[handle_request](../../crates/observer-server/src/lib.rs) 先鉴权再分发到 `handle_route`/`handle_read_route`，两路由都吃 `root: &Path`。
- tiny_http 串行处理（`incoming_requests()` 单线程），**无真正并发写**--限流据此设计。
- [SettingsView.vue](../../src/views/SettingsView.vue) 已有 `retainMax` UI 占位但无后端执行（B13 文档提及未建）。

## 范围

1. **多租户存储**：`recordings/<tenantId>/<sessionId>/`；API key 映射 tenant + 授权 appId 集合；`session.json` 加 `tenantId`；越权 appId 上报被拒。**必须补 session ID 校验**--read API `/sessions/:id` 当前信任 URL（[routes.rs](../../crates/observer-server/src/routes.rs) 直接 `root.join(id)`），多租户下 `../` 可跨租户逃逸。
2. **配额 + 保留策略**：每租户磁盘配额（ingest 前查、超限拒 507/429）；会话保留期/数量上限，后台线程清扫；[SettingsView.vue](../../src/views/SettingsView.vue) `retainMax` 接后端。
3. **segments gzip**：落盘 `.jsonl.gz` + HTTP `Content-Encoding: gzip`，replay 侧按扩展名透明解压。**bundle 契约不动**（version 1 保持纯 JSON），gzip 只作用在落盘 + 传输两层。
4. **服务端 redaction**：Rust 移植 [redact.ts](../../packages/observer-sdk/src/redact.ts)，`POST /sessions/import` 入 server 时过 redact；per-tenant scrubbers。**不可逆**，上云即脱敏。
5. **并发写限流**：串行模型下 per-tenant 请求计数（滑动窗口）；跨租户写隔离由目录分层 + 串行天然成立，无需额外锁。

## 设计决策（已落实）

| # | 决策点 | 选择 | 理由 |
|---|---|---|---|
| D1 | 租户配置源 | `tenants.json` 文件，启动读 + 热加载 | 起步零运维，admin API/UI 留后续；console 内嵌退化为单租户 |
| D2 | session ID 校验 | `^[0-9]+$` | 与 `unique_session_id` 生成器一致，堵 read API 路径穿越 |
| D3 | bundle 契约 | 不动（version 1 纯 JSON） | gzip 限于落盘+传输已覆盖 B3 大头；动 bundle 要 TS/Rust 双端解压 + 版本协商，复杂度跳一档 |
| D4 | console 内嵌模式 | 隐式单租户（无 key、扁平目录） | 不破坏本地优先默认；`ObserverServer` 支持无 tenant 配置透传 |
| D5 | 并发模型 | 保持 tiny_http 串行 + 计数限流 | 自托管小团队够用；线程化 + 文件锁留瓶颈时 |
| D6 | redact 语义 | 不可逆，服务端入库即脱敏 | 集中管控 PII；UI/文档须明示「上云即脱敏，不可恢复」 |

## 实施顺序（已按此落地）

| 步 | 内容 | 依赖 | 风险 |
|---|---|---|---|
| 1 | session ID 校验 + read API 路径穿越加固 | 无 | 安全，应最先（即使 P9 不全做也该修） |
| 2 | gzip 落盘 + 传输 | 无 | 低，独立高价值（segments 通常 5-10x 压缩） |
| 3 | 租户模型（tenants.json + key->tenant + 目录分层 + appId 越权拒） | 1 | 中，地基 |
| 4 | 配额 + 保留（tenant 级大小缓存 + 后台清扫线程） | 3 | 中 |
| 5 | 服务端 redact（Rust 移植 + import 前过） | 3 | 低，可并行 4 |
| 6 | 限流（串行 + per-tenant 计数） | 3 | 低 |

## 改动

- [observer-server](../../crates/observer-server)：tenant registry + key 解析 + 配额/保留 + gzip 传输 + 限流 + 服务端 redact 钩子。
- [observer-storage](../../crates/observer-storage)：`validate_session_id` + gzip 落盘/读路径 + redact 模块（Rust）+ `enforce_retention`。
- [routes.rs](../../crates/observer-server/src/routes.rs)：所有 `/sessions/:id` 路由过 `validate_session_id`；ingest 加 appId 越权校验。
- [SettingsView.vue](../../src/views/SettingsView.vue)：保留策略配置接后端（UI 已有字段，纯数据接线）。

## 验收

- 多租户：不同 key 数据隔离；`../` 跨租户访问被拒；越权 appId 上报被拒。
- 配额超限上报被拒（429）；过期会话被后台清扫。
- gzip 压缩比显著，回放无感。
- 服务端 redact：上传 bundle 后 network body/headers 被剥离，scrubbers 命中。
- 限流：超阈值请求被拒（429）。
- console 本地模式（默认）行为不变；`cargo test` 全过 + 多租户端到端冒烟。

## 风险与边界

- **session ID 路径穿越**：当前 read API 信任 URL，多租户放大风险--步骤 1 必修。
- **配额统计成本**：目录大小不能每写都算，需 tenant 级缓存（启动扫 + 写入累加）。
- **redact 不可逆**：脱敏后原始 PII 永久丢失，文档与 UI 须明示。
- **bundle 向后兼容**：gzip 落盘后旧 `.jsonl` 仍需可读，按扩展名分派，零迁移。
- **多租户对 console 内嵌**：`ObserverServer` 单 `ServerConfig` 结构需扩展为可选 tenant registry，无配置时透传为单租户。
